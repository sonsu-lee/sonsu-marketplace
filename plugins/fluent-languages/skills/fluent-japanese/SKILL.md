# 자연스러운 일본어 출력

일본어 설명문을 요청된 장르, 독자, 문체와 형식에 맞게 작성한다. 표현을 다듬을 때는 사실,
지정된 구조와 의미의 강도를 보존한다. 문체 선호와 보존 기준이 충돌하면 보존 기준을 우선한다.

## 적용 범위

- 요청된 답변과 문서의 일본어 설명문에 적용한다. 코드 작업 결과, 기술 답변과 기술 문서도 포함한다.
- 프롬프트에 쓰인 언어가 아니라 요청한 출력 언어를 기준으로 선택한다.
- 외국어 문장, 인용문과 전문 용어는 사용자가 변경을 요청한 범위에서만 번역·수정한다.
- 코드, 코드 주석, commit message 등 프로젝트에서 관리하는 문자열은 사용자 지시와 프로젝트 관례를 따른다.

## 작업 연속성

장문·여러 문서의 언어 편집을 주 작업으로 맡았다면
[작업 연속성](../task-continuity/SKILL.md)에 원문·초안·완료 구간을 기록한다.
다른 작업의 표현을 돕는 경우에는 주 작업 담당자의 기록으로 이어 간다.

## 표현 지침의 범위

요청된 언어의 어순·어휘·어조와 자연스러운 생략을 다룬다. 문서 전체의 정보 순서와 장르별
양식은 사용자 또는 현재 작성을 맡은 스킬이 정한 구성을 따른다.

단독으로 사용할 때는 요청 범위에서 작성·편집한다. Writing이나 Workflow와 함께 사용할 때는
같은 초안에 필요한 표현 지침을 반영한다. 다른 플러그인의 설치나 재호출은 적용 조건이 아니다.

## 내용과 형식 보존

입력에 있거나 그대로 포함하라고 지정된 다음 항목은 철자, 대소문자, 문장부호와 값을 그대로 유지한다.

- 코드 블록과 구분자, 인라인 코드
- 명령어, 옵션, 환경 변수, 경로와 식별자
- API 엔드포인트, HTTP 메서드, 함수와 API 시그니처, JSON/YAML 키
- 로그와 오류 메시지, 버전, commit SHA와 티켓 ID
- 수치, 날짜, 단위, URL과 Markdown 링크 대상
- 직접 인용문, 보호 문자열과 리터럴

편집 범위에 따라 구조를 보존한다.

- 부분 수정이나 표현 다듬기에서는 지정 범위 밖의 제목·표·목록 순서를 유지한다.
- 자유 초안의 전체 재작성이나 형식 변경을 요청받았다면 그 범위에서 정한 새 구성을 따른다.
  Writing 등 작성 담당이 정한 구성도 같은 기준으로 유지한다.
- 고정 양식·필수 필드·HTML 마커와 번호 절차의 실행 순서·조건은 문체 편집의 보존 대상이다.
  보호할 구조인지 불명확할 때도 기존 구조를 유지한다.
- 실제 동작에 영향을 줄 수 있는 `Fixes`, `Closes`, `Part of`, `Ignore`, 티켓 ID·Jira 키·연결 URL은
  명시된 관계·문법·위치를 그대로 유지한다.

표현을 다듬을 때 사실, 주장, 귀속, 인과 관계와 영향 범위를 보존한다. 부정과 긍정, 조건·전제·예외·제한,
추측·가능성·확신·불확실성의 정도, `must`, `should`, `may`에 해당하는 의무와 허용 수준도 유지한다.
결론, 수치, 사례, 출처와 행위자는 입력으로 뒷받침되는 내용만 사용한다.

요약을 명시적으로 요청받았다면 정해진 요약 범위에서 목적에 불필요한 정보를 생략할 수 있다.
남긴 주장의 진위를 좌우하는 조건·예외·확실성은 함께 보존한다.

## 화제와 행위자

- 같은 화제가 이어지고 행위자나 대상을 문맥에서 하나로 특정할 수 있으면 주어나 역할명을 자연스럽게 생략한다.
- 행위자가 바뀌거나 후보가 여러 명일 때, 책임·권한·안전성이 관련될 때는 입력에서 확인된 역할명을 쓴다.
- 시스템, 앱, CLI나 서버가 실제 처리를 수행하면 해당 이름을 행위자로 쓴다.
- 주어진 정보로 행위자나 의미를 특정할 수 없다면 그 불확실성을 유지한다.

## 문장 성분의 관계와 쉼표

- 조사, 서술어와 논항, 수식어와 피수식어의 관계를 한 번에 이해할 수 있게 쓴다. 해석이 여러 가지면
  의미를 보존하면서 조사·어순을 조정하거나 문장을 나눈다. 제목, UI 레이블과 관용적인 짧은 항목은
  자연스러운 조사 생략을 유지한다.
- 수식어가 여러 개면 의미 관계를 보존할 수 있는 범위에서 긴 수식어를 앞에, 짧은 수식어를 피수식어 가까이에 둔다.
  긴 관형절도 길이 자체보다 관계의 명료성을 기준으로 다듬는다.
- 쉼표는 실제 절의 경계, 삽입구와 병렬 관계를 드러내는 데 쓴다. 위치는 문장 구조로 정하며,
  원문에서 미확정인 의미는 쉼표를 조정할 때도 유지한다.

## 문체와 어휘

- 본문은 사용자 지정, 기존 문서와 프로젝트 관례에 맞는 문체로 쓴다. 지정이 없는 일반 답변과
  기술 보고 본문은 간결한 「です・ます調」를 기본으로 한다.
- 제목, 목록, 표와 UI 문구는 각 형식에 맞는 종결 표현을 쓴다. 「です・ます調」, 「だ・である調」,
  체언 종결과 구어체는 요청된 문체와 일관되게 사용한다.
- 경어가 행위자나 동작을 흐리면 입력에서 확인된 역할명과 동작을 명확히 한다. 고객 대응이나
  기존 문서에 필요한 존중의 수준은 유지한다.
- 프로젝트와 분야에 정착된 용어, 공식 명칭과 표기를 따른다. 독자에게 생소한 용어는 이해에 필요한 경우
  처음에 짧게 설명한다.
- 「こと」, 연속하는 「の」, サ変 명사, 명사화와 수동태는 행위자·대상·결과의 관계가 모호해질 때
  의미가 같은 직접적인 표현으로 다듬는다. 결과·상태가 주제이거나 행위자가 불명확·부차적인 경우,
  법령·계약서·학술 문서에서 정착된 표현은 유지한다.
- 추상적인 가타카나어가 겹쳐 대상이나 관계가 흐려지면 입력에서 확인된 구체적인 표현으로 다듬는다.
  API, 제품명, 기술 용어와 식별자는 표기 문자와 관계없이 유지한다.

## 문어 표기와 번역

- 문서 종류, 독자, 지정된 표기 기준과 기존 용어를 먼저 확인한다. 공용문·번역 실무의 표기 기준은
  해당 문서 범위에 적용한다. 이 절은 문어 표기를 다루며 구어의 축약·발음·말하기는 범위 밖이다.
- 상용한자표는 일반 독자를 위한 표기의 참고 기준으로 삼고, 각 단어의 읽기와 용법도 함께 본다.
  표에 없는 한자라도 「推敲」, 「梱包」처럼 정착된 단어, 전문 용어와 고유명사는 문맥에 맞게 유지한다.
  익숙한 표기를 우선하며 한자 비율은 수정 기준으로 삼지 않는다.
- 보조동사나 형식적 용법은 일반 실무 문서에서 「確認していただく」, 「記載のとおり」,
  「利用するとき」처럼 히라가나를 기본으로 한다. 「賞状を頂く」, 「二通り」처럼 실질적인 뜻을
  가진 용법과 구분한다. 「すべて／全て」, 「さまざま／様々」처럼 허용되는 표기 차이는 지정이나
  문서 내 일관성이 필요할 때 맞춘다.
- 한자어와 고유어는 해당 문장의 뜻, 단어의 결합과 문체에 맞게 선택한다. 일반 독자를 위한 설명은
  의미를 보존하면서 쉽게 풀어 쓴다. 한자어라는 이유만으로 바꾸거나 「順調」 같은 평가를 덧붙이지 않고,
  전문적인 구분을 유지한다.
- 한국어를 번역할 때는 한자 대응보다 문맥상 뜻, 품사, 단어의 결합과 조사를 확인한다. 「-적」,
  「하다」, 「되다」는 동작의 주체·대상과 자동사·타동사 관계에 맞게 옮긴다. 자연스럽게 퍼지는
  「普及する」와 누군가가 널리 퍼뜨리는 「普及させる」를 구분한다. 일본어에서도 성립하는 「的」,
  サ変 동사와 수동태는 유지한다.
- 뜻, 조사, 품사나 자동사·타동사 용법의 오류는 한 번만 나타나도 문맥에서 확인되면 고친다.
  여러 해석이 가능한 원문은 그 불확실성을 유지한다. 이 확인은 아래의 반복·장황함 점검과 별개로 수행한다.

## 최종 점검

초안에서 다음 목표를 확인하고, 읽기를 방해하는 부분만 국소적으로 다듬는다.

- 문두 접속 표현, 종결어미와 문형의 반복이 내용의 흐름을 돕는다.
- 명사화, 수동태와 추상적인 가타카나어를 사용해도 행위와 관계를 쉽게 따라갈 수 있다.
- 도입과 맺음말이 있다면 필요한 맥락과 내용을 전달한다. 중요성에 대한 표현은 근거에 맞춘다.

용어 일관성, 절차, 규칙, 교육이나 안전 확인에 필요한 반복은 유지한다. 개별 표현의 한두 번 사용이나
수치 목표는 수정 이유가 아니다. 다듬은 표현이 의미, 긍정·부정, 확실성, 의무 수준, 전문 용어나
지정 형식을 바꾸면 원래 표현을 유지한다.
