# 한국어 커스텀 기준

작성 지침과 윤문 규칙은 아래 조건으로 함께 적용한다. 각 결정은 SKILL.md와 해당 참조 파일에도 반영한다.

| 상황·관련 규칙 | 적용 기준 | 수정·유지 예시 |
| --- | --- | --- |
| 성분 보완과 생략: Fluent 문장 단위, A-13·A-16 | 의미를 이해하는 데 필요한 성분만 입력에서 확인해 보완한다. 자연스러운 생략·강조는 유지한다. | “그것이 제 선택입니다”는 강조가 있으므로 유지. 경고 대상이 불명확하면 파일 이름을 만들어 넣지 않음. |
| 한자어·추상어: Fluent 구 단위, F-4·F-5·F-7 | 정확한 전문용어를 유지하고 관계를 가리는 추상화만 푼다. | “정책 시행” 유지. “지원을 확대해야 한다”에 예산 증액을 임의 추가하지 않음. |
| 피동·진행: A-8·A-9·A-20·E-2 | 실제 이중 피동만 정리하고 행위자·진행·완료를 보존한다. | “판단되어진다” → “판단된다”. “배포가 진행되고 있다”는 완료형으로 바꾸지 않음. |
| 가능·의무·유보: A-10·G-1·G-2·I-1·I-4 | 의미의 강도·극성·책임을 유지한다. 불확실하면 고치지 않는다. | “실패할 수 있다”를 “실패한다”로 바꾸지 않음. 협상 문장의 중첩 완곡 유지. |
| 구체화·출처: A-15·A-22·D-4·D-5·D-9·I-7 | 입력에 있는 주체·수치·원인·출처만 사용한다. 평가를 사실로 바꾸지 않는다. | “가치가 분명하다”에 “40% 절감”을 추가하지 않음. “수요가 늘 것이라는 분석이다”의 유보 유지. |
| 구조·리듬: C·E·H | 장르와 정보 관계에 따라 수정한다. 길이·어미·개수·삭제 비율을 맞추지 않는다. | 설치 절차의 번호와 순서, 비교표, 한다체·합니다체 유지. |
| 비유·대시: Fluent 구 단위, D-14·J-3 | 모호한 장식만 풀고 관용 표현·중심 은유·개인 문체는 유지한다. | “잠식” 출현만으로 교정하지 않음. 요청한 비유와 직접 인용의 대시 유지. |
| 기술 문서·보호 문자열: 전 규칙 | 한국어 설명에 적용하되 코드·명령·식별자·로그·수치·링크·고정 양식을 보존한다. | `cacheKey`, 오류 메시지, Markdown 링크 대상, PR 연결 문법 유지. |
| 보류·관찰: A-17·G-3·C-12·E-6·담화 지표 | 보류·관찰을 교정 명령으로 사용하지 않는다. | “여러 조건들”, “양쪽 모두”를 규칙의 빈도만으로 삭제하지 않음. |
| 결과 반환·과윤문: post-editing | 수정량·등급·파일 저장을 강제하지 않는다. 문제가 있던 부분만 고친다. | 이미 자연스러운 문장은 그대로 반환. 사용자 요청 없이 진단 보고서·HTML 마커를 붙이지 않음. |

의미 보존과 표현 개선이 충돌하면 의미를 보존한다. 문헌·코퍼스 수치는 문맥 판단의 보조 자료이며 AI 작성 판정이나 개별 교정의 효능 보증으로 사용하지 않는다.
