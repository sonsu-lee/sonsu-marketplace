# 자연스러운 한국어 출력

한국어 설명문을 요청된 장르, 독자, 어조와 형식에 맞게 작성한다. 표현을 다듬을 때는 사실,
지정된 구조와 의미의 강도를 보존한다. 문체 선호와 보존 기준이 충돌하면 보존 기준을 우선한다.

## 적용 범위

- 요청된 답변과 문서의 한국어 설명문에 적용한다. 코드 작업 결과, 기술 답변과 기술 문서도 포함한다.
- 프롬프트에 쓰인 언어가 아니라 요청한 출력 언어를 기준으로 선택한다.
- 외국어 문장과 기술 용어는 사용자가 변경을 요청한 범위에서만 번역·수정한다.
- 코드, 코드 주석, commit message 등 프로젝트에서 관리하는 문자열은 사용자 지시와 프로젝트 관례를 따른다.

## 작업 연속성

장문·여러 문서의 언어 편집을 주 작업으로 맡았다면
[작업 연속성](../task-continuity/SKILL.md)에 원문·초안·완료 구간을 기록한다.
다른 작업의 표현을 돕는 경우에는 주 작업 담당자의 기록으로 이어 간다.

## 표현 지침의 범위

요청된 언어의 어순·어휘·어조와 자연스러운 생략을 다룬다. 문서 전체의 정보 순서와 장르별
양식은 사용자 또는 현재 작성을 맡은 스킬이 정한 구성을 따른다.

단독으로 사용할 때는 요청 범위에서 작성·편집한다. Writing이나 Workflow와 함께 사용할 때는
같은 초안에 필요한 표현 지침을 반영한다. 다른 플러그인의 설치나 재호출은 적용 조건이 아니다.

## 내용과 형식 보존

새 문서의 참고 자료와 편집할 원문을 구분한다. 작성 단계에서 목적에 맞게 선별한 내용과 구성을
따르고, 제외한 참고 내용을 표현 단계에서 다시 추가하지 않는다. 명시적으로 포함하도록 지정한
내용과 편집 대상의 사실은 유지하며, 표현 다듬기를 임의 생략의 근거로 삼지 않는다.

편집 대상과 최종 문서에 포함하는 다음 항목은 철자, 대소문자, 문장부호와 값을 그대로 유지한다.

- 코드 블록과 구분자, 인라인 코드
- 명령어, 옵션, 환경 변수, 경로와 식별자
- API 엔드포인트, HTTP 메서드, 함수와 API 시그니처, JSON/YAML 키
- 로그와 오류 메시지, 버전, commit SHA와 티켓 ID
- 수치, 날짜, 단위, URL과 Markdown 링크 대상
- 직접 인용문, 보호 문자열과 리터럴

편집 범위에 따라 구조를 보존한다.

- 부분 수정이나 표현 다듬기에서는 지정 범위 밖의 제목·표·목록 순서를 유지한다.
- 자유 초안의 전체 재작성이나 형식 변경을 요청받았다면 그 범위에서 정한 새 구성을 따른다.
  Writing 등 작성 담당이 정한 구성도 같은 기준으로 유지한다.
- 고정 양식·필수 필드·HTML 마커와 번호 절차의 실행 순서·조건은 문체 편집의 보존 대상이다.
  보호할 구조인지 불명확할 때도 기존 구조를 유지한다.
- 실제 동작에 영향을 줄 수 있는 `Fixes`, `Closes`, `Part of`, `Ignore`, 티켓 ID·Jira 키·연결 URL은
  명시된 관계·문법·위치를 그대로 유지한다.

표현을 다듬을 때 사실, 주장, 귀속, 인과 관계와 영향 범위를 보존한다. 부정과 긍정, 조건·전제·예외·제한,
추측·가능성·확신·불확실성의 정도, `must`, `should`, `may`에 해당하는 의무와 허용 수준도 유지한다.
결론, 수치, 사례, 출처와 행위자는 입력으로 뒷받침되는 내용만 사용한다.

요약을 명시적으로 요청받았다면 정해진 요약 범위에서 목적에 불필요한 정보를 생략할 수 있다.
남긴 주장의 진위를 좌우하는 조건·예외·확실성은 함께 보존한다.

## 한국어 문체

- 피동이 필요한 문장은 단일 피동으로 쓴다. `~되어지다`, `~지게 되어지다`와 같은 이중 피동은
  원래 의미를 유지하면서 다듬는다.
- 성과와 의의는 구체적인 사실과 근거로 설명한다. 중요성을 강조하는 표현도 근거가 뒷받침하는 수준에 맞춘다.
- 대상과 동작을 정확히 나타내는 말을 쓴다. 표준 기술 용어, 사용자 표현과 분야에 정착된 관용 표현을
  유지하고, 비유는 요청이나 설명 목적에 맞게 사용한다.
- 요약과 맺음말은 독자가 필요한 내용을 파악하는 데 도움을 주도록 쓴다. 결산 문구의 반복으로
  글이 늘어진 부분은 내용에 맞게 다듬는다.

## 최종 점검

초안의 접속어, 종결어미, 문장 구조·길이와 어휘가 자연스러운 흐름을 이루는지 확인한다.
반복이 내용보다 두드러져 읽기를 방해하는 부분만 국소적으로 다듬는다.

용어 일관성, 문맥 연결, 교육이나 안전 확인에 필요한 반복은 유지한다. 개별 표현의 한두 번 사용이나
수치 목표는 수정 이유가 아니다. 다듬은 표현이 의미, 긍정·부정, 의무 수준, 기술 용어나
지정 형식을 바꾸면 원래 표현을 유지한다.
