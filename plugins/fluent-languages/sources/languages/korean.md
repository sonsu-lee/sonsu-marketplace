# 자연스러운 한국어 출력

한국어 설명문을 요청된 장르, 독자, 어조와 형식에 맞게 작성한다. 표현을 다듬을 때는 사실,
지정된 구조와 의미의 강도를 보존한다. 문체 선호와 보존 기준이 충돌하면 보존 기준을 우선한다.

## 적용 범위

- 요청된 답변과 문서의 한국어 설명문에 적용한다. 코드 작업 결과, 기술 답변과 기술 문서도 포함한다.
- 프롬프트에 쓰인 언어가 아니라 요청한 출력 언어를 기준으로 선택한다.
- 외국어 문장과 기술 용어는 사용자가 변경을 요청한 범위에서만 번역·수정한다.
- 코드, 코드 주석, commit message 등 프로젝트에서 관리하는 문자열은 사용자 지시와 프로젝트 관례를 따른다.

## 한국어 문체

- 피동이 필요한 문장은 단일 피동으로 쓴다. `~되어지다`, `~지게 되어지다`와 같은 이중 피동은
  원래 의미를 유지하면서 다듬는다.
- 성과와 의의는 구체적인 사실과 근거로 설명한다. 중요성을 강조하는 표현도 근거가 뒷받침하는 수준에 맞춘다.
- 대상과 동작을 정확히 나타내는 말을 쓴다. 표준 기술 용어, 사용자 표현과 분야에 정착된 관용 표현을
  유지하고, 비유는 요청이나 설명 목적에 맞게 사용한다.
- 요약과 맺음말은 독자가 필요한 내용을 파악하는 데 도움을 주도록 쓴다. 결산 문구의 반복으로
  글이 늘어진 부분은 내용에 맞게 다듬는다.

## 최종 점검

초안의 접속어, 종결어미, 문장 구조·길이와 어휘가 자연스러운 흐름을 이루는지 확인한다.
반복이 내용보다 두드러져 읽기를 방해하는 부분만 국소적으로 다듬는다.

용어 일관성, 문맥 연결, 교육이나 안전 확인에 필요한 반복은 유지한다. 개별 표현의 한두 번 사용이나
수치 목표는 수정 이유가 아니다. 다듬은 표현이 의미, 긍정·부정, 의무 수준, 기술 용어나
지정 형식을 바꾸면 원래 표현을 유지한다.
