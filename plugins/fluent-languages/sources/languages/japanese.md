# 自然な日本語出力

日本語の説明文を、要求されたジャンル、読者、文体と形式に合わせて自然に作成します。表現を整える過程で、事実、構造、確実性や義務の強さを変えません。表現の指針と保持規則が衝突する場合は、保持規則を優先します。

## 適用範囲

- ユーザーが求める日本語の回答と文書の説明部分に適用します。コード作業の結果、技術的な回答と技術文書も含みます。
- プロンプトの言語ではなく、ユーザーが求める出力言語を基準に適用します。
- 外国語の文章、引用文や専門用語を、依頼なしに翻訳したり別の表現に置き換えたりしません。
- コード、コードコメント、コミットメッセージなど、プロジェクトの規約が適用される文字列では、その規約とユーザーの指示を優先します。
- このスキルは出力の文体だけを案内します。別のワークスペースの作成、採点・検出処理、ファイルへの書き出し、複数回の改稿を要求しません。

## 話題と行為者

- 同じ行為者や対象が文脈から一つに定まり、話題が続いている場合は、主語や役割名を不自然に繰り返しません。
- 行為者が切り替わる場合、行為者や対象の候補が複数ある場合、責任・権限・安全性に関わる場合は、入力から確認できる実際の役割名を示します。入力にない行為者は補いません。
- システム、アプリ、CLIやサーバーが実際に処理を実行する場合は、その名称を行為者として使えます。人を主語にするためだけに処理の主体を変えません。
- 利用できる情報だけでは意味を一つに特定できない場合は、一つの解釈を正しいものとして確定しません。

## 係り受けと読点

- 助詞、述語と項、修飾語と被修飾語の関係が一度で分かるように書きます。複数の解釈が生じる場合は、意味を変えない範囲で助詞や語順を調整するか、文を分けます。見出し、UIラベルや慣用的な短い項目には助詞を機械的に補いません。
- 複数の修飾語を並べ替える場合は、意味関係を保てるときに限り、長い修飾語を先に、短い修飾語を被修飾語の近くに置きます。長い連体修飾節も、長さだけを理由に分割しません。
- 読点は、文の構造に合う節境界、挿入句や並列関係を示すために使います。一定の文字数ごとには置かず、読点だけで未確定の意味を決めません。

## 文体と語彙

- 本文は、ユーザーの指定、既存文書やプロジェクトの規約に合う文体で書きます。指定のない一般的な回答と技術報告の本文では、簡潔な「です・ます調」を基本とします。
- 見出し、箇条書き、表やUI文言には、本文と同じ文末を強制しません。文体に変化を付けるためだけに「です・ます調」と「だ・である調」、体言止めや口語を混在させません。
- 敬語によって行為者や動作が分かりにくい場合は、入力から確認できる役割名や動作だけを明示します。顧客対応や既存文書で必要な敬意の水準は変えません。
- プロジェクトや分野で定着した用語、正式名称と表記を優先します。読者に馴染みのない用語は、読者の理解に必要な場合だけ最初に短く説明します。
- 「こと」、連続する「の」、サ変名詞、名詞化や受身形は、それらが行為者、対象または結果の関係を実際に分かりにくくし、直接的な表現にしても意味が変わらない場合だけ調整します。結果や状態が主題の場合、行為者が不明または重要でない場合、法令・契約書・学術文書で定着した表現では維持します。
- 抽象的なカタカナ語が重なって具体的な対象や関係を隠す場合だけ、入力から確認できる具体的な表現を使います。API、製品名、技術用語や識別子を、カタカナという理由で言い換えません。

## 書き言葉の表記と翻訳

- 文書の種類、読者、指定された表記基準と既存の用語を先に確認します。公用文や翻訳実務の表記基準を、すべての文章に共通する正誤の基準にはしません。口頭会話の縮約、発音や話し方は扱いません。
- 常用漢字表は一般向けの表記を考える目安です。字種だけでなく、その語での読みと用法も見ます。表外の漢字を一律に削除せず、「推敲」「梱包」のような定着した語、専門用語と固有名詞は文脈に応じて維持します。読み慣れた語までひらがなにしたり、漢字率の目標を設けたりしません。
- 補助動詞や形式的な用法は、一般的な実務文書では「確認していただく」「記載のとおり」「利用するとき」のようにひらがなを基本とします。ただし、「賞状を頂く」「二通り」のような実質的な意味を持つ用法と区別し、文字列だけで置換しません。「すべて／全て」「さまざま／様々」のように認められる表記の違いは、指定や文書内の一貫性が必要な場合だけそろえます。
- 漢語と和語は、その文での意味、結び付きや文体に合う方を使います。一般向けの説明では意味を保てる範囲で分かりやすく言い換えますが、漢語であること自体は修正理由にしません。言い換えによって、進み具合に「順調」などの評価を加えたり、専門的な区別を失わせたりしません。
- 韓国語から訳す場合は、漢字の対応よりも、その文での意味、品詞、語の結び付きと助詞を確認します。「-적」「하다」「되다」を機械的に「的」「する」「される」にせず、動作の主体・対象と自他の関係に合う形を選びます。例えば、自然に広まる「普及する」と、誰かが広める「普及させる」を区別します。日本語でも成立する「的」やサ変動詞、受身形は維持します。
- 語義、助詞、品詞や自他の取り違えは、一度だけでも文脈から誤りと確認できれば直します。複数の解釈が残る原文は、自然さを理由に一つの意味へ確定しません。この確認は、次の反復や冗長さの調整とは別に行います。

## 最終確認

下書きを作成した後、次の傾向が実際に目立つ場合だけ、その箇所を局所的に調整します。

- 文頭の接続表現や同じ文末・文型が短い範囲で繰り返され、内容より反復パターンが目立っています。
- 名詞化、受身形や抽象的なカタカナ語が重なり、行為や関係を追いにくくしています。
- 定型的な前置き、根拠のない重要性の強調、または新しい内容のない結びが本文を引き延ばしています。

個々の表現が一、二度現れること自体は問題にしません。数値目標を満たしたり、表面的な変化を機械的に付けたりするために、自然な文を無理に変えません。反復が用語の一貫性、手順、規則、教育や安全確認に必要な場合は維持します。調整によって意味、極性、確実性、義務の水準、専門用語または要求された形式が揺らぐ場合は、その調整を行いません。
