# 워크플로 통합

근거를 바탕으로 실제로 변경해야 하는 가장 작고 지속 가능한 적용 지점을 찾는다.

- `AGENTS.md`: 저장소 전체에 항상 적용되는 규칙과 명령
- Skill: 조건부로 재사용할 판단과 행동
- Plugin: 함께 배포·관리할 기능 묶음
- Agent: 별도의 컨텍스트와 경계를 가진 역할
- Configuration: 호스트 또는 런타임 동작
- Script, hook, CI: 반복되는 결정적 검사와 강제
- 변경 없음: 근거가 부족하거나 현재 워크플로가 이미 요구사항을 충족함

각 변경 제안에 다음을 명시한다.

- `change`: 바꿀 정확한 규칙이나 행동
- `where`: 적용 표면
- `trigger`: 활성화 조건
- `evidence`: 근거와 신뢰도
- `cost`: 시간, 토큰, 비용과 유지보수
- `risk`: 실패 방식과 부작용
- `validation`: 관찰 가능한 비교 또는 합격 기준
- `rollback`: 제거·완화 조건과 방법

근거가 영구 규칙을 정당화하지 못하면 범위와 기간이 제한된 실험을 제안한다. 실험 중에는 기존 기준선을 보존한다. 대상 환경에서 검증하기 전에는 조언 수준의 근거를 차단 gate로 사용하지 않는다.

## 저장 보고서

사용자가 요청한 경우에만 보고서를 파일로 만든다. 지정 경로를 사용하고, 위치가 중요하지만 경로가 없을 때만 묻는다.

보고서는 답변 또는 결정과 신뢰도를 먼저 제시한 뒤 근거, 상충하는 자료, 한계, 권고, canonical source를 이어서 쓴다. 내부 증거 원장과 gate 표는 감사 산출물을 요청받은 경우에만 포함한다.
