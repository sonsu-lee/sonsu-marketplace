name: brainstorming
description: 구현 전에 기존 변경이나 새 기능의 작업 범위와 설계 경계를 정할 때 사용한다.
---

요청과 기존 코드를 읽고 작업 경로, 관찰 가능한 결과, 필요한 결정을 정한다. 승인된 목표 안의 내부 선택은 직접 해결하고 결과를 바꾸는 사용자 결정을 구분한다.

## 절차

1. 현재 요청·사용자 승인·승인된 문서와 이슈에서 수행 범위를 확인하고 아래 실행 권한 표를 적용한다.
2. 코드·문서·최근 변경에서 목적·제약·완료 기준과 현재 계약·소비자·관찰 결과·검증 방법을 읽는다. 판단에 필요한 범위까지 탐색한다. 유용한 대안이 있으면 2–3개 접근과 추천 근거를 제시한다.
3. 작업 경로와 설계 깊이를 정한다. 의미 변화 없는 기계적 변경은 스크립트·AST·생성기·Code Mode와 실제 소비 검사로 처리한다. 동작 변화의 독립 리뷰와 고위험 설계·상태·권한·복구 경계의 red-team은 [품질 게이트](../../references/quality-gates.md)에 선언한다.
4. 범위가 명확한 변경은 접근·예상 결과·검사를 짧게 정리하고 여러 흐름·의존성·인터페이스 조정은 `dev-workflow:plan`으로 연결한다. 독립적으로 유용하고 검증 가능한 조사·설계는 [위임 경계](../../references/delegation.md)에 따라 할당한다. 후속 계획에 의존성·쓰기 범위·실행 방식과 생략한 산출물을 대신할 근거를 넘긴다.
5. [출처 표기](../../references/provenance.md)와 [설계 문서 배치·검토](design-documentation.md)에 따라 판단 근거, 문서 영향과 현재 리비전의 검증 상태를 기록한다. 조정자의 여러 단계 작업은 [연속성 계약](../../references/continuity.md)을 적용한다.
6. 재개할 때 현재 소스·계약과 이전 근거를 대조한다. task ID·이력·소비 라운드를 유지하고 새 위험에 맞춰 영향받은 정책과 근거를 갱신한다. 재개 자체가 진행을 막는 조건은 아니며 게이트 통과를 위해 확인한 위험을 낮추지 않는다.
7. 화면 시안·배치·시각 비교에 도움이 되면 브라우저 보조 도구 사용을 제안한다. 수락하면 [시각 보조 도구](visual-companion.md)를 읽고 시작한다. 거절하면 다시 요청받기 전까지 텍스트로 진행하고 요구사항·개념·장단점은 대화로 다룬다.

### 실행 권한

| 조건 | 수행 범위와 다음 단계 |
| --- | --- |
| 승인된 구현이며 미결정 계약이 없음 | 필요한 탐색·설계·계획·수정·검증을 계속한다. 별도의 설계 승인 메시지를 요구하지 않는다. |
| 설계·검토 전용 요청 | 요청한 산출물을 완성하고 구현 전에 종료한다. |
| 충족되지 않은 명시적 구현 전 확인 조건 | 요청된 설계·문서·계획을 완성해 제시한다. 응답에 의존하는 작업만 보류하고 독립적인 승인 작업은 계속한다. |
| 미결정 제품 규칙·충돌 요구사항·승인된 목표나 설계·관찰 계약 변경 | 근거와 변경안을 제시하고 해당 의존 작업은 사용자 확인까지 보류한다. 독립적인 승인 작업은 계속한다. |
| 이미 충족된 확인 조건 | 그 승인 범위에서 계속한다. 절차 전환이나 재개로 확인을 다시 요구하지 않는다. |

## 결과

작업 경로, 설계 선택과 출처, 관찰 가능한 결과, 문서 영향(`없음 / 기존 문서 갱신 / 영속 문서 생성 / 기존 결정 대체`), 검사·리뷰 상태와 다음 단계를 보고한다. 조사 전용은 질문·확인 범위·관찰을, 설계 전용은 완성한 산출물을 보고한다. 구현이 승인된 구조 변경은 plan의 의사코드·대응 관계·검증 선택 규칙으로 이어간다.

## 예시

입력: “내보내기 파일명을 사용자가 지정할 수 있게 설계만 해 줘. 디렉터리는 서버가 관리해.”

결과: 저장 위치와 경로 검증 계약은 서버가 소유하고 사용자 입력은 파일명으로 한정한다. 기존 API 계약 설계 문서를 갱신 대상으로 정하고 허용 문자·중복 이름 정책의 미결정 사항을 제시한다. 설계 전용 범위이므로 구현은 시작하지 않는다.

## 경계

- 작업 경로·복잡도·계획 필요 여부·품질 판정은 실행 권한을 부여하거나 취소하지 않는다. 응답 부재를 승인으로 취급하지 않는다.
- Git·배포·외부 쓰기는 각각의 권한을 확인한다.
