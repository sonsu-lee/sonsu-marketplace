# 터치 기기의 웹

> 영문 정본: [web-touch-platform.md](web-touch-platform.md) (`6ebbde0` 기준 번역).
> 사람이 읽기 위한 번역본이며 에이전트는 이 파일을 읽지 않는다.

웹 인터페이스를 휴대폰이나 태블릿에서 쓸 때 읽는다. 이것은 취향이 아니라 브라우저 동작이다. 특정 세부에 의존하기
전에 현재 브라우저 지원 여부를 확인한다.

- **터치에서는 호버가 남는다.** 탭하면 `:hover`가 적용되고 그대로 유지된다. 호버 전용 효과는
  `@media (hover: hover) and (pointer: fine)` 안에 두고, 터치 사용자에게는 `:active`로 누름 피드백을
  주며, 어떤 행동도 호버로만 숨기지 않는다. 기기가 아니라 입력 능력으로 구분한다. 트랙패드가 달린 태블릿과
  터치 노트북은 두 방식을 섞어 쓴다.
- **`100vh`는 가장 큰 뷰포트다.** 브라우저 막대가 보이는 동안에는 넘친다. 보이는 영역을 따라가는 앱 셸에는
  `dvh`를, 가장 작은 뷰포트에 맞아야 하는 콘텐츠에는 `svh`를 쓴다.
- **작은 입력란은 페이지를 확대한다.** iOS Safari는 글꼴 크기가 16px 미만인 입력란에 포커스하면 확대한다.
  입력란 크기를 키운다. `user-scalable=no`나 `maximum-scale=1`로 확대를 막는 것은 접근성 실패이므로 하지
  않는다.
- **안전 영역에는 `viewport-fit=cover`가 필요하다.** 이것이 없으면 `env(safe-area-inset-*)`는 0이다.
  `env()`에는 대체값을 준다.
- **스크롤 체이닝.** 시트나 모달의 스크롤 콘텐츠에 `overscroll-behavior: contain`을 주면 그 스크롤이
  페이지로 넘어가지 않는다. 시트가 열린 동안 페이지를 잠그지는 않는다. 페이지에 `none`을 주면
  당겨서 새로고침도 사라진다.
- **`touch-action`은 브라우저가 여전히 할 수 있는 동작을 지정한다.** 가로 캐러셀은 `pan-y`를 유지한다.
  `none`은 요소가 모든 제스처를 직접 처리할 때만 쓴다. 직접 만든 캐러셀보다 네이티브 스크롤 스냅을 우선한다.
- **키보드.** 알맞은 키보드를 위해 `type`과 `inputmode`를, 리턴 키를 위해 `enterkeyhint`를 고르고, 코드와
  이메일에는 자동 대문자와 자동 수정을 끈다.
- **브라우저 색상.** 브라우저가 `theme-color`를 따르는 경우 색상 스킴별로 지정해 페이지 상단과 맞춘다. 일부
  브라우저는 대신 페이지 배경에서 색조를 가져온다.

데스크톱의 기기 에뮬레이션은 남는 호버, 탭 지연, 러버밴딩, 안전 영역, 화면 키보드를 재현하지 않는다.
시뮬레이터는 더 많이 다루지만 터치 감각은 다루지 못한다. 어떤 동작을 실제 기기에서 확인했고 어떤 동작을 코드로만
확인했는지 밝힌다.
