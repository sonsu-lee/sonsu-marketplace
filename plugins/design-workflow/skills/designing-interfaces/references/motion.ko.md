# 모션

> 영문 정본: [motion.md](motion.md) (`6ebbde0` 기준 번역).
> 사람이 읽기 위한 번역본이며 에이전트는 이 파일을 읽지 않는다.

제안이 애니메이션을 추가, 변경, 검토, 제거할 때 읽는다.

## 애니메이션할지 결정하기

1. **빈도.** 사람들이 자주 볼수록 덜 움직여야 한다. 키보드로 시작하는 동작이나 하루에도 여러 번 하는 동작은
   즉시 반응해야 한다.
2. **목적.** 목적을 이름 붙인다. 피드백, 공간상 위치 유지, 상태 변화 표시, 설명, 갑작스러운 변화 피하기 중
   무엇인가. 이름 붙일 수 없다면 애니메이션하지 않는다.
3. **기능.** 사람들이 읽거나 조작하는 데이터는 스타일을 위해 움직이지 않아야 한다.

애니메이션하지 않는 것도 타당한 결론이다. 모션을 제안할 때는 애니메이션하지 않기로 한 것과 그 이유를 나열한다.

## 동작

- 모션은 원인이 있는 곳에서 시작한다. 팝오버는 트리거에서 자라나고, 요소는 들어온 방식대로 나간다.
- 전환 중에 입력을 막지 않는다. 사람들이 전환을 중단하거나 되돌릴 수 있어야 한다. CSS 트랜지션은 도중에
  목표를 바꾸고, 키프레임 애니메이션은 처음부터 다시 시작한다.
- `prefers-reduced-motion: reduce`는 모션을 없애라는 것이 아니라 부드럽게 하라는 요청이다. 이동을 짧은
  페이드로 바꾸고 이해를 돕는 변화는 유지한다. `prefers-reduced-transparency`와 `prefers-contrast`도
  존중한다.
- 크게 움직이는 배경과 끝없는 반복을 피한다. 5초보다 긴 자동 재생 모션에는 멈출 수단이 필요하다.

지속 시간과 이징은 제품의 성격에 따라 다르다. 기존 디자인 시스템을 따르고, 하나의 값을 보편적으로 옳다고
제시하지 않는다.

## 비용

`transform`과 `opacity`를 애니메이션하면 대개 레이아웃과 페인트를 피한다. `width`, `height`, `top`, `left`,
`margin`, `padding`은 레이아웃을 일으킨다. JavaScript가 프레임마다 구동하는 애니메이션은 메인 스레드에서 실행되므로
페이지가 바쁘면 프레임이 떨어진다. 상속되는 CSS 변수를 바꾸면 모든 자손의 스타일이 다시 계산된다. 부드러움은 실제
중급 기기에서 확인한다. 빠른 데스크톱으로는 증명되는 것이 거의 없다.

## 모션 제거하기

애니메이션이 실행되기 전까지 시작 상태가 숨겨져 있는 요소, 애니메이션이 끝나기를 기다리는 코드, 언마운트를
늦추는 퇴장, 애니메이션 후에 옮겨지는 포커스, 애니메이션 클래스를 기다리는 테스트를 확인한다.

모션이 어떻게 느껴지는지 판단하려면 코드만으로는 안 되고 녹화나 실행 중인 빌드가 필요하다. 구현 세부는 이 내용의
출처인 Emil Kowalski의 [motion skills][upstream] (MIT)를 참고한다.
