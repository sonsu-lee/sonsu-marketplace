# 최악의 데이터

> 영문 정본: [worst-case-data.md](worst-case-data.md) (`6ebbde0` 기준 번역).
> 사람이 읽기 위한 번역본이며 에이전트는 이 파일을 읽지 않는다.

검토 대상 디자인이 사용자나 시스템에서 오는 데이터, 즉 이름, 레이블, 개수, 날짜, 목록, 이미지, 상태를
렌더링할 때 읽는다. 깔끔한 샘플 콘텐츠로 보여 준 디자인은 실제로 받게 될 콘텐츠에 대해 아무것도 말해 주지 않는다.

## 실제 한도 찾기

렌더링되는 값마다 출처, 타입, 한도를 나열한다. 한도는 검증 스키마, 데이터베이스 컬럼, API 계약에서 가져온다.
그런 것이 없다면 그 값을 무제한으로 보고한다. 그 자체가 발견이다. 입력 한도와 저장 한도가 어긋나는 곳도
기록한다.

## 시험할 값

무작위 문자열이 아니라 현실적인 예를 쓴다.

- **이름:** 발음 구별 기호가 있는 긴 하이픈 이름, 한 글자 이름, 겹쳐 쌓인 발음 구별 기호, CJK, 오른쪽에서
  왼쪽으로 쓰는 문자, 이모지와 결합 이모지, 여분의 공백, 이메일만 있고 이름이 없는 경우.
- **식별자:** 긴 이메일과 URL, 파일 이름, UUID처럼 끊기지 않는 토큰. 도메인은 `example.com`, `example.org`,
  `.test`를 쓴다.
- **레이블:** 긴 제목과 상태 텍스트, 긴 합성어, 번역으로 길어지는 텍스트, 많은 태그, 비어 있거나 공백뿐인
  텍스트, 문자 그대로의 마크업.
- **숫자:** 0, 1, 큰 값, 음수, 소수, 누락된 값, 다른 로케일의 서식.
- **컬렉션:** 없음, 하나, 정확히 한 페이지와 하나 더, 아주 긴 목록, 다른 것보다 훨씬 큰 항목 하나, 같은
  이름들.
- **시간:** 방금, 오래전, 미래, 시간대 경계의 날짜, 긴 기간.
- **미디어:** 없거나 깨진 이미지, 아주 넓거나 높은 이미지, 어두운 테마 위의 투명하거나 어두운 로고.
- **상태:** 로딩, 원본 메시지가 그대로 나오는 오류, 일부만 있는 데이터, 모든 상태가 한꺼번에, 권한 없음,
  목록 안의 현재 사용자.
- **환경:** 지원하는 가장 좁은 너비와 가장 넓은 너비, 키운 텍스트 확대, 지원하는 경우 어두운 테마와 오른쪽에서
  왼쪽 레이아웃.

## 판단하고 보고하기

깨지는 곳마다 깨졌는지(읽을 수 없거나, 도달할 수 없거나, 데이터가 틀림), 보기 흉한지, 취약한지(현실적인 한
단계만 더 가면 깨짐) 밝힌다. 숫자, 금액, 날짜, 사용자가 비교하는 값은 절대 자르지 않는다. 다른 텍스트를 자를 때는
전체 값을 볼 방법이 있어야 한다. 어떤 값이 버텼는지도 말한다.

관찰한 깨짐과 추론한 깨짐을 구분한다. 가능하면 디자인을 렌더링한다. 그럴 수 없다면 마크업에서 추론할 수 있는
깨짐은 추론으로 보고하고, 영향을 추론할 수 없는 값은 열린 질문으로 나열한다. omp 엄격 실행에서는 `web` 캡처가
최악의 경우 픽스처를 제공하는 URL을 대상으로 `assert-no-overflow` 단계를 실행할 수 있다. 깨짐을 만들려고
디자인을 수정하지 않는다.
