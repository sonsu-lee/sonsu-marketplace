# 업무 문서 작성

독자가 이해·판단·행동하는 데 필요한 내용을 요청한 언어와 형식으로 쓴다. Writing은 정보 선별과
문서 배치, 문장·문단 구성과 편집 범위를 맡는다. 언어별 표현은 Fluent, 티켓·PR 양식과 외부 작업은
Workflow가 맡으며, 각 플러그인은 단독으로 쓰거나 필요한 지침을 함께 적용할 수 있다.

## 요청한 범위에서 작성한다

문맥에서 독자, 목적, 출력 언어와 편집 범위를 파악한다. 결과를 좌우하는 정보가 빠졌을 때만
확인하고, 나머지는 알려진 내용으로 진행한다. 짧은 답변·한 문장 수정·지정 구간 편집은
해당 범위에서 바로 작성하며 문서 배치를 위한 저장소 탐색을 요구하지 않는다.

| 요청 | 다루는 범위 |
| --- | --- |
| 새 작성 | 제공된 사실·합의로 목적에 맞는 구성을 만든다. 미확인 내용은 그 상태로 남긴다. |
| 부분 수정 | 지정된 문장·항목과 필요한 연결만 고치고, 나머지 제목 체계·순서·내용을 유지한다. |
| 전체 재작성 | 자유 초안의 문장·문단·제시 순서를 바꿀 수 있다. 지정 양식과 실행 절차의 의미·순서는 유지한다. |
| 요약 | 목적에 맞게 정보를 줄이고 남긴 주장의 조건·예외·확실성을 보존한다. 절차 요약은 개요임을 밝히고 원 절차의 위치를 남긴다. |

[의미와 형식 보존](references/integrity.md)으로 수정 가능한 범위를 정하고,
[문장·문단 구성](references/composition.md)에 따라 읽기 어려운 관계를 다듬는다.

## 지속적으로 찾을 문서는 갱신 대상을 정한다

영속 문서의 새 작성·갱신이나 문서 정리를 맡았을 때 적용한다. 사용자가 지정한 위치·포함 내용과
프로젝트 관례를 우선한다. 앞선 작업에서 정한 문서 영향·목적·경로·갱신 범위가 있으면 이어받고,
현재 내용과 달라진 부분만 확인한다.

1. 이후에도 찾아볼 사용법·설정·계약·운영 지식인지 판단한다. 일회성 작업 과정이나 검사 결과만
   있으면 작업 보고에 남긴다. 회고·검증 보고 자체를 요청받았다면 그 목적에 맞게 작성한다.
2. 허용된 자료에서 해당 주제를 담당하는 기존 문서를 찾아 갱신한다. 관련 문서와 연결된 위치부터
   확인하며 모든 문서를 매번 탐색하지 않는다. 독립된 읽기 목적이 있고 기존 문서에 적합한 자리가
   없을 때 새 문서를 만든다. 문서가 짧으면 한 문서에서 완결할 수 있다.
3. 상세 내용은 담당 문서에 두고, 다른 문서는 필요한 요약과 링크로 연결한다. README를 갱신할지는
   [README의 역할과 갱신 기준](references/readme.md)으로 별도 판단한다.

자료나 쓰기 권한이 부족하면 확인한 범위의 초안과 남은 확인 사항을 반환한다. 경로나 내용을
추측해 링크·자리표시자 문서를 만들지 않는다. 글 작성만 요청받았다면 파일 생성으로 확대하지 않는다.

## 필요한 지침으로 한 초안을 작성한다

사용자·프로젝트가 지정한 양식과 작성 관례를 우선하고, 작성 대상에 맞는 참고 자료를 읽는다.

| 작성 대상 | 참고 자료 |
| --- | --- |
| README | [처음 읽는 사람의 이해와 실행](references/readme.md) |
| 코드·API 주석 | [호출 계약, 이유와 유지보수 정보](references/comments.md) |
| 동료에게 보낼 요청·보고·인계 | [메시지의 요청과 맥락](references/messages.md) |

티켓·PR은 전달받은 항목 안에서 설명을 구성한다. 구체적인 기본 양식·필수 항목·양식 조회와
게시 절차는 Codex의 `workflow:to-ticket`·`workflow:to-pr` 또는 OMP의
`skill://to-ticket`·`skill://to-pr`가 맡는다. 양식이 전달되지 않았으면 주어진 사실로 임시
초안을 작성하고, 저장소나 팀의 유효한 양식인지 확인하는 일은 해당 절차에 남긴다.

현재 사용할 수 있는 Fluent 지침 중 **요청된 출력 언어**에 맞는 지침을 함께 적용한다.
프롬프트 언어와 구분하고, 여러 언어는 각 부분에 맞춰 선택한다.

| 출력 언어 | Codex ID | OMP ID |
| --- | --- | --- |
| 한국어 | `fluent-languages:fluent-korean` | `skill://fluent-korean` |
| 일본어 | `fluent-languages:fluent-japanese` | `skill://fluent-japanese` |
| 영어 | `fluent-languages:fluent-english` | `skill://fluent-english` |

이미 적용 중인 지침에 필요한 지침만 보태고, 독자·목적·선별한 사실·출력 언어·편집 범위와 정해진 구성을
공유해 같은 초안에 반영한다. 다른 플러그인이 없으면 Writing의 구성·보존 지침으로 작성한다.
표현 선호가 사실·조건·고정 양식과 충돌하면 보존 기준을 따른다.

외국어 인용·고유명·기술 용어는 유지하고, 코드 주석·commit message·UI처럼 프로젝트가 관리하는
문자열은 사용자 지시와 프로젝트 관례를 따른다.

## 의미와 형식을 대조해 반환한다

초안을 원문·요구사항과 대조해 사실·조건·확실성·편집 범위와 보호 문자열을 확인한다.
영속 문서는 필요한 정보의 누락, 상세 설명의 중복, 불필요한 파일 생성과 링크도 대조한다.
외부 작업 담당자가 전달한 양식·필수 필드·연결 문법·첨부 위치도 유지한다. 원격 조회·게시와
링크에 따른 상태 변경은 해당 담당 절차와 사용자 권한에 따르며, 초안 작성만으로 게시 준비가
완료되는 것은 아니다. 설명이나 비교를 요청받지 않았다면 요청한 글을 반환한다.

장문·여러 문서의 작성과 편집을 여러 단계로 맡은 주 작업 조정자는 파일 쓰기가 허용된 경우
[작업 연속성](../../references/continuity.md) 지침으로 원문·초안·처리 구간을 기록한다.
다른 작업의 출력 문체만 담당할 때는 별도 기록을 만들지 않는다.
