# Writing

독자가 글을 읽고 이해하거나 판단하거나 행동하는 데 필요한 내용을, 요청한 언어와 형식으로 쓴다.
문장 안의 관계, 문단의 역할과 정보 순서를 다룬다. 언어별 표현 지침과 실제 업무 양식은 그 지침을 소유한 스킬과 함께 적용한다.

## 요청한 범위에서 작성한다

문맥에서 독자, 목적, 출력 언어와 편집 범위를 파악한다. 이미 알 수 있는 정보를 다시 묻거나
짧은 답변·한 문장 수정에 별도 계획, 점수, 작업 파일이나 여러 번의 개작 절차를 요구하지 않는다.
빠진 정보가 결과를 좌우할 때만 확인하고, 나머지는 알려진 내용으로 진행한다.

| 요청 | 다루는 범위 |
| --- | --- |
| 새 작성 | 제공된 사실·합의로 목적에 맞는 구성을 만든다. 빈칸을 채우려고 새 사실이나 결정을 만들지 않는다. |
| 부분 수정 | 지정된 문장·항목과 필요한 연결만 고친다. 기존 문서의 제목 체계·순서를 전체 재편하지 않는다. |
| 전체 재작성 | 자유 초안의 문장·문단·제시 순서를 바꿀 수 있다. 지정 양식과 의미를 담는 절차 순서는 유지한다. |
| 요약 | 목적에 맞게 정보를 줄이되 남긴 주장의 조건·예외·확실성을 보존한다. 실행용 절차 전체처럼 오인하게 만들지 않는다. |

[의미와 형식 보존](references/integrity.md)을 적용하고,
[문장·문단 구성](references/composition.md)으로 실제 읽기 어려운 관계를 다듬는다.
설명이나 비교를 요청받지 않았다면 수정 과정 대신 요청한 글을 반환한다.

## 필요한 작성 지침을 함께 적용한다

사용자·프로젝트가 지정한 양식과 작성 관례를 우선한다. 일반 답변이나 문장 수정에 장르별 양식을
억지로 씌우지 않는다. 해당 문서를 작성할 때만 다음 지침을 읽는다.

| 작성 대상 | 참고 자료 |
| --- | --- |
| README | [처음 읽는 사람의 이해와 실행](references/readme.md) |
| 코드·API 주석 | [호출 계약, 이유와 유지보수 정보](references/comments.md) |
| 동료에게 보낼 요청·보고·인계 | [메시지의 요청과 맥락](references/messages.md) |

티켓·PR은 전달받은 항목 안에서 공통 구성 지침을 적용한다. 구체적인 기본 양식·필수 항목·양식
조회와 게시 절차는 `workflow:to-ticket` 또는 `workflow:to-pr`의 책임이다. Workflow가 이미 작업을
맡았다면 다시 호출하지 않는다. Writing만 사용할 때도 주어진 사실로 초안을 만들 수 있지만,
임시 구성을 저장소의 유효한 양식이나 Workflow 기본 양식으로 확정하지 않는다.

프롬프트 언어가 아닌 **요청된 출력 언어**에 맞는 Fluent 스킬이 현재 inventory에 있으면 함께 적용한다.

| 출력 언어 | 선택적 표현 지침 |
| --- | --- |
| 한국어 | `fluent-languages:fluent-korean` |
| 日本語 | `fluent-languages:fluent-japanese` |
| English | `fluent-languages:fluent-english` |

이미 적용한 스킬은 다시 불러오지 않는다. 여러 언어에서는 각 부분에 필요한 지침만 적용한다.
Fluent가 없으면 Writing의 구성·보존 지침으로 계속 작성하며, 미설치 지침을 읽었다고 주장하거나
설치·연결을 요구하지 않는다. 독자·목적·사실·출력 언어·편집 범위와 정해진 구성을 함께 전달해
한 초안에 필요한 규칙을 반영한다. 스킬마다 별도 작업이나 완성본 재작성 단계를 만들지 않는다.
표현 선호와 전달된 사실·조건·고정 양식이 충돌하면 보존 기준을 따른다.

외국어 인용, 고유명과 기술 용어를 임의 번역하지 않는다. 코드 주석·commit message·UI처럼
프로젝트가 관리하는 문자열은 사용자 지시와 프로젝트 관례를 먼저 따른다.

## 초안과 외부 작업을 구분한다

양식이 전달되지 않아도 글을 작성·편집할 수 있다. 그 초안이 실제 저장소나 팀의 유효한 양식을
충족한다고 추정하지 않는다. 이 스킬은 원격 조회·게시·링크 상태 효과를 결정하지 않는다.
Workflow 등 외부 작업의 담당자가 전달한 사실, 유효한 양식·필수 필드, 보호할 연결 문법과
첨부 위치 안에서 작성한다. 문장이 자연스러워졌다는 이유로 게시 준비가 끝난 것은 아니다.

장문·여러 문서의 작성과 편집을 여러 단계로 맡은 메인 controller만
[task-continuity](../task-continuity/SKILL.md)로 원문·초안·처리 구간을 기록한다.
다른 작업의 출력 문체만 담당할 때는 별도 기록을 만들지 않는다. 파일 쓰기가 금지되면 기록과
Git exclude도 수정하지 않는다.
