# 의미와 형식 보존

## 의미와 보호 문자열을 유지한다

사실, 주장, 귀속, 인과 관계와 영향 범위를 보존한다. 부정·긍정, 조건·전제·예외·제한,
확실성과 의무·허용 수준도 유지한다. 관찰·가설·선호·제안·합의·실행 결과를 구분하고,
불분명한 주체·담당자·원인은 미확인 상태로 남긴다. `미기록`과 `미정`, 담당자 배정과 실제 실행은
각각 다른 사실이다. 없는 결론·수치·사례·출처·경험을 채워 넣지 않는다.

새 문서의 참고 자료에서는 목적에 필요한 내용을 선별할 수 있다. 사용자가 포함하도록 지정한
내용은 유지한다. 원문 편집에서 생략은 요청된 범위에서만 허용하며, 전체 재작성이나 표현 다듬기를
사실을 임의로 삭제할 권한으로 해석하지 않는다. 선별한 주장의 진위를 좌우하는 조건·예외는 함께 남긴다.

편집 대상과 최종 문서에 포함하는 다음 내용은 명시적인 수정 요청이 없는 한 그대로 보존한다.

- fenced code block과 fence, inline code, 명령어·option·환경 변수·경로·식별자
- API endpoint·HTTP method·signature·JSON/YAML key, 로그·오류 메시지
- 버전·commit SHA·ticket ID, 수치·날짜·단위, URL·Markdown link destination
- 직접 인용문, 보호 문자열과 literal

요약에서는 목적에 불필요한 내용을 생략할 수 있다. 남긴 주장의 진위를 결정하는 조건·예외는
유지한다. 인용을 의역할 때는 직접 인용 표시를 없애고 원래 의미와 출처를 남긴다.

## 편집 범위와 구조를 구분한다

새 작성·전체 재작성에서는 자유 초안의 문장·문단 순서와 산문·목록·표 형식을 목적에 맞게
바꿀 수 있다. 부분 수정에서는 지정 범위 밖의 제목·항목 순서·표 형태·내용을 유지한다.

지정되거나 외부 작업 담당자가 확정한 양식은 기존 항목 안에서 작성한다. 제목·순서·필수 필드·
checklist·고정 문구는 양식이 허용하는 범위에서만 바꾸고, 없는 필수 정보는 미확인으로 남긴다.
선택 항목의 작성 안내는 양식에 따라 제거할 수 있지만 고정 HTML marker는 보존한다.
용도가 불분명한 HTML comment도 유지한다.

실행 절차는 재작성하더라도 전제·단계·순서·복구 조건을 유지한다. 절차 요약은 실행용 문서와
구분되도록 개요임을 밝히고 원 절차의 위치를 남긴다.

## 외부 동작을 담는 문법을 보존한다

`Fixes`, `Closes`, `Part of`, `Ignore`와 ticket ID·Jira key·연결 URL, 자동화 marker는 상태 변경에
영향을 줄 수 있으므로 지정된 관계·문법·위치를 그대로 유지한다. 변경하거나 추가할 필요가 있으면
외부 작업 담당자가 연결 의도와 효과를 확인하게 한다.
글을 고쳤다는 사실은 게시·전송·티켓 전이·Git 작업의 권한이 아니다.
