# 의미와 형식 보존

## 바꾸면 다른 내용이 되는 것

사실, 주장, 귀속, 인과 관계와 영향 범위를 새로 만들지 않는다. 부정·긍정, 조건·전제·예외·제한,
확실성과 의무·허용 수준을 유지한다. 관찰, 가설, 선호, 제안, 합의와 실행 결과는 서로 바꾸지 않는다.
문장의 주체가 불분명해도 담당자나 원인을 임의로 채우지 않는다. `미기록`은 `미정`과 다르고,
배정된 담당자가 실제 행위자라는 근거도 되지 않는다.

입력에 있거나 그대로 포함하도록 지정한 다음 내용은 명시적인 수정 요청이 없는 한 그대로 보존한다.

- fenced code block과 fence, inline code, 명령어·option·환경 변수·경로·식별자
- API endpoint·HTTP method·signature·JSON/YAML key, 로그·오류 메시지
- 버전·commit SHA·ticket ID, 수치·날짜·단위, URL·Markdown link destination
- 직접 인용문, 보호 문자열과 literal

요약에서는 요청 목적에 불필요한 내용을 생략할 수 있지만, 남긴 주장의 진위를 바꾸는 조건과 예외를
지우지 않는다. 인용을 의역할 때는 직접 인용 표시를 없애고 원래 의미와 출처를 유지한다.
원문이나 결과가 없으면 새로운 결론·수치·사례·출처·경험을 만들어 완결하지 않는다.

## 편집할 수 있는 구조

자유 초안의 제시 순서와 고정 계약을 구분한다. 새 작성·전체 재작성에서는 문장·문단을 옮기고
산문·목록·표를 목적에 맞게 선택할 수 있다. 부분 수정에서는 지정 범위 밖의 제목·항목 순서와
표 형태를 유지한다. 원문에 목록이 있다는 사실만으로 전체 재작성에서도 그 형식을 고정하지 않는다.

사용자가 지정하거나 외부 작업 담당자가 확정한 양식의 제목·순서·필수 필드·checklist·고정 문구는
그 양식이 허용한 범위에서만 바꾼다. 기존 항목에 내용을 넣고 기본 양식의 제목을 뒤에 덧붙이지 않는다.
필수 정보가 없으면 실제 미확인 상태를 남긴다. 선택 항목의 작성 안내 제거와 고정 HTML marker
보존은 서로 다르다. marker인지 알 수 없는 HTML comment는 임의 삭제하지 않는다.

실행 절차의 전제·단계·순서·복구 조건을 재작성만으로 바꾸거나 합치지 않는다. 절차 요약은 개요임이
드러나게 쓰고 원 절차의 위치를 남긴다. 빠진 단계가 있는 요약을 그대로 실행할 수 있는 절차처럼 제시하지 않는다.

## 외부 동작을 담는 문법

`Fixes`, `Closes`, `Part of`, `Ignore`와 ticket ID·Jira key·연결 URL, 자동화 marker는 설명문처럼
보여도 상태 변경에 영향을 줄 수 있다. 지정된 관계·문법·위치를 문체 개선 때문에 번역·치환·이동하거나
새로 만들지 않는다. 의미나 위치를 바꿀 필요가 있으면 외부 작업 담당자가 연결 의도와 효과를 확인하게 한다.
글을 고쳤다는 사실은 게시·전송·티켓 전이·Git 작업의 권한이 아니다.
