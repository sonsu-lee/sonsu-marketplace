# 협업과 언어 선택

설치된 스킬 중 요청한 작업과 출력 언어에 필요한 지침만 같은 초안에 적용한다. 다른 플러그인이 없으면 Writing의 구성·보존 지침으로 작성한다.

## 담당 작업을 구분한다

| 담당 | 적용할 때 |
|---|---|
| Writing | 업무 문서의 정보 선별·배치, 개발자 블로그의 흐름·근거를 구성한다. |
| Engineering | 실제 제품 결함의 진단·수정과 구현 검증이 주목적인 작업을 맡는다. 글에는 전달받은 근거를 사용한다. |
| Research | 외부 다중 출처 조사·교차 검증이 글의 결론을 좌우할 때 적용한다. |
| Fluent | 출력 언어의 표현·어순·어조를 다듬는다. |
| Workflow | 티켓·PR 양식 조회·필수 항목·실제 변경과 근거 확인·연결 문법·게시·재조회를 맡는다. |

티켓·PR 설명은 `workflow:to-ticket`·`workflow:to-pr`가 전달한 항목 안에서 쓴다. 양식이 없으면 사실에 근거한 임시 초안으로 두고 유효한 저장소·팀 양식 확인은 Workflow 절차에 남긴다.

## 출력 언어에 맞춰 적용한다

| 스킬 | 적용 범위 |
|---|---|
| `fluent-english:fluent-english` | 일상·기술 문장의 작성·윤문·검토 |
| `fluent-japanese:fluent-japanese` | 일상·기술 문장의 작성·윤문·문서 진단. 기술 문서의 장 구성·Markdown 정리는 Writing이 맡는다. |
| `fluent-korean:fluent-korean` | 한국어 산출물의 생성 규칙, 기존 일상 메시지·기술 설명의 AI 티·번역투 윤문·진단. 일반 대화 답변·단순 맞춤법 교정·번역은 자동 선택 대상에서 제외하고 단순 교정은 Writing이 맡는다. |

한국어 블로그 `draft`에서는 Fluent Korean이 설치되어 있으면 해당 스킬의 `references/drafting-rules.md`를 읽어 생성 규칙을 적용한다. 설치되어 있지 않으면 Writing 지침으로 작성한다.

독자·목적·선별한 사실·언어·편집 범위·구성을 공유하고 이미 적용 중인 지침에 필요한 부분만 보탠다. 외국어 인용·고유명·기술 용어는 유지한다. 코드 주석·commit message·UI 등 프로젝트가 관리하는 문자열은 사용자 지시와 프로젝트 관례를 따른다. 표현 선호가 사실·조건·고정 양식과 충돌하면 보존 기준을 적용한다.

## 호스트의 호출 표기를 사용한다

이 문서의 `plugin:skill`은 Codex·Claude Code 표기다. omp에서는 접두어 없는 스킬 이름으로 찾는다. Research도 Codex·Claude Code에서는 `research:research`, omp에서는 `research`로 찾는다. 각 플러그인의 설치 여부를 확인해 선택하고 Writing만 설치된 경우에도 작업을 완성한다.
