# 정보 자산의 제작과 보존

사진·로고·앨범 아트처럼 정체성을 보존할 자산, 지도·차트·도식처럼 의미에 맞춰 표현할 자산,
과업 기여에 따라 대체·제거할 장식을 구분한다. 정보 자산의 문제를 바깥 카드 장식이나 기존
비트맵 확대만으로 해결하지 않는다.

1. 보존할 데이터·관계·방향·순서·단위·상태와 사용자가 읽을 질문을 정한다.
2. 질문에 맞는 시점·축·척도·표시 범위·집계·밀도·기호·라벨을 선택한다.
3. 기반 구조를 만들고 데이터를 결합한다. 정밀도가 필요한 구현은 실제 데이터와 적합한 렌더러를 쓴다.
4. 배경 맥락·기반 구조·핵심 데이터·현재 상태·라벨의 위계를 정한다. 강조가 기반 구조를 가리지 않게 한다.
5. 영역 자체를 확대해 의미·기하·연결·정렬·가독성을 대조한다.

| 자산 | 확인할 증거 |
| --- | --- |
| 지도 | 도로망 → 경로 → 현재 위치의 연결, 적절한 시점·범위·밀도. 경로가 도로를 따르고 위치와 주변 맥락이 구별된다. |
| 차트 | 질문에 맞는 차트 형태, 축·척도·단위·범례·집계와 실제 값의 대응. 표현 변경이 비교·변화를 왜곡하지 않는다. |
| 도식 | 노드 역할·연결 방향·분기·순서·그룹이 실제 관계와 일치한다. |
| 표·복합 위젯 | 비교 열, 행 정체성, 요약·상세 관계, 선택·조작 범위가 분명하다. |

명세에 이번의 선택과 보존할 의미를 구체적으로 쓴다. 예를 들어 경로를 읽기 어려운 원근 지도는
상부 시점과 필요한 범위의 도로망으로 다시 설계할 수 있다. 도로의 실제 좌표를 모르면 디자인용
도식임을 표시하고 실제 지도 복원·정확한 길 안내로 보고하지 않는다. 차트도 예시 값과 실제 값을 구분한다.

원본 자산의 의미·정체성을 보존하지 못했거나, 영역만 커지고 문제였던 표현은 그대로라면 실패다.
실제 데이터가 부족할 때는 필요한 데이터와 구현의 미확인을 남기되 가능한 표현 설계까지 막지 않는다.
