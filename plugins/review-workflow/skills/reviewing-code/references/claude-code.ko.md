# Claude Code 실행

> 영문 정본: [claude-code.md](claude-code.md) (`5b362ef` 기준 번역).
> 사람이 읽기 위한 번역본이며 에이전트는 이 파일을 읽지 않는다.

Claude Code에서 일반 플러그인 리뷰를 통제할 때만 이 참조를 읽는다. 배정받은
커스텀 리뷰어는 이 문서 대신 공통 스킬과 자신의 배정을 읽는다.

## 진입 경로 분리

`/code-review`, 그 별칭인 `/review`, `/security-review`, ultrareview를 내부
작업자로 호출하지 않으며, 다른 Claude Code CLI를 띄우지 않는다. 네이티브
전용으로 명시한 요청은 플러그인 오케스트레이션 없이 네이티브 워크플로를
유지한다.

## 대상과 브리프 준비

공통 스킬이 요구하는 대로 대상을 고정하고 공유 브리프를 준비하며, 일반적인
절대 경로를 쓴다. 작업자는 이 대화나 이미 호출된 스킬 없이 시작한다.
`Base directory for this skill:` 줄에 나온 절대 경로로 불러온 `SKILL.md`를
주고, 적용되는 제약을 밝힌다.

## 리뷰어 디스패치와 수집

일반 리뷰어와 집중 리뷰어 하나 이상을, 각각 `subagent_type: "general-purpose"`
로 하여 한 메시지의 Agent 호출로 시작한다. `"fork"`는 절대 쓰지 않는다. 포크는
이 대화를 상속하므로 리뷰어가 독립적이지 않다. omp의
`review-workflow-focused` 프로필을 쓰지 않는다. 변경이 작다고 해서 일반 플러그인
리뷰가 이 작업자들을 면제받지는 않는다.

단독 리뷰에서는 사용자가 명시적으로 요청할 때만 스킬 기준 작업자를 추가한다.
승인된 구현 컨트롤러도 `executing-work`나 `authoring-skills`를 충족하기
위해, 사용자의 두 번째 동의 없이 이를 배정할 수 있다. 리뷰 컨트롤러는 공유
브리프, 설치된 `authoring-skills` `SKILL.md`의 절대 경로, 스킬 지침 질문
하나와 함께 같은 메시지에서 한 번만 디스패치한다. 이 작업자는 그 스킬을 작성
점검이 아니라 기준으로 쓴다. 스킬을 쓸 수 없으면 필요한 리뷰를 빼지 말고
충족하지 못한 커버리지로 보고한다.

생성 확인이 아니라 각 작업자의 전체 최종 결과를 쓴다. 기다리는 동안 sleep,
폴링, 깨우기(wakeup) 예약을 하지 않는다. 깨우기는 이후 턴에서 요청을 다시
재생한다.

Agent 도구가 거부되었거나, 권한이 거부되었거나, 동시 실행 한도에 걸렸거나,
작업자가 중단되거나 잘렸다면 리뷰는 불완전하다. 단일 에이전트나 네이티브
리뷰로 대체하지 말고 그렇게 보고한다.

참고: [Claude Code subagents](https://code.claude.com/docs/en/sub-agents).
