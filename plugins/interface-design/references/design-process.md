# 과업에서 디자인으로

## 의미와 제약

사용자·숙련도·사용 장소·입력 방식, 핵심 과업·완료 상태, 실제 콘텐츠·행동과 디자인 시스템을
확인한다. 플랫폼, 사용 목적, 산출물을 별도 축으로 기록한다. 확인된 사실·가정·미결정을 구분하고
화면을 완성하기 위해 없는 제품 규칙·수치·인과를 만들지 않는다. 긴 문장, 여러 자릿수, 0·1·여러
항목과 현지화처럼 구조의 한계를 드러내는 콘텐츠를 사용한다.

화면을 그리기 전에 사용자가 답해야 할 `primary_question`, 기대 결과와 잘못 판단했을 때의
비용을 먼저 쓴다. 과업마다 정보를 `must_know`, `supporting`, `on_demand`로 나누고 의미·출처·
신선도·불확실성을 기록한다. 각 정보가 어떤 표현으로 왜 제공되는지 연결한다.

리디자인은 보존할 의미와 변경할 표현을 구분한다. 모호한 값·중복·반복 기호는 의미를 확인하기
전에 삭제·통합하지 않는다. 새 설계도 관련 없는 기능을 늘리지 않는다.

## 정보 구조와 공간

중요도·긴급성·확인 빈도·다음 행동의 의존 관계로 우선순위를 정하고 그룹 → 읽는 순서 → 공간을
설계한다. 함께 비교할 정보는 같은 기준으로 정렬하고 판단 근거와 해당 행동을 가깝게 둔다.
모든 정보를 같은 크기의 카드로 나누거나 필수 정보를 작은 글자로 압축하지 않는다.

읽기 순서는 왼쪽→오른쪽이라는 전역 규칙이 아니다. locale, `writing_mode`, 화면 방향, 입력
방식과 플랫폼 convention을 environment로 선언하고 실제 콘텐츠에서 확인한다.

읽기 중심 화면은 본문 폭·제목·요약·다음 탐색을, 비교 화면은 행·열과 기준을, 입력 흐름은
앞 단계와의 관계·피드백을 먼저 정한다. 지도·차트·편집기가 핵심이면 그 내부를 읽고 조작할
연속 공간을 먼저 확보하고 보조 정보의 크기를 조절한다. 비율은 해당 화면의 근거로만 쓴다.

## 시각 체계

기존 component와 semantic token을 우선한다. 참고 자료의 좌표·색만 복사하지 않고 위계·밀도·
여백·형태가 과업에 기여하는 방식을 해석한다. 방향 비교를 요청한 경우 의미 있게 다른 대안을 제시한다.

- 제목·핵심 수치·행동·본문·보조 라벨의 역할을 구분하고 실제 언어·긴 콘텐츠로 타이포그래피를 확인한다.
- 값·단위·상태를 함께 읽게 배치하고 문자열 전체 폭, 반복 행과 숫자의 정렬을 맞춘다.
- 간격은 관계와 그룹 경계를 표현한다. 카드·선·그림자는 실제 그룹·조작·겹침 관계에 사용한다.
- 주 정보·선택·행동·상태·배경의 색 역할과 강조 면적을 정한다. 상태는 색만으로 전달하지 않는다.
- 아이콘은 의미·비례·라벨을 확인하고 정확한 브랜드·인물·상품에는 원본 자산을 사용한다.
- 모션은 상태·공간 변화를 설명하는 데 사용하고 감소된 모션 설정과 과업 지연을 확인한다.

## 상태와 수정

조작 → 상태 변화 → 피드백 → 다음 행동을 연결한다. 해당 흐름의 loading·empty·error·permission·
pending·success·disabled 상태를 다루되 존재하지 않는 상태를 형식적으로 만들지 않는다.
오류·취소·뒤로 가기에서 입력과 작업 맥락의 보존·삭제가 요구사항과 맞는지 확인한다.

수정 전 가장 큰 문제, 원인이 있는 단계, 기대하는 변화를 짧게 정한다. 구조·공간·표현 방식처럼
큰 영향을 주는 문제부터 고치고, 해결된 뒤 기준선·작은 간격·아이콘 비례를 조정한다. 같은 실패가
반복되면 명세 충돌·데이터 부족·도구 한계를 구분한다. 비슷한 금지 문장을 계속 추가하지 않는다.
일반 작업에서 매번 이미지를 처음부터 생성하거나 스킬 자체를 수정하지 않는다.
