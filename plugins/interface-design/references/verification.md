# 실제 결과 검증

요청된 산출물에 필요한 항목을 `passed / failed / blocked / inconclusive / not_run`과 근거로
기록한다. 적용 대상이 아닌 검사는 이유와 함께 제외하고 성공 근거로 세지 않는다.

1. 대표 과업을 따라 필요한 정보를 찾고 판단하고 행동할 수 있는지 확인한다.
2. 요구사항·원본·데이터와 대조해 값·단위·상태·관계·권한·조작의 누락·중복·임의 변경을 확인한다.
3. 전체·축소 화면에서 읽는 순서·밀도·강조를, 실제 크기에서 잘림·겹침·대비·정렬을 확인한다.
4. 지도·차트·도식 내부의 데이터 대응·표현을 전체 화면과 별도로 검사한다.
5. 요청된 창 크기·입력 방식·긴 콘텐츠·데이터 변화·오류/빈 상태를 확인한다.
6. 원본·참고 방향·직전 최선 결과와 비교해 개선과 퇴보를 함께 기록한다.

제안은 실제 시각적 제안과 명세의 일치를 확인한다. Figma는 screenshot·구조·binding·resize와
요청된 reaction/playback을 분리한다. 코드는 실제 실행 환경의 렌더링·조작·검사 결과를 연결한다.
정적 시안의 버튼을 동작 구현으로, 모의 데이터의 그림을 실제 데이터 검증으로 보고하지 않는다.

실패는 원인이 있는 설계·자산·상태·실행·데이터 단계로 돌려 수정한다. 정보 오류를 미적 개선으로
상쇄하지 않는다. 필요한 도구가 없어 요청 산출물을 만들지 못하면 준비된 명세와 미완료 범위를
반환하고 완료를 주장하지 않는다. 사소한 선호 차이만으로 무한 반복하지 않는다.

결과 파일/미리보기, 주요 결정·전후 차이, 실제 검사와 남은 미확인을 전달한다. 재현성이 요청된
경우에만 같은 입력·명세로 독립 실행을 추가한다. 이전과 같은 화면·대화에서의 성공을 다른 제품의
범용성 증거로 확대하지 않는다.
