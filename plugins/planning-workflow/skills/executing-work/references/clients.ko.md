# 클라이언트별 실행

> 영문 정본: [clients.md](clients.md) (`5b362ef` 기준 번역).
> 사람이 읽기 위한 번역본이며 에이전트는 이 파일을 읽지 않는다.

위임이나 독립 리뷰를 조율할 때만 읽는다. 현재 호스트의 도구 스키마, 권한, 지시가
우선한다. 작업자에게는 명시적인 배정과 해당 제약이 필요하다. 작업자가 대화를
물려받는다고 가정하지 않는다. 구현, 테스트, 정리에는 이름 붙은 에이전트를
만들어 내지 말고 쓸 수 있는 일반 작업자를 쓴다. 위임을 얻으려고 지속되는
클라이언트 설정을 바꾸지 않는다.

- **omp:** 노출된 `task` 인터페이스와 유효한 에이전트 프로필을 쓴다. 코드 리뷰
  컨트롤러는 `reviewing-code`의 omp 실행 참조를 따르며, 네이티브 리뷰어와
  스킬 리뷰어 디스패치도 거기에 포함된다. 그 컨트롤러가 없는 스킬 단독 작성은
  `authoring-skills`의 omp 리뷰 절차를 쓴다. 생성 확인이 아니라 완료된 결과를
  수집한다.
- **Codex:** 노출된 서브에이전트 인터페이스와 실제 스키마를 쓴다. 코드 리뷰는
  `reviewing-code`의 Codex 참조가 새 일반 작업자, 독립된 컨텍스트, 결과 수집을
  설명한다. 스킬 기준 리뷰는 실행 시 독립 리뷰가 기본이다. 코드 리뷰
  컨트롤러가 이를 이미 포함하지 않으면 `authoring-skills` 기준으로 명시적으로
  배정한다. omp 프로필 이름이나 필드가 있다고 가정하지 않는다.
- **Claude Code:** 노출된 Agent 도구와 적절한 일반 작업자를 쓴다. 코드 리뷰는
  `reviewing-code`의 Claude Code 참조가 설명하는 독립된 일반 작업자와 집중
  작업자를 따른다. 스킬 기준 리뷰는 실행 시 독립 리뷰가 기본이다. 코드 리뷰
  컨트롤러가 이를 이미 포함하지 않으면 `authoring-skills` 기준으로 명시적으로
  배정한다. 포크(fork)를 독립 리뷰어로 쓰거나 omp 프로필 이름이 있다고
  가정하지 않는다.

Codex나 Claude Code에서 스킬 기준 리뷰를 배정할 때는 새 작업자에게 설치된
`authoring-skills` SKILL.md의 절대 경로, 변경의 목적, 의도한 사용자, 변경된
파일, 적용되는 요구 사항, 구체적인 스킬 지침 질문을 준다. 리뷰 컨트롤러가
없으면 통합 책임자가 이 배정을 맡고, 있으면 컨트롤러가 이를 한 번만 포함하도록
지시한다. 리뷰어는 수정하지 않고 작성 점검도 실행하지 않는다. 필요한 위임이나
독립성을 확보할 수 없으면 그 한계를 밝히고, 이루어졌다고 주장하지 않는다.
