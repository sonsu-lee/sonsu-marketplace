# UI 증거

> 영문 정본: [ui-evidence.md](ui-evidence.md) (`a482860` 기준 번역).
> 사람이 읽기 위한 번역본이며 에이전트는 이 파일을 읽지 않는다.

UI 변경에는 리뷰어가 애플리케이션을 실행하지 않고도 바뀐 위치, 모습, 동작을 이해할
수 있도록 시각적 증거를 제공한다. 저장소의 증거 요건이 있으면 먼저 따른다. 이것은
리뷰를 위한 증거이며, 테스트를 대체하거나 모든 동작을 확인했다는 주장이 아니다.

## 보여 줄 것 고르기

녹화하기 전에 증거를 계획한다. 보여 주려는 변경, 시작 상태, 동작, 기대 결과를
정한다. 쓸모 있는 최소한의 미디어 묶음을 고른다.

| 변경 | 기본 증거 | 보여 줄 것 |
| --- | --- | --- |
| 레이아웃, 스타일, 문구, 정적 상태 | 스크린샷 | 위치와 차이 |
| 입력, 탐색, 상태 전환 | 동영상 | 시작, 동작, 결과 |
| 애니메이션, 타이밍, 응답 순서 | 동영상 | 트리거와 실제 동작 |
| 중요한 모습과 상호작용 | 둘 다 | 서로 다른 유용한 세부 사항 |
| 관찰 가능한 UI·상호작용 변경 없음 | 생략 가능 | 자명하지 않으면 설명 |

파일 확장자만이 아니라 실제 diff를 기준으로 고른다. 동영상의 마지막 프레임을 그대로
옮긴 스크린샷은, 그 세부 사항이 유용하지 않다면 첨부하지 않는다. 변경이나 저장소
정책과 관련이 없는 모든 뷰포트, 테마, 상태를 요구하지 않는다. 변경이 드러나는
조건을 포함한다.

필요 없는 증거와, 캡처하거나 표시하거나 업로드할 수 없는 증거를 구분한다. 후자는
빠진 선결 조건과 함께 미완료로 보고한다. 허가된 Draft에는 그 공백을 기록할 수
있다. 하지만 증거가 완전한 것처럼 제시하거나 조용히 ready for review가 되어서는
안 된다.

## 실제 구현을 캡처하기

문서화된 설정으로 관련 애플리케이션이나 프리뷰를 실행한다. 실제로 바뀐 화면과
시나리오를 캡처한다. 목업, 합성한 UI, 조작한 이전 상태로 대신하지 않는다. 안전한
테스트 데이터를 쓰고 프로덕션 부작용을 피한다.

기존 UI라면 비교할 수 있는 Before와 After 화면을 선호한다. 가능하면 뷰포트, 줌,
데이터, 테마, 시작 상태를 맞추고 각 버전에 이름표를 붙인다. 새 화면은 After만
써도 된다. 이전 동작을 재현할 수 없다면 그렇게 밝히고, 비교를 억지로 만들지 말고
차이를 설명한다.

위치를 알아볼 수 있을 만큼 주변 UI를 남긴다. 맥락이나 회귀를 가리지 않을 때만 관련
없는 여백을 자른다. 관련 조건은 환경을 빠짐없이 나열하지 말고 캡션에 기록한다.

## 모든 스크린샷에 표시하기

바뀐 영역을 상자, 화살표, 번호 표시로 표시한다. 텍스트나 보여 주려는 동작을 가리지
않는다. 여러 영역이 중요하면 번호 표시와 그에 맞는 짧은 캡션을 쓴다. 리뷰어가 변경을
찾아다니거나 색깔 상자의 의미를 짐작하게 해서는 안 된다.

사용할 수 있는 이미지 주석 도구를 쓴다. 예를 들어 FFmpeg이 설치되어 있다면 스크린샷의
나머지 부분은 그대로 두고 상자를 추가할 수 있다.

```sh
ffmpeg -i before.png \
  -vf 'drawbox=x=120:y=80:w=240:h=100:color=red:t=3' before-marked.png
```

좌표는 예시일 뿐이다. 이 예시가 아니라 실제로 캡처한 이미지를 보고 고른다. 원본
캡처가 보존되도록 표시한 파일을 따로 쓴다. 결과 이미지를 의도한 표시 크기로
확인한다. 선택한 도구를 쓸 수 없으면 다른 사용 가능한 도구를 쓰거나 차단 요인을
보고한다. 표시하지 않은 이미지를 완료된 증거로 조용히 첨부하지 않는다. 허가 없이
도구를 설치하지 말고 사용자의 설치 정책을 따른다.

설명하는 이미지 대체 텍스트와, 변경을 짚는 캡션을 제공한다. 표시는 주의를 끌고
캡션은 그 의미를 설명한다.

## 녹화를 이해하기 쉽게 만들기

각 녹화는 바뀐 흐름 하나에 집중한다.

1. 주변 캡션이나 짧은 시작 라벨로 시나리오를 밝힌다.
2. 알아볼 수 있는 시작 상태를 보여 준다.
3. 관련 동작을 수행하며 그 대상이 보이게 한다.
4. 결과를 이해할 수 있을 만큼 충분히 유지한다.

변경을 찾는 데 필요하면 커서나 클릭 강조, 콜아웃, 간결한 화면 텍스트를 쓴다. 오디오만
믿지 않는다. 텍스트는 읽을 수 있게 두고 관련 없는 설정, 로그인, 대기, 무관한 탐색은
뺀다. 관련 없는 시연은 하나의 긴 투어로 만들지 말고 나눈다.

동작이 다를 때는 가능하면 같은 Before와 After 시나리오를 보여 준다. 검토 대상인
타이밍이나 순서를 빠르게 돌리거나 이어 붙이거나 편집해서 없애지 않는다. 의미 있는
컷이나 동영상처럼 제시한 이미지 시퀀스, 그리고 그로 인해 타이밍이나 순서에 대해
확립되는 것의 한계를 밝힌다. 캡션은 모든 클릭이나 제작 단계가 아니라 주목할 점을
설명한다. 캡처 지표는 증거 해석에 영향을 줄 때만 포함한다.

## 확인하고 게시하기

업로드하기 전에 최종 이미지를 모두 열고 최종 동영상을 모두 재생한다. 다음을 확인한다.

- 캡처가 의도한 리비전에서 나왔고 실제로 변경을 보여 준다.
- 표시, 캡션, 중요한 텍스트를 읽을 수 있고 결과를 가리지 않는다.
- 녹화에 관련 트리거와 결과가 있고, 오해를 부르는 편집이나 설명 없는 상태 변화가
  없다.
- 자격 증명, 토큰, 개인정보, 비공개 알림, 고객 데이터가 노출되지 않는다. 정제된
  테스트 데이터를 선호하고 가림 처리를 확인한다.

저장소 템플릿의 증거 위치를 쓰고, 없으면 PR 본문의 전용 영역을 쓴다. 검증 내용
문장은 간결하게 쓰고 설명을 반복하지 말고 미디어를 가리킨다. 저장소가 별도 댓글을
요구하면 증거를 찾을 수 있도록 본문에서 그 댓글로 링크한다.

업로드가 허가되었다면 [첨부 절차](publishing.md#attach-and-verify-media)를 읽는다.
업로드 후 렌더링된 PR을 확인한다. 이미지는 의도한 위치에 불러와져야 하고 녹화는
재생되어야 한다. UI 리비전이 바뀔 때마다 캡션과 증거를 동기화한다. 오래된 증거는
현재 결과처럼 보이게 두지 말고 제거하거나 분명히 표시한다. 미디어는 리뷰용 산출물이며,
프로젝트가 명시적으로 요구하지 않는 한 커밋할 저장소 에셋이 아니다.
