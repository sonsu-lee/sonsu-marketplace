# UI 증거

> 영문 정본: [ui-evidence.md](ui-evidence.md) (`fed67c3` 기준 번역).
> 사람이 읽기 위한 번역본이며 에이전트는 이 파일을 읽지 않는다.

저장소의 증거 요구사항을 우선 따른다. 실제 변경을 보여 주는 최소한의 자료를 고른다.
정적인 모습은 스크린샷, 상호작용·상태 전환·타이밍은 비디오를 사용하고, 각각 다른
정보를 보여 줄 때는 둘 다 사용한다. 변경을 확인하는 데 필요한 조건을 포함한다. 눈에
보이는 UI나 상호작용 변경이 없다면 증거를 생략할 수 있으며 이유가 분명하지 않으면
설명한다.

캡처, 표시 또는 업로드에 실패한 것은 증거가 불필요하다는 뜻이 아니다. 빠진 증거와
필요한 선행 조건을 보고한다. 허가된 Draft에 그 공백을 기록할 수 있지만 완료된 것처럼
표현하지 않는다.

## 캡처와 표시

의도한 리비전의 실제 애플리케이션이나 문서화된 미리보기를 실행한다. 안전한 테스트
데이터를 쓰고 운영 환경에 부작용을 일으키지 않는다. 목업, 합성 UI 또는 조작한 이전
상태로 대체하지 않는다. 기존 UI는 가능하면 조건을 맞춘 Before와 After를 표시한다.
새 화면은 After만 보여 줄 수 있다. 이전 상태를 재현할 수 없다면 그 사실을 밝힌다.

화면 위치를 알아볼 수 있는 맥락을 남긴다. 각 스크린샷의 변경 영역을 상자, 화살표
또는 번호로 표시하되 결과를 가리지 않는다. 설명적인 대체 텍스트와 표시의 의미를
설명하는 짧은 캡션을 추가한다.

비디오는 알아볼 수 있는 시작 상태, 동작, 결과를 보여 준다. 시나리오를 밝히고 필요하면
대상을 강조한다. 오디오에만 의존하지 않는다. 검토 대상인 타이밍이나 순서를 편집으로
없애지 않는다. 중요한 편집이나 이미지 시퀀스를 공개하고 그것이 증명할 수 있는 범위의
한계를 밝힌다.

## 확인과 게시

최종 이미지마다 열어 보고 비디오마다 재생한다. 의도한 리비전과 변경, 읽을 수 있는
표시와 캡션, 관련 동작과 결과를 확인한다. 자격 증명, 토큰, 개인정보, 비공개 알림,
고객 데이터가 노출되지 않았는지 확인한다. 정제된 데이터를 쓰고 가림 처리도 확인한다.

저장소가 요구하는 위치에 증거를 두고, 요구사항이 없다면 PR 본문에 둔다. 별도 댓글이
필요하면 링크한다. 업로드가 허가되었다면 [게시 절차](publishing.md#edge-cases)를
따른다. 렌더링된 배치와 재생을 확인하고 확인하지 못한 항목은 보고한다. UI가 바뀌면
오래된 증거를 갱신하거나 표시한다. URL을 얻기 위해서만 미디어를 커밋하지 않는다.
