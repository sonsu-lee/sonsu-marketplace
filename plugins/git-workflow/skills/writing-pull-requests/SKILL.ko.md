# 풀 리퀘스트 작성하기

> 영문 정본: [SKILL.md](SKILL.md) (`fed67c3` 기준 번역).
> 사람이 읽기 위한 번역본이며 에이전트는 이 파일을 읽지 않는다.

PR 설명은 리뷰어가 diff를 다시 짜 맞추지 않고도 무엇이 바뀌었고 어디에 집중해야
하는지 알게 해 준다. 왜 그 작업이 필요했는지는 연결된 티켓이 담는다. 저장소의
기여 규칙과 템플릿 필수 항목이 우선한다. 글을 작성하거나 수정할 때는 해당 언어
스킬도 읽는다.

## 요청된 작업 고르기

- **제목만:** 변경을 파악하고 제목을 검증한다.
- **내용 초안:** diff를 읽고 설명을 작성한다.
- **게시, 수정, Ready 전환:** 요청된 작업만 수행한다.

## 변경과 범위 파악하기

저장소, head, 대상 브랜치를 확인한다. 사용자 지정이나 프로젝트 기준을 따르고,
없으면 기본 브랜치를 확인한다. base 대비 전체 diff와 관련 티켓이나 설계 맥락을 읽는다.

하나의 PR은 하나의 목적을 다루며 구현, 호출부, 테스트, 필수 문서를 함께 포함한다.
독립적인 변경은 분리하되 분량을 줄이려고 관련 파일을 나누지 않는다. 각 PR이 병합된
상태에서도 대상 브랜치는 정상 동작해야 한다.

미병합 PR에 의존하면 base를 고르기 전에
[스택 PR](references/stacked-prs.md)을 읽는다. 독립적인 PR은 각각 trunk를 대상으로 한다.

## 제목 작성과 검증

제목은 최종 커밋 subject로 작성하고 [writing-commits](../writing-commits/SKILL.md)로
검증하며, 수정할 때마다 다시 검증한다. 작업 순서가 아닌 최종 변경을 설명한다.
작업 중인 PR은 제목 접두사가 아니라 GitHub Draft 상태로 표시한다.

## 본문 작성

`## Summary`로 시작해 무엇을 바꿨는지 짧게 설명한다. 추가 설명이 필요할 때만
내용에 맞는 소제목을 붙인다. 고정된 목차를 채우지 않는다. 작은 변경은 Summary만으로 충분하다.

적용되는 저장소 템플릿을 읽고 CLI나 API로 제출할 때도 필수 항목과 마커를 보존한다.
GitHub는 기본 브랜치의 템플릿을 제공한다. 필수 형식이 다르면 요약에 해당하는
항목을 사용하고 중복 섹션을 추가하지 않는다.
GitHub 저장소에 적용되는 템플릿이 없으면 소유자의 공개 `.github` 저장소에서 상속되는
기본 템플릿을 확인한다. 이 템플릿은 대상 저장소의 checkout에 포함되지 않는다.

이번 변경의 리뷰에 도움이 되는 내용을 고른다.

- **바뀐 동작:** 기능, 인터페이스, 구현이 어떻게 달라졌는지 설명한다.
  중요하다면 유지되는 동작도 포함한다.
- **중점적으로 볼 코드:** 조건, 처리 순서, 데이터 변환, 책임 경계처럼 리뷰에 중요한
  구현을 몇 가지 추린다. 필요하면 짧은 코드 발췌나 링크로 결정을 설명한다.
  diff를 파일별로 나열하지 않는다.
- **구조나 흐름:** 구성요소 관계나 처리 흐름은 Mermaid 다이어그램으로 보여 주고,
  같은 내용을 문장으로 반복하지 않는다.
- **제약:** 변경 이해나 병합 판단에 영향을 주는 호환성 변화, 배포 순서, 알려진 제한을 적는다.
- **UI 변경:** [UI 증거](references/ui-evidence.md)에 따라 준비하고 확인한 표시가
  있는 스크린샷이나 집중된 녹화로, 리뷰어가 앱을 실행하지 않아도 변경 위치와
  결과를 볼 수 있게 한다.

문장, 목록, 표, 체크박스는 내용에 맞게 선택한다. 배경을 반복하는 대신 관련 티켓을 연결한다.
접근할 수 있는 티켓이 없으면 문제를 짧게 적는다. 티켓에 없고 구현을 이해하는 데
필요한 결정 이유만 보충한다.

통상적인 검증 결과, 명령, 작업 일지는 넣지 않는다. 저장소가 요구하거나 성능 개선처럼
주장을 뒷받침해야 할 때만 근거를 넣는다. 근거를 해석하는 데 필요한 방법, 환경,
장단점은 유지하고 관찰 결과와 미검증 주장을 구분한다.

목록 항목을 포함해 각 문단은 소스 한 줄로 유지한다. GitHub는 PR 본문의 단일
줄바꿈을 줄바꿈으로 렌더링한다. 저장소 Markdown의 줄 길이 제한은 PR 본문에
적용되지 않는다.

이슈와 의존 관계는 내용을 복사하지 않고 링크한다. 이슈마다 적힌 목표를 최종
diff, 그리고 그 전이나 함께 반영되는 작업과 대조해, 이 PR이 그 이슈를
완료하는지, 일부만 진행하는지, 관련만 있는지 정한다. 이 PR이 완료하는 이슈는
머지되면 닫히도록 링크하고, 그 밖의 이슈는 머지 뒤에도 열려 있도록 링크한다.
base가 GitHub의 기본 브랜치가 아니면
[이슈 닫기](references/publishing.md#edge-cases)를 읽는다.

## PR 게시와 유지

게시, 수정, Ready 전환, 병합 메시지 준비 시 [PR 게시](references/publishing.md)를
읽는다. 새 PR은 Draft로 생성하고, 사용자가 요청하고 저장소의 준비 요건을 충족했을
때만 Ready로 전환한다. 후속 변경에 맞춰 제목, 본문, 링크, 미디어를 갱신한다.
