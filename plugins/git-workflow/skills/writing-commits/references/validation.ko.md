# 커밋 검증

> 영문 정본: [validation.md](validation.md) (`fcbe81d` 기준 번역).
> 사람이 읽기 위한 번역본이며 에이전트는 이 파일을 읽지 않는다.

실행 환경과 설정을 각각 독립적으로 선택한다. 설치된 스킬 디렉터리가 아니라 대상
저장소의 루트에서 실행한다.

## 저장소의 실행 환경 재사용

기여자 안내문, 패키지 스크립트, 의존성 선언과 lockfile, 관련 hook이나 CI 설정을
살펴본다. commitlint가 아니더라도 문서화된 검증기와 그 버전을 사용한다. hook이
관련 없는 작업까지 수행한다면 hook 전체를 호출하지 말고, 문서화된 메시지 검사를
제안하는 메시지를 입력으로 실행한다.

선언된 의존성이나 관리되는 도구가 설치되어 있지 않다면, 환경이 없는 것이 아니라
문서화된 설치 절차가 필요한 기존 환경이다. 실행할 수 없으면 막힌 점을 보고한다.
업그레이드하거나, 실패한 뒤 버전을 고정한 대체 수단으로 바꾸지 않는다. 설정
파일만으로는 실행기나 버전이 정해지지 않는다. 실행 환경이 없다면 대체 수단이 그
파일을 불러올 수 있다.

완성된 메시지를 정확히 그대로 임시 UTF-8 파일에 저장하고 `message_file`을 그
절대 경로로 설정한다. 파일을 다시 읽어 헤더가 비어 있지 않은지, 의도한 body와
footer가 들어 있는지 확인한다. commitlint는 빈 파일을 건너뛸 수 있다. 저장소의
검증기가 지원하는 입력 방식을 사용하고, 이전 커밋이 아니라 이 메시지를 검사하는지
확인한다. 아직 실행되지 않은 hook은 검증이 되었다는 증거가 아니다.

래퍼 명령 없이 commitlint 바이너리를 직접 설치한 저장소의 예:

```sh
./node_modules/.bin/commitlint --verbose --edit "$message_file"
```

Yarn Plug'n'Play처럼 적절한 경우에는 대신 저장소의 패키지 매니저 명령을 사용한다.
그 플래그와 경고 정책을 유지하며, 기존 명령에 `--strict`를 무작정 추가하지
않는다.

## 기존 실행 환경이 없을 때만 npx 사용

대체 수단에는 Node.js 22.12.0 이상과 npm이 필요하다. 첫 실행에는 npm 레지스트리
접근이 필요하다. 대상 저장소에 의존성을 추가하지는 않는다.

저장소에 commitlint 설정이 있으면 그것을 유지한다.

```sh
npx --yes --package @commitlint/cli@21.2.4 commitlint \
  --verbose --edit "$message_file"
```

명시적으로 선택한 설정 경로는 `--config`로 따른다. 필요한 preset과 plugin을
유지하고 그 문서화된 설정 방법을 따른다. 명시적으로 선택한 설정이 없거나, 설정이
잘못되었거나, 의존성이 호환되지 않으면 막힌 점이며 번들 기본값으로 대체하지
않는다. 설정 문제를 숨기려고 `--default-config`를 사용하지 않는다.

## 설정이 없을 때만 기본값 선택

저장소의 commitlint 설정이 정해져 있지 않은 경우에만, `skill_dir`을 불러온
`SKILL.md`가 있는 디렉터리의 절대 경로로 설정하고 그 안의
`assets/commitlint.config.mjs`를 사용한다. 플러그인 캐시 경로를 짐작하지 않으며
에셋을 저장소로 복사하지 않는다. 불러온 위치나 에셋을 찾을 수 없으면 검증을
우회하지 말고 설치 또는 조회 오류를 보고한다.

commitlint가 이미 설치되어 있다면 그 실행 파일을 유지하고, 지원되는 메시지 검사
호출에 `--config "$skill_dir/assets/commitlint.config.mjs" --strict`를 추가한다.
이 에셋을 불러오려고 버전을 교체하지 않으며, 불러올 수 없으면 호환되지 않는다고
보고한다. 다른 검증기라면 그 문서화된 동작을 유지하고, 그 검증기가 검사하지 않는
스킬 기본값은 직접 검토한다.

실행 환경도 설정도 없는 경우:

```sh
npx --yes --package @commitlint/cli@21.2.4 commitlint \
  --config "$skill_dir/assets/commitlint.config.mjs" \
  --strict --verbose --edit "$message_file"
```

번들 설정은 외부 preset이나 import가 없는 독립적인 ESM이다. `!`, 호환성을 깨는
변경 footer, 또는 둘 다를 허용한다. 메시지가 변경을 정확히 설명하는지는 판단하지
않는다.

## 검사 마무리

정상 종료와, 의도한 메시지가 검사되었다는 증거를 요구한다. 저장소에 이미 있는 경고
수준을 따른다. 번들 기본값은 오류도 경고도 없어야 한다. 실행 실패를 검증 성공으로
취급하거나 조용히 다른 도구로 바꾸지 않는다. 메시지를 수정할 때마다 다시 검사하고
끝나면 임시 메시지 파일을 삭제한다.

대체 수단을 실행하려고 새 프로젝트 매니페스트, 설정, hook, CI job을 설치하지
않는다. 도구 설치와 설정 변경은 커밋 메시지 작성과 별개의 일이다.
