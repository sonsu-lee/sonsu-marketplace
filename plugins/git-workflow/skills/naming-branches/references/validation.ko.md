# 브랜치 검증

> 영문 정본: [validation.md](validation.md) (`599da29` 기준 번역).
> 사람이 읽기 위한 번역본이며 에이전트는 이 파일을 읽지 않는다.

실행 환경과 설정을 각각 독립적으로 선택한다. 대상 저장소의 루트에서 실행한다.
`branch_name`은 제안하는 이름 그대로 설정한다. `@{-1}` 같은 Git 축약 표기나
`refs/heads/`를 포함한 전체 경로는 쓰지 않는다.

먼저 Git ref 문법을 확인한다.

```sh
git check-ref-format --branch "$branch_name"
```

이 명령은 Git 문법만 확인하며 저장소의 이름 규칙은 확인하지 않는다.

## 저장소의 실행 환경 재사용

기여자 안내문, 스크립트, 의존성 선언, 관리되는 도구 버전, 관련 hook이나 CI
설정을 살펴본다. commit-check가 아닌 도구를 포함해, 문서화된 브랜치 검증기와
그 버전을 사용한다. 그 설정, 환경 설정, 통과 기준을 유지한다.

선언되었거나 관리되는 도구가 설치되어 있지 않다면 문서화된 설치 방법을 따른다.
그것이 대체 수단을 써도 된다는 허가는 아니다. 설정된 검증기를 사용할 수 없거나
실패하면 다른 것으로 바꾸지 말고 그 사실을 보고한다. 설정 파일만으로는 실행기나
버전이 정해지지 않으므로, 실행 환경이 없을 때는 대체 수단이 그 파일을 불러올 수
있다.

검증기가 지원하는 후보 이름 입력 방식을 사용한다. 현재 브랜치만 검사하는
명령이 제안한 이름을 보게 하려고 브랜치를 만들거나 이름을 바꾸지 않는다. 현재
체크아웃된 브랜치를 검사한 결과로 제안한 이름이 통과했다고 주장하지도 않는다.
설정된 도구가 변경 없이는 제안한 이름을 검사하지 못한다면, 조용히 다른 검증기로
바꾸지 말고 그 한계를 보고한다.

브랜치 이름을 stdin으로 받는 commit-check 버전의 경우:

```sh
printf '%s\n' "$branch_name" | commit-check --branch --format json
```

저장소의 래퍼, 관리되는 환경, 설정된 버전은 그대로 유지한다. 이 예시를 쓰기 전에
설치된 버전이 이 입력을 지원하는지 확인한다. hook이 관련 없는 검사까지 함께
실행한다면 hook 전체를 호출하지 않는다.

## 기존 실행 환경이 없을 때만 uvx 사용

[Conventional Branch](https://conventionalbranch.org/#tooling)는
[commit-check](https://github.com/commit-check/commit-check)를 링크한다. 이것은
Python CLI이며 npm 패키지가 아니다. 대체 수단은 `npx commit-check`가 아니라 uv의
`uvx`와 Python 3.10 이상을 사용한다. 캐시가 없는 첫 실행에는 레지스트리 접근이
필요하다.

저장소에 commit-check 설정이 있으면 그것을 유지한다.

```sh
printf '%s\n' "$branch_name" |
  uvx --from commit-check==2.19.1 commit-check --branch --format json
```

버전을 고정한 CLI는 저장소 루트 또는 `.github/`의 `cchk.toml`과
`commit-check.toml`을 찾는다. `--config`로 명시적으로 선택한 설정과 기존
`CCHK_*` 설정을 따른다. 저장소 규칙을 대체하는 플래그는 넘기지 않는다.
명시적으로 선택한 설정이 없거나 환경이 망가졌다면 그것은 막힌 점이며,
번들 기본값으로 바꿔도 된다는 허가가 아니다.

## 설정이 없을 때만 기본값 선택

저장소 브랜치 설정이 정해져 있지 않은 경우에만, `skill_dir`을 불러온 `SKILL.md`가
있는 디렉터리의 절대 경로로 설정하고 그 안의 `assets/commit-check.toml`을
사용한다. 플러그인 캐시 경로를 짐작하지 않으며 이 파일을 대상 저장소로 복사하지
않는다.

호환되는 commit-check가 이미 설치되어 있다면 그 실행 파일을 유지하고
`--config "$skill_dir/assets/commit-check.toml"`을 추가한다. 에셋을 불러오려고 버전을
올리지 않으며, 호환되지 않으면 그 사실을 보고한다. 다른 검증기를 쓴다면 그 문서화된
동작을 유지하고, 그 검증기가 검사하지 않는 스킬 기본값은 직접 검토한다.

실행 환경도 설정도 없는 경우:

```sh
printf '%s\n' "$branch_name" |
  uvx --from commit-check==2.19.1 commit-check --branch --format json \
    --config "$skill_dir/assets/commit-check.toml"
```

번들 설정은 허용 접두사를 스킬의 기본값으로 좁히고 description 문법 검사를
켠다. 허가된 에이전트 접두사처럼 저장소나 사용자가 명시적으로 고른 것을 대체해서는
안 된다. 그런 선택은 저장소의 규칙 설정이나 실행마다 명시하는 재정의로 처리하되,
관련 없는 규칙을 넓히지 않는다. 이 도구는 특수한 CI ref 이름도 허용하므로 스킬의
trunk 이름 제한은 직접 적용한다.

## 검사 마무리

정상 종료와, 정확히 그 후보 이름에 대한 브랜치 검사 결과를 요구한다.
commit-check의 JSON 출력이라면 `CC201` 항목의 `value`와 `status`를 확인한다.
건너뛴 규칙이나 다른 이름에 대한 결과는 검증이 되었다는 증거가 아니다. 저장소의
경고 정책을 따른다. 번들 기본값을 쓸 때는 `CC201`이 경고 없이 통과해야 한다.
`--dry-run`으로 통과를 확정하지 않는다.

목적, 이슈 ID, 접두사 선택은 별도로 검토한다. 이 검사를 실행하려고 프로젝트 설정,
hook, CI를 설치하지 않는다. 런타임 부재, 네트워크 접근 불가, 설정 오류는 막힌 점으로
보고한다. 제안한 이름이 바뀔 때마다 다시 검사한다.
