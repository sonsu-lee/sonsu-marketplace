# Runner 선택과 실패 처리

> 영문 정본: [runtime.md](runtime.md) (`fcbe81d` 기준 번역).
> 사람이 읽기 위한 번역본이며 에이전트는 이 파일을 읽지 않는다.

스크립트 실행이 실패하거나 경고를 출력할 때, `--genre`나 런타임을 고를 때, 또는
upstream의 시맨틱 실험에 대해 질문받았을 때 읽는다. 리소스 확인(`SKILL_DIR`,
절대 파일시스템 경로, 캐시 경로 추측 금지)은 [스킬](../SKILL.md)에서 정의한다.
여기의 모든 명령은 같은 `SKILL_DIR`와 `TARGET`을 쓴다.

## Runner와 장르

알면 `--genre tech`, `business`, `essay`를 고르고, 확실하지 않으면 생략한다.
Python import는 스크립트 옆에서 해결되므로 소스 체크아웃, 개발 파일, 코퍼스가
필요 없다. 프로젝트에 설정된 런타임이 있으면 그것을 쓴다. 없으면 uv가 스크립트의
인라인 의존성 선언을 사용한다. 이 스킬을 쓰기 위해 프로젝트 설정, 전역 설치,
사용자 설정, 훅을 바꾸지 않는다.

quick 모드에서도 짧은 글에 lint를 실행한다. 통계적 탐지기에 데이터가 너무 적어도
한 문장이 구(phrase) 검사를 일으킬 수 있기 때문이다.

## 실패와 수동 검토

실행할 수 없으면 [수동 검토](manual-checklist.md)를 쓰고, 기계적 검사를 하지
못했음을 밝힌다. 설정된 runner, 의존성, 입력, 스크립트의 실패는 조용히 수동
검토나 다른 runner로 넘어가도 된다는 허가가 아니다. 실패를 보고하고 원인을
해결한다. 계속 막혀 있으면 수동 관찰을 따로 표시한다. 점수를 지어내지 않는다.

결과가 많아도 종료 코드는 0이고, 입력 오류는 0이 아닌 값을 반환한다. JSON뿐
아니라 stderr도 읽는다. 잘못된 baseline은 upstream 경고를 내고 비교를 생략할 수
있다. 그런 결과를 근거로 수렴했다고 주장하지 않는다. 경고를 성공한 비교로
취급하지 말고 baseline을 고친다.

## 시맨틱 실험 없음

upstream의 선택적 시맨틱 모델 실험은 여기에 포함되어 있지 않다. 이 변형에는
`exp` 모드나 자동 모델 다운로드가 없다. 그 요청에는 이 제한을 설명해야 하며,
full 검토를 실험이라고 조용히 바꿔 부르지 않는다.
