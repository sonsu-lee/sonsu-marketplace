# 구조와 가독성 검토

> 영문 정본: [readability.md](readability.md) (`fcbe81d` 기준 번역).
> 사람이 읽기 위한 번역본이며 에이전트는 이 파일을 읽지 않는다.

full 모드에서, 그리고 lint나 `--reading-load`의 가독성 결과를 고쳐야 할 때
읽는다. 그런 결과가 없는 quick 모드에서는 필요 없다. `SKILL_DIR`와 `TARGET`은
[스킬](../SKILL.md)에서 가져오며, 스킬 3절의 수정 한계와 보존 규칙이 아래의 모든
변경에 적용된다. 문서 유형을 알면 `doctypes/`의 해당 문서 유형 가이드를 쓴다.

작성 책임을 에이전트 사이에 나누지 않는다. 강조와 전환은 문서 전체를 한 시점에서
봐야 한다. 병렬 읽기는 긴 문서에 실제로 도움이 될 때만 유용하며, 편집 책임은
당신에게 남는다.

## Full 모드 명령

항상 `tech`를 쓰지 말고 적절한 장르를 쓴다. `--reading-load`는 별도의 편집
경로이며 자연스러움 점수나 baseline 비교에 들어가지 않는다.

```sh
uv run "$SKILL_DIR/scripts/outline.py" "$TARGET"
uv run "$SKILL_DIR/scripts/terms.py" "$TARGET"
uv run "$SKILL_DIR/scripts/lint.py" --reading-load --genre tech "$TARGET"
```

## 구조

lint는 표면 패턴을 살피므로, 회의록이나 슬라이드에서 결과가 드문 것은 그 구조에
대해 알려 주는 바가 거의 없다. 제목과 문단의 시작을 이어서 읽는다. 논지를 따라갈
수 있는지, 제목이 유용한 내용을 전달하는지, 반복되는 정의, 시작, 절 구조가
강조를 흐리지 않는지, 독자가 필요로 할 때 결론이 나오는지 확인한다. 사실을 다루는
산문에 서스펜스 구조를 억지로 씌우지 않는다. 장애 분석에서는 시간순이 근거가 될
수 있고, 에세이에서는 의도된 것일 수 있다. 새 보고서에서는 뒷받침되는 다음
행동을 확인하고, 수정에서는 원문에 있는 것만 평가한다. 해당하는 문서 유형
레퍼런스를 적용한다.

## 가독성 순서

1. 중첩된 부정과 조건. 진리 조건을 보존한다. 「設定が無効でない限り」와
   「設定が有効なら」는 설정되지 않았을 때 다르다(설정이 무효가 아닌 한 / 설정이
   유효하면). 이 구분이나 의도적인 유보를 단순화하여 없애지 않는다.
2. 의존 관계: 여러 주장은 나누고, 주어와 서술어를 맞추고, 긴 수식어를 앞에 두고,
   구조상의 경계에 문장부호를 찍는다. 「〜が、」의 반복과, 「これ」「それ」의
   선행사가 정확히 하나인지 확인한다.
3. 어휘 부담: 한자가 일곱 개 이상 이어지는 곳과 「の」가 세 개 이상인 곳을
   살핀다. 명사화가 동작을 감추고 있으면 동사를 되살린다. 행위자를 알 때만
   반복되는 수동태를 명확히 한다. 정확하다면 모호한 외래어를 바꾸되, 확립된
   용어나 식별자는 바꾸지 않는다.
4. 중복: 정보 손실이 없을 때 「〜することができる」 → 「〜できる」,
   「〜という形になる」 → 「〜になる」.
5. 문단: 끊김 없는 벽 같은 문단도, 이어진 논리를 끊는 파편화도 피한다. 기존에
   의도된 줄바꿈은 존중한다.
6. 문장 속 목록: 병렬 항목이 세 개 이상일 때, 그 문장이 너무 길 때만 드러낸다.
   모든 항목을 기본적으로 **굵은 라벨**과 설명으로 만들지 않는다.
7. 문단을 가로지르는 반복: 정보가 없는 중복만 제거한다.
8. 용어: 일관된 이름을 쓴다. `terms.py`는 편집 검토를 위해 처음 쓰인 곳과
   설명이 필요할 수 있는 곳을 나열한다.
9. 구조와 전제 지식: 스킬 3절의 수정 한계 안에서, 늦게 나오는 결론과 설명 없는
   전문 개념을 확인한다.

간결함이 목표는 아니다. 먼저 사실과 문법 관계를 보존하고, 똑같이 충실한 후보
사이에서만 더 짧은 표현을 택한다. 더 명확하게 나눈 문장이나 목록은 더 길 수 있다.
