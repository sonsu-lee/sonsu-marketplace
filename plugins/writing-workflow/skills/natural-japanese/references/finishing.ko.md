# 처리, 수렴, 작업 파일

> 영문 정본: [finishing.md](finishing.md) (`7cd88a9` 기준 번역).
> 사람이 읽기 위한 번역본이며 에이전트는 이 파일을 읽지 않는다.

편집하거나 초안을 쓸 때 lint 뒤에 읽는다. 각 결과의 처리를 기록하고, 언제 멈출지
정하고, 원문과 비교하고, 작업 파일을 다루기 위한 것이다. 점수만 매기는 요청은
건너뛴다. 명령, `SKILL_DIR`, `TARGET`은 [스킬](../SKILL.md)에서 가져온다.

## 처리

lint는 구(phrase), 번역투, 반복되는 부정, 단조로운 문장 길이, 명사형 종결의
부재, 어휘 재사용, 영어식 구문을 탐지한다. 결과는 의심일 뿐 지시가 아니다. 세부
정보와 힌트를 참고해 문맥에서 판단하며, 문장을 소리 내어 읽어 보면 도움이 될 수
있다. 각 결과의 처리를 응답이나 작업 공간에 기록한다.

```text
- [Fixed] translationese「〜という点で」: changed to「〜では」.
- [Kept/product name] forbidden_phrase「多角的」: part of「多角的レビュー機能」.
```

인용, 기술 용어, 필요한 대비, 장르 관습처럼 구체적인 이유를 쓴다. 이유 없는
“Kept”는 편집상의 결정이 아니다.

## 수렴

편집한 뒤 lint를 다시 실행한다. 이전 JSON 파일을 `--baseline`으로 넘기면 결과를
`resolved`, `new`, `persisting`으로 분류한다.

```sh
uv run "$SKILL_DIR/scripts/lint.py" --json --genre tech \
  --baseline "$BASELINE" "$TARGET"
```

임의의 반복 횟수가 아니라, 모든 결과가 고쳐졌거나 이유와 함께 명시적으로 유지되고
편집으로 해결되지 않은 새 결과가 생기지 않았을 때 끝낸다. 어떤 결과가 두 번
다시 나타나면 동의어를 돌려 쓰지 말고 그 문장이나 문단을 다시 생각하거나, 이유와
함께 유지한다. 결과 수가 적다고 해서 언어적 품질, 사실 충실성, 사람이 썼음이
증명되지는 않는다.

## 원문과 비교

수정본을 편집 전 원본 그대로와 비교한다. 원본을 달리 구할 수 없다면 덮어쓰기
전에 작업 공간에 보존한다. 새 초안은 허가된 자료와 비교하고, 문단 수준의 구체적
의미 검토도 수행한다. 다음 도우미는 새로 나타난 숫자, 고유명사, ASCII 단어를
나열한다.

```sh
uv run "$SKILL_DIR/scripts/newfacts.py" "$ORIGINAL" "$TARGET"
uv run "$SKILL_DIR/scripts/newfacts.py" --git "$TARGET"
```

`--git`은 HEAD와 비교하며, 이미 존재하던 커밋되지 않은 변경과는 비교하지 않는다.
HEAD가 의도한 원본일 때만 쓰고, 그렇지 않으면 확보해 둔 편집 전 사본을 쓴다.
뒷받침되지 않는 추가는 제거하거나 원래 내용을 복원한다. 직접 뒷받침되는 확장은
남겨 둘 수 있다. 이 도우미는 추가된 일반 명사 세부 사항, 바뀐 확실성, 사라진
조건, 뒤바뀐 화자를 탐지하지 못한다. 출력이 비어 있어도 수동 비교는 여전히
필수다.

## 작업 파일

lint JSON, 처리 메모, 원본 사본, 초안 백업은 대상 옆이 아니라 환경의 임시
디렉터리나 `mktemp -d`로 만든 디렉터리에 둔다. 끝나면 자신이 만든 임시 작업
파일만 제거한다. 요청받은 최종 문서와, 명시적으로 요청받은 경우의 작성자 프로필만
사용자 프로젝트에 남긴다. 이 워크플로는 대상 텍스트를 게시하거나 전송하지 않는다.
게시는 허가된 산출물 워크플로가 맡는다.
