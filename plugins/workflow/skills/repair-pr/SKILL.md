# PR 복구

정확한 PR의 요청된 문제를 확인하고 가장 작은 수정과 검증을 수행한다. Engineering이나
다른 플러그인이 없어도 이 절차로 완료한다. 이미 진행 중인 개발 작업의 필수 검증은 유지한다.

## 범위와 작업 공간

1. [PR 조회](../../references/pr-inspection.md)로 PR URL, host/repository, base/head SHA와 상태,
   실패 CI와 미해결 대화를 확인한다. 번호 생략 시 현재 브랜치의 유일한 PR을 사용한다.
2. 요청이 CI만·리뷰만이면 그 범위를 유지한다. 스킬 이름만 지정했고 실행 목적이 없다면
   상태와 필요한 범위를 먼저 확인한다. 자동 선택·이름 지정은 commit·push·댓글·대화 해결 권한이 아니다.
3. repo 지침, 현재 HEAD/branch, staged/unstaged/untracked와 진행 중 Git operation을 읽는다.
   관계없는 변경을 stash/reset/restore하지 않는다. 다른 PR branch나 충돌 작업은 소유한 격리
   worktree에서 수행하고 baseline·원격 ref를 기록한다. 필요한 객체만 확인된 remote에서 fetch한다.
4. fork PR은 base 저장소와 실제 push 대상 head 저장소·ref를 구분한다. 정확한 head를 확보할 수
   없으면 수정하지 않는다. 사용자의 기존 작업 공간에서 무조건 `gh pr checkout`하지 않는다.

## 1. 충돌

충돌 해결이 범위에 있으면 최신 base를 확인해 PR head에 merge한다. rebase·force push와 일괄
ours/theirs 선택은 기본 절차가 아니다. commit 승인이 없으면 소유한 격리 공간에서
`git merge --no-commit --no-ff <verified-base-ref>`로 자동 commit을 막고 해결 결과와 필요한 검사를 준비한다.
실패한 merge는 실제 상태를 읽어 판단하며 중간 상태·격리 경로를 보존해 전달한다.

계약·주변 코드·테스트를 근거로 충돌을 해결하고 관련 검사를 실행한다. merge commit을 포함한
commit이 승인되었다면 해당 범위만 생성한다. 후속 CI가 commit을 요구하지만 승인이 없으면 가능한
로컬 검증을 마치고 그 제한을 명시한다. 전달할 미커밋 결과가 있는 worktree를 삭제하지 않는다.

## 2. 리뷰 의견

요청 범위의 미해결 의견을 작성자와 무관하게 읽는다. outdated/중복은 현재 코드와 대조하며
오래됐다는 이유만으로 해결 처리하지 않는다. 현재 동작·계약·테스트에서 발생 조건과 영향을 확인한다.

- 수정 필요: 같은 원인의 의견을 묶어 최소 수정하고 해당 회귀와 가까운 보존 동작을 검증한다.
- 근거로 기각: 잘못된 전제를 코드·계약·검사 근거로 설명한다. 맞는 코드를 리뷰에 맞추려고 바꾸지 않는다.
- 추가 확인 필요: 필수 근거·결정의 공백과 영향을 보고한다. 불확실함을 기각으로 바꾸지 않고 대화를 남긴다.

권한이 있는 독립 수정은 계속한다. 하나의 의견이 불명확하다고 관련 없는 승인 작업까지 멈추지 않는다.
답글은 작업 대상 저장소의 언어 규칙과 사용자 요청을 따른다.

## 3. CI 실패

현재 head의 실패 check와 정확한 run/job 로그를 읽고 독립 원인과 연쇄 실패를 구분한다.
프로젝트 지침·manifest에서 검증 명령을 도출한다. 환경·권한·서비스 장애인지 코드 결함인지
확인하고 관찰된 원인만 수정한다. 외부 check 로그가 없으면 추정 수정 대신 미확인을 보고한다.
검사를 통과시키려고 assertion·보안 검사·hook·branch protection을 약화하지 않는다.

## 전달과 원격 반영

최종 diff와 관련 검사를 확인하고 [원격 복구 결과](references/remote-results.md)를 따른다.
commit은 독립적으로 설명·되돌릴 변경 목적별로 구성한다. push가 승인되면 로컬 수정을 마친 뒤
한 번의 일반 push를 기본으로 한다. 새 원격 변경은 fetch/readback으로 확인하고 덮어쓰지 않는다.
자동 감시·병합은 하지 않는다.

결과에는 해결·기각·추가 확인 필요, 변경과 격리 경로, 로컬 검사, 실제 원격 head·CI 상태,
게시·대화 해결 결과와 미실행을 나눠 보고한다. 로컬 성공을 push 후 CI 성공으로 보고하지 않는다.
여러 단계 복구는 [작업 연속성](../task-continuity/SKILL.md)에 target/head·승인·문제별 상태를 기록한다.
