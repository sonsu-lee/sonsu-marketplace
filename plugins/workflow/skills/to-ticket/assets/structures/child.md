# 자식 구조 — `child`

상위 목표 중 독립적으로 맡고 완료할 결과가 있을 때 선택한다. 부모의 긴 배경을 복사하지 않는다. parent가 아직 불명확하면 추정 ID 대신 미해결 관계로 표시한다.

접수에는 맡을 결과 또는 확인할 질문과 부모 맥락이 필요하다. 실행 준비에는 자신의 범위·완료 조건, 공통 제약의 연결과 필요한 선행 결과가 확인되어야 한다.

## 선택한 종류의 본문에 통합할 내용

```markdown
## 맡을 결과와 상위 맥락
<자신의 결과·범위와 parent locator 또는 게시 전 client_key>

## 완료 조건
- <이 자식만으로 판정할 수 있는 결과>
```

종류별 목적·완료 section을 위 의미로 구체화하고 bug 재현 증거 같은 고유 내용은 유지한다. parent가 native field로 표시되면 body에 ID를 반복하지 않고 맡는 범위와 필요한 공통 제약만 보존한다. 형제와의 dependency는 실제 선행 조건이 있을 때만 native relation으로 다룬다.

자식 종료는 자신이 맡은 결과의 판정이다. 다른 자식이나 전체 목표를 완료로 표현하지 않는다. 독립 결과가 아닌 단순 작업 절차는 자식으로 늘리지 않는다.
