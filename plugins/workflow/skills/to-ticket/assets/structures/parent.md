# 부모 구조 — `parent`

여러 독립 결과의 전체 목표를 추적할 때 선택한다. 부모는 template 종류나 자동 생성할 Epic·project가 아니다. tracker의 실제 hierarchy와 생성 권한을 확인한다.

접수 단계에서는 전체 목표와 아직 나눌 수 없는 질문을 기록한다. 실행 준비에는 포함 범위, 자식별 결과, 실제 의존 관계와 전체 완료 판정이 필요하다. 자식 수·담당자·일정을 채우기 위해 만들지 않는다.

여러 초안의 관리 정보에는 부모·자식 각각의 `client_key`와 자식의 parent 참조를 기록하여 게시 전에도 관계를 검토할 수 있게 한다. 실제 remote ID가 확인되면 매핑하며 키를 본문마다 반복하지 않는다.

## 본문에 통합할 내용

```markdown
## 전체 목표와 범위
<전체 사용자·시스템 결과, 포함 범위·비목표·공통 제약>

## 자식별 결과
- <자식 locator 또는 게시 전 client_key>: <자식이 맡는 독립 결과>

## 선행 관계
<실제로 진행을 막는 자식 간 의존성만>

## 전체 완료 조건
- <자식 결과를 합쳐 충족해야 할 전체 결과와 필요한 검증·제공 조건>
```

선택한 종류의 목적·범위·완료 조건을 위 section에 대응시켜 한 번만 작성하고, migration 복구 조건 같은 고유 의미는 보존한다. 유효한 팀 양식이 있으면 그 heading 안에 같은 의미를 채운다. 자식의 재현 절차·상세 수용 기준은 복제하지 않는다.

자식 완료만으로 전체 목표·검증·배포가 충족되는지 확인한다. tracker의 자식 기반 자동 종료 정책을 사용할 때는 필요한 독립 검증·배포 결과도 추적 구조에 반영하거나 부모 종료 조건과의 차이를 보고한다. 정책을 자동 수정하지 않는다. 초안 구조 자체로 parent를 완료 전이하지 않는다.
