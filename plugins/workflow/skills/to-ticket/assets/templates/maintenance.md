# 유지보수·문서·리팩터링 — `maintenance`

## 선택과 준비 상태

dependency·설정·문서·내부 품질을 정비하면서 기존 속성을 보존할 때 선택한다.

- 접수 최소 정보: 변경할 대상과 필요한 이유가 있으면 접수한다.
- 실행 준비: 목표 상태와 보존해야 할 실제 동작·호환성·문서 의미, 완료 조건이 확인되어야 한다.

## 기본 본문

공통 작성 기준에 따라 단계에 필요한 section만 사용한다. 완료·판정 기록은 실제 결과가 있을 때 채운다.

```markdown
## 변경 대상과 이유
<정비할 대상·현재 문제·목표 상태>

## 보존할 속성
<확인된 동작·호환성·문서 의미와 승인 제약>

## 완료 조건
- <목표 상태와 필요한 보존 속성을 확인할 결과>
```

## 종료와 다음 관계

목표 상태와 명시된 보존 속성을 확인한다. 근거 없는 전 영역 무회귀 약속을 만들지 않는다.

같은 유지 목적은 같은 티켓에 둔다. 데이터 변환·cutover가 별도 결과이면 migration을 연결한다.
