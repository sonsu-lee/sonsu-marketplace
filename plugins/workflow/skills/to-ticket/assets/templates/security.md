# 보안 취약점·개선 — `security`

## 선택과 준비 상태

취약점 접수 또는 보안 결과를 추적하며 공개 범위·민감 정보 취급을 구분해야 할 때 선택한다.

- 접수 최소 정보: 민감 내용을 노출하지 않는 증상·영향 경계·안전한 근거 locator로 접수한다. 위험도·원인·악용 가능성은 확인된 범위만 쓴다.
- 실행 준비: 정확한 제한 대상 공간·허용된 공개 범위·개선 결과·검증 기준과 제약이 확인되어야 한다. 공개 범위를 확인할 수 없으면 제한 세부 정보는 게시하지 않는다.

## 기본 본문

공통 작성 기준에 따라 단계에 필요한 section만 사용한다. 완료·판정 기록은 실제 결과가 있을 때 채운다.

```markdown
## 보안 문제와 영향 범위
<확인된 사실과 미확인 주장 구분. 공개 가능한 요약>

## 제한된 근거
<접근 권한에 맞는 locator. secret·token·원본 개인정보를 포함하지 않음>

## 개선 결과와 제약
<합의된 보안 결과·호환성·공개 제약>

## 완료 조건
- <합의된 검증 기준과 필요한 후속 처리>
```

## 종료와 다음 관계

요구된 보안 결과와 증거를 확인한다. 미검증 상태를 안전함으로 표현하거나 severity를 추정하지 않는다.

독립 조사·수정·공개 절차는 필요할 때만 분리한다. 제한된 자료를 일반 parent나 공개 PR 본문으로 복제하지 않는다.
