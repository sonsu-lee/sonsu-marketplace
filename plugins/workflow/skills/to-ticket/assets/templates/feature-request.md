# 기능 제안·요청 — `feature-request`

## 선택과 준비 상태

기능 채택 여부나 구현 범위가 결정되지 않은 제안을 기록할 때 선택한다.

- 접수 최소 정보: 누가 어떤 상황에서 겪는 문제인지, 어떤 변화가 필요한지 기록할 수 있으면 접수한다. 해결책 후보는 제안으로 표시한다.
- 실행 준비: 이 티켓을 검토하는 데 필요한 질문·결정 범위·판정 근거가 합의되면 검토 작업을 맡을 수 있다. 구현 준비와는 구분한다.

## 기본 본문

공통 작성 기준에 따라 단계에 필요한 section만 사용한다. 완료·판정 기록은 실제 결과가 있을 때 채운다.

```markdown
## 사용자 문제와 맥락
<대상 사용자·상황·현재 어려움과 근거>

## 원하는 변화
<원하는 결과와 제안된 아이디어. 미승인 제안임을 보존>

## 검토할 질문
<가치·범위·규칙 등 아직 결정되지 않은 사항>

## 검토 결론
<결론이 나온 경우에만 채택·보류·기각의 이유와 근거>
```

## 종료와 다음 관계

확인된 검토 결론과 이유를 남긴다. 채택은 구현 완료가 아니며 보류·기각을 가짜 구현 수용 기준으로 바꾸지 않는다.

채택 후 같은 결과면 같은 티켓을 feature 형식의 합의 내용으로 보강할 수 있다. 요청 검토와 여러 구현 결과의 독립 추적이 필요할 때만 분리한다.
