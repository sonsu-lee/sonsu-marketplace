# 진행 중 장애 대응 — `incident`

## 선택과 준비 상태

현재 서비스 영향의 억제·복구를 추적할 때 선택한다.

- 접수 최소 정보: 관찰된 서비스 영향과 발생 맥락·시점이 있으면 접수한다. 심각도·원인은 근거가 있을 때만 확정한다.
- 실행 준비: 복구 대상·목표·대응 경계와 확인할 회복 조건이 있으면 원인 미상이어도 대응 가능하다. 승인된 대응·복구 제약을 보존한다.

## 기본 본문

공통 작성 기준에 따라 단계에 필요한 section만 사용한다. 완료·판정 기록은 실제 결과가 있을 때 채운다.

```markdown
## 현재 영향
<관찰 시각·영향 서비스·사용자 범위와 근거>

## 복구 목표와 대응 경계
<회복할 상태·승인된 안전 조건>

## 대응 기록
<확인된 조치·시각·관찰 결과만>

## 복구 확인
<확인된 회복 상태와 남은 영향·미확인 범위>
```

## 종료와 다음 관계

실제 영향 억제·회복 기준의 충족을 확인한다. 추정 원인을 확정하지 않고 복구와 재발 방지 완료를 구분한다.

독립적인 재발 방지는 problem, 회고 기록은 postmortem으로 연결할 수 있다. 모든 장애에서 세 티켓을 자동 생성하지 않는다.
