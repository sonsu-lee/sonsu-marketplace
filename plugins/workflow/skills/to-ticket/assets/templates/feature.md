# 기능 추가·변경 — `feature`

## 선택과 준비 상태

합의된 사용자·시스템 결과를 제공할 때 선택한다. 채택 전 요청은 feature-request로 받는다.

- 접수 최소 정보: 원하는 결과와 사용 맥락이 있으면 미정 범위를 표시한 intake를 작성할 수 있다.
- 실행 준비: 사용자·시스템 결과, 포함 범위·중요한 규칙, 관찰 가능한 수용 기준이 합의되어야 한다.

## 기본 본문

공통 작성 기준에 따라 단계에 필요한 section만 사용한다. 완료·판정 기록은 실제 결과가 있을 때 채운다.

```markdown
## 목적과 기대 결과
<필요한 이유와 완료 후 사용자·시스템의 변화>

## 범위와 제약
<해석이 갈릴 범위·비목표와 승인된 결정만>

## 완료 조건
- <관찰 가능한 사용자·시스템 결과>
```

## 종료와 다음 관계

합의된 결과와 제약을 충족해야 한다. 실제 제공·배포가 완료 조건이면 코드 merge만으로 완료라 하지 않는다.

동일 결과의 검증·배포는 티켓 안에 둘 수 있다. 독립 결과가 여러 개면 parent/child를 적용하고 별도 공개 판정이 필요하면 rollout을 연결한다.
