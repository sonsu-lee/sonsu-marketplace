# 버그 보고·수정 — `bug`

## 선택과 준비 상태

기존 계약의 기대 동작과 실제 동작에 차이가 있을 때 선택한다. 기능 채택 요청은 feature-request다.

- 접수 최소 정보: 관찰된 증상과 발생 맥락 또는 증거가 있으면 접수한다. 정확한 재현 절차·원인은 없어도 되며 기대 동작의 근거가 없으면 확인 질문으로 남긴다.
- 실행 준비: 복구할 동작·영향 범위·완료 기준이 확인되면 실행 준비가 됐다. 해결 방법은 작업자가 정한다.

## 기본 본문

공통 작성 기준에 따라 단계에 필요한 section만 사용한다. 완료·판정 기록은 실제 결과가 있을 때 채운다.

```markdown
## 문제 상황
<발생 조건과 확인된 영향>
- 실제 동작: <관찰된 결과>
- 기대 동작: <계약에 따른 결과 또는 확인할 질문>

## 재현 조건 또는 증거
<최소 재현 조건·관찰 기록·안전한 로그 locator>

## 미해결 질문
<접수 후 확인해야 할 조건>

## 완료 조건
- <실행 준비 단계에서 합의된 복구 동작>
```

## 종료와 다음 관계

접수만으로 복구 완료라 하지 않는다. 실행 완료에는 원래 문제 조건에서 합의된 동작과 필요한 증거가 있어야 한다.

같은 결함의 원인·복구 기준·검증은 기존 티켓에 보강한다. 독립 조사가 필요한 때만 investigation과 실제 선행 관계를 제안한다.
