# 버그 양식

```markdown
## 현상
<!-- 필수: 실제 동작과 발생 상황, 알고 있는 영향을 설명합니다. 기대 동작은 `완료조건`에 적고 여기서 반복하지 않습니다. -->

<관찰된 동작, 발생 상황과 영향>

## 재현 정보
<!-- 조건부: 확인된 환경·시작 상태·재현 단계와 문제를 보여 주는 이미지·영상·로그·요청·응답을 필요한 만큼 적습니다.
자료가 어느 현상을 보여 주는지 설명하고 비밀·개인정보를 제거합니다. 순서가 중요한 경우에만 번호 목록을 사용합니다. -->

## 참고
<!-- 조건부: 현상과 재현 정보에 없는 수정 범위(하지 않을 일 포함)·합의된 제약, 데이터 보존·호환성 같은 유의사항,
외부 의존, 필요한 미확인 사항과 관련 근거만 적습니다.
반드시 지킬 조건과 제안·선호를 구분하고 링크·첨부에 짧은 설명을 붙입니다. -->

## 완료조건
<!-- 필수: 수정 후 확인할 수 있어야 하는 기대 동작이나 상태를 적습니다. 현상과 합의된 범위에서 도출하고 원인·수정 방법을 새로 정하지 않습니다.
자동 검증 예정이어도 기대 동작은 남깁니다. 팀 공통 절차는 넣지 않고, 테스트 케이스·검증 절차는 합의됐거나 안전·호환성에 필수일 때만 넣습니다. 기대 동작이 미정이면 결정이 필요하다는 사실을 적습니다. -->
- <확인 가능한 기대 동작이나 상태>
```

확인하지 않은 환경·단계·자료를 만들지 않는다. 자료가 없다는 사실이 작업 착수나 재현 판단에 중요할 때만 `참고`에 짧게 남긴다.
