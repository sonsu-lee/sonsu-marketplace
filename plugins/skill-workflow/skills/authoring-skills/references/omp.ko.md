# omp 작성 시 고려사항

> 영문 정본: [omp.md](omp.md) (`d7e73ba` 기준 번역).
> 사람이 읽기 위한 번역본이며 에이전트는 이 파일을 읽지 않는다.

작성하는 스킬이 omp를 대상으로 할 때 이 레퍼런스를 사용한다. 대상 프로젝트에
필요한 부분만 적응시킨다. 다른 스킬 작업에서 omp가 기본값은 아니다.

## 로딩 경로 확인하기

대상 프로젝트의 기여자 안내와 설치 안내를 읽고, [omp의 스킬 문서][skills]로 탐색
경로를 확인한다. 관례적인 디렉터리에서 로드되는 스킬과 이식 가능한 Agent Plugins
패키지로 배포되는 스킬은 메타데이터 검증이 같지 않다.

표준 루트 `plugin.json`을 가진 이식 가능한 패키지라면 스킬을
`skills/<name>/SKILL.md`에 두고 공통 Agent Skills 프런트매터를 사용한다. 다른
곳의 느슨한 스캐너가 받아 준다는 이유만으로 omp의 `hide`, `globs`, `alwaysApply`나
다른 클라이언트의 확장을 추가하지 않는다. 워크플로에 수동 명령, 파일 범위 규칙,
런타임 강제가 필요하다면 스킬 본문이나 메타데이터가 이를 제공한다고 가정하지 말고
알맞은 omp 구성 요소를 쓴다.

지원 파일은 스킬 디렉터리 안에 둔다. omp는 이를 `skill://<name>/<relative-path>`로
읽을 수 있다. 설치 캐시 경로를 스킬에 박아 넣지 않는다. omp 전용 URI가 필요 없다면
일반적인 상대 참조를 유지한다.

## 의도한 환경에서 검증하기

대상 프로젝트의 검증 및 설치 절차를 따른다. 로컬 검사에는 사용자의 실제 설치가
아니라 임시 `HOME`을 사용한다. `omp skill list`에서 의도한 스킬과 경고 줄을
확인한다. 읽을 수 있는 파일이라고 해서 탐색된다는 증거는 아니다. 관련 요청을 따로
실행해 실제 로딩과 동작을 확인하고, 검증하지 못한 동작은 보고한다.

마켓플레이스 카탈로그 필드, 버전 관리, 게시는 해당 프로젝트의 절차에 둔다. 해당
패키징 작업이 범위에 있을 때만 [공식 마켓플레이스 가이드][marketplaces]를 참고하고,
모든 스킬에 복사하지 않는다.
