# Codex 작성 시 고려사항

> 영문 정본: [codex.md](codex.md) (`fe462ed` 기준 번역).
> 사람이 읽기 위한 번역본이며 에이전트는 이 파일을 읽지 않는다.

작성하는 스킬이 Codex를 대상으로 할 때 이 레퍼런스를 사용한다. 탐색, 호출, 선택적
메타데이터는 다른 클라이언트의 설정을 복사하지 말고 대상 프로젝트의 워크플로와
최신 [Build skills 가이드][skills]를 따른다.

## 필요한 Codex 적응만 추가하기

공통 `SKILL.md` 형식을 유지하고 지침부터 시작한다. 기존 도구와 지침으로는 필요한
작업을 안정적으로 수행할 수 없을 때만 스크립트를 추가한다. Codex는 큰 초기 스킬
목록에서 description을 줄일 수 있으므로, 핵심 사용 사례와 트리거를 앞에 둔 간결한
description을 쓴다.

`agents/openai.yaml`은 워크플로에 Codex용 표시 메타데이터, 호출 정책, 도구 의존성이
필요할 때만 고려한다. 공통 Agent Skills 형식이 요구하는 파일이 아니다. 필드를
고르기 전에 최신 가이드를 확인하고, 브랜딩, 의존성, 권한 가정을 추측으로 만들어
내지 않는다.

플러그인 워크플로에서는 [플러그인 스킬 가이드][plugins]를 사용해, 스킬의 판단과
출력 계약을 도구가 맡는 실시간 데이터, 인가, 통제된 동작과 구분한다. 일반적인 도구
설정은 해당 도구의 문서에 둔다.

## 플러그인 프롬프트 로딩 한도 지키기

Agent Skills 형식 안내만이 아니라, 지원하는 Codex 버전의 실제 로더 한도를 확인한다.
Codex CLI `0.163.0`은 Agent Plugins 스킬의 메인 프롬프트를 [렌더러][renderer]에서
**8,000 UTF-8 바이트**로 제한하고, [호스트 프롬프트 주입][injection] 단계에서 잘라
낸다. 이는 버전별 플러그인 로딩 제약이며, 독립 스킬이나 다른 클라이언트에 공통된
한도가 아니다.

프런트매터를 포함한 `SKILL.md` 전체를 `wc -c`로 측정한다. 줄 수, 문자 수, 토큰
수는 바이트가 아니다. 한도를 목표로 삼지 말고 이후 수정을 위한 여유를 남긴다.
너무 크면 불필요한 지침부터 뺀다. 핵심 판단과 안전장치는 메인 파일에 두고, 조건부
세부 내용은 목적이 분명한 레퍼런스로 옮기며 각각 언제 읽을지 적는다. 필수 지침을
참조되지 않는 파일에 숨기거나 모든 레퍼런스를 무조건 로드하지 않는다. 지원하는
Codex 버전이 바뀌면 실제 로더를 다시 확인한다.

## 주장하는 지원 범위 검증하기

명시적 호출에는 탐색이 반환한 설치된 이름을 사용한다. 플러그인 스킬은 예를 들어
`$skill-workflow:authoring-skills`처럼 한정된 이름을 쓴다. `0.163.0`에서는 이름만
쓴 `$authoring-skills`로는 설치된 플러그인 스킬이 선택되지 않는다. 호출 이벤트와
실제로 주입된 프롬프트를 확인해, 메인 파일의 끝까지 완전한 내용이 잘림이나 로딩
경고 없이 모델에 전달되는지 본다. 파일의 존재, `skills/list`, 형식 검증으로는 이를
증명할 수 없다.

그다음 대표적인 작업, 암묵적 선택, 스킬을 로드하면 안 되는 인접 요청을 실행해
본다. 필요한 레퍼런스가 링크만 된 것이 아니라 실제로 읽히는지 확인한다.
[평가 가이드][evals]가 트레이스 검사를 설명한다. 버전에 민감한 명령은 재사용하기
전에 검증한다.

Codex는 평가 실행기를 제공하지 않는다. 출력과 트리거 평가에는 `evaluating-skills`
스킬이나 프로젝트 자체 도구를 쓴다. 로컬 요청 캡처는 모델 호출을 끝내지 않고도
프롬프트 로딩을 확인할 수 있지만 레퍼런스 추적이나 작업 동작은 확인하지 못한다.
인가된 모델 접근이 없다면 그 검사는 검증되지 않았다고 보고한다. 탐색 결과, 다른
클라이언트의 실행, 텍스트만의 리뷰로 Codex 호환성을 주장하지 않는다.
