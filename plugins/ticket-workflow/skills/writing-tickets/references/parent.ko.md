# 상위 티켓

> 영문 정본: [parent.md](parent.md) (`5cdc0e5` 기준 번역).
> 사람이 읽기 위한 번역본이며 에이전트는 이 파일을 읽지 않는다.

요청이 우선순위를 정하거나 미루거나 독립적으로 완료할 수 있는 여러 부분에
걸쳐 있을 때, 또는 상위 티켓, 에픽, 트래커 프로젝트를 만들거나 수정하거나
나눌 때 읽는다. 사용할 네이티브 컨테이너는 플랫폼 참조 문서가 정한다.

## 작업 순서

1. **분할 여부를 정한다.** 하위 티켓들이 따로 진행되는 동안 공유 목표를 계속
   보여 주어야 할 때만 상위 티켓을 사용한다. 작은 변경은 티켓 하나로 둔다.
   하위 티켓이 하나뿐인 상위 티켓이나 한 사람이 함께 끝내는 단계를 위한 하위
   티켓은 만들지 않는다. 코드, 필요한 테스트, 필수 문서는 함께 둔다. 문제는
   알지만 접근법이 열려 있다면 추측한 구현 하위 티켓 대신 조사용 하위 티켓이나
   미해결 질문으로 남긴다. 맥락이 뒷받침하지 못하는 분할은 지어내지 않는다.
2. **공유된 합의를 상위 티켓에 쓴다.**
   - **문제:** 현재 상황과 중요성을 밝힌다. 현재 상태가 왜 실패하는지 보여 주는
     구체적인 사례가 있으면 좋다.
   - **원하는 결과:** 여러 부분이 함께 작동할 때 관찰되는 결과를 설명한다.
     변경 전달과 이후 효과 평가가 모두 중요하다면 둘을 구분한다.
   - **제외 사항:** 인접 기능처럼 합리적인 담당자가 포함할 수 있는 작업만
     적는다. 시간이나 노력의 한도는 확립된 경우에만 기록하고 지어내지 않는다.
   - **순서:** 트래커에 표시되지 않는 하위 티켓 간 의존성을 적고, 없으면
     생략한다. 초안에서 제안하는 분할은 상위 티켓 본문 밖에 제시하고, 하위
     이슈처럼 트래커가 기본으로 보여 주는 목록은 반복하지 않는다.
   - **맥락:** 결정, 설계, 증거는 복사하지 말고 링크한다.
3. **하위 티켓을 쓴다.** 각 티켓에 고유한 문제와 판단 가능한 결과를 적는다.
   공유 정책은 상위 티켓을 링크하고, 전체 명세 대신 안전하게 행동하는 데 필요한
   로컬 제약만 남긴다. 각 요구 사항은 티켓 하나가 소유한다. 하위 티켓을
   취소하면 해당 요구 사항이 제거, 대체, 이동 중 어떻게 처리됐는지 상위 티켓에
   기록한다.
4. **완료 조건을 반영한다.** 통합, 롤아웃 또는 종단 간 검증이 결과의 일부라면
   명시한다. 트래커가 상위 티켓을 자동으로 닫는다면 별도의 하위 티켓으로
   만든다.

## 주의할 점

- 같은 상위 티켓에 속한다고 해서 하위 티켓 간 순서가 정해지는 것은 아니다.
- 하위 티켓이 모두 닫혔다고 해서 상위 티켓이 완료된 것은 아니다.
