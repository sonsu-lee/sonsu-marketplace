# Linear

> 영문 정본: [linear.md](linear.md) (`4f07d42` 기준 번역).
> 사람이 읽기 위한 번역본이며 에이전트는 이 파일을 읽지 않는다.

[티켓 작성](../SKILL.md)의 절차와 함께 아래 Linear 차이를 적용한다.

## 템플릿

- 상위 팀에서 쓸 수 있는 템플릿을 포함해 워크스페이스 및 팀 템플릿과 팀
  기본값을 확인한다.
- 생성 도구가 템플릿 매개변수를 지원하면 선택한 템플릿을 쓰고 결과를 확인한다.
  그렇지 않으면 필수 내용과 해당 속성을 직접 반영한다.

## 필드와 구조

- 팀·워크스페이스 레이블, 팀 구성원과 담당 지침, 우선순위 관례, 팀의 추정치
  설정, 대상 프로젝트의 마일스톤을 확인한다. 추정치는 활성화된 경우에만 쓰고
  티켓을 채우려고 활성화하지 않는다.
- 팀의 관행을 따른다. 하위 이슈는 이슈 하나로는 너무 크지만 프로젝트로는 작은
  작업에 적합하다. 프로젝트는 명확한 결과나 완료 예정일이 있는 이슈를 묶으며
  여러 팀에 걸칠 수 있다. 허가받지 않았다면 새 프로젝트는 만들지 말고 제안한다.
  통합이나 검증을 상위 이슈에 남기기 전에 상위 이슈의 자동 닫기 설정을 확인한다.

## 공개 범위와 연동

- 취약점 의심 내용을 기록하기 전에 팀의 공개 범위와 공개 저장소로 연결되는
  GitHub Issues Sync가 있는지 확인한다.
- 실제 Linear 이슈 식별자를 쓴다. 자동 상태 변경에 의존하기 전에 연동
  워크플로를 확인하고 결과 PR 연결을 확인한다.

## 주의사항

- 템플릿 기본값은 팀 구성원과 비구성원에게 다를 수 있으며 익숙한 이름이
  기본값이라는 뜻은 아니다. 워크스페이스 템플릿은 팀 고유 레이블이나 상태를
  미리 설정할 수 없다. API 생성에 UI 기본값이 반드시 적용되는 것은 아니며,
  제목이 일치해도 특정 템플릿이 사용되었다는 증거는 아니다.
- 하위 이슈는 상위 이슈의 팀, 우선순위, 프로젝트를 상속하지만 레이블은
  상속하지 않는다. 팀은 모든 하위 이슈가 끝나면 상위 이슈를 자동으로
  닫도록 설정할 수 있다.
- PR 설명에서 `Fixes ENG-123`은 설정된 머지 상태를 적용하고,
  `Refs ENG-123`은 그 상태를 적용하지 않고 부분 작업을 연결하지만 다른 설정된
  상태 전환을 일으킬 수 있다. `Related to ENG-123`은 상태 변경 없이 맥락을
  연결한다. PR 댓글은 이런 연결을 만들지 않는다. 이슈 ID가 든 브랜치도 자동
  연결될 수 있으므로 닫기 키워드 생략만으로 모든 자동화가 꺼지지는 않는다.
- Linear는 이슈당 여러 PR과 PR당 여러 이슈를 지원한다. 문서화된 다중 PR
  동작은 마지막으로 연결된 PR이 설정된 상태에 도달할 때까지 기다리지만,
  앞으로 연결될 PR은 고려하지 못하며 티켓의 결과가 충족되었다는 증거도
  아니다.
