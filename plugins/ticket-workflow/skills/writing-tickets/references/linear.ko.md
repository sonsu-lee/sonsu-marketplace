# Linear

> 영문 정본: [linear.md](linear.md) (`5cdc0e5` 기준 번역).
> 사람이 읽기 위한 번역본이며 에이전트는 이 파일을 읽지 않는다.

Linear 이슈를 작성하거나 게시할 때 이 절차를 따른다.

## 절차

1. **템플릿을 선택한다.** 워크스페이스와 팀을 확정하고 상위 팀에서 쓸 수
   있는 템플릿을 포함해 적용 가능한 워크스페이스 및 팀 템플릿과 팀 기본값을
   확인한다. 번들된 대체 템플릿보다 명시적으로 선택된 해당 템플릿이나 관련
   팀/워크스페이스 템플릿을 먼저 쓴다. 내용과 속성을 확인하고 필수 답변과
   확립된 메타데이터를 보존하되 우선순위, 담당자, 마감일을 지어내지 않는다.
   생성 도구가 템플릿 매개변수를 지원하면 선택한 템플릿을 쓰고 결과를
   확인한다. 그렇지 않으면 필수 내용과 해당 속성을 직접 반영한다.
2. **메타데이터를 검토한다.** 팀/워크스페이스 레이블, 팀 구성원과 담당
   지침, 우선순위 관례, 팀의 추정치 설정, 대상 프로젝트의 마일스톤을
   확인한다. [공통 기준](metadata.md)을 적용하고 템플릿이나 프로젝트
   지침이 이미 정한 메타데이터를 사용자에게 요구하지 않는다. 모든 버그를
   긴급하게 취급하지 말고 보고된 영향을 근거로 우선순위를 설명한다. 추정이
   활성화되어 있고 범위로 의미 있는 제안을 할 수 있을 때만 팀의 실제 척도를
   쓴다. 추정을 활성화하거나 모르는 값을 0으로 대신하지 않는다. 명시적
   담당자와 유효한 템플릿 기본값을 제안된 담당자와 구분한다. 마일스톤은
   대상 프로젝트 안에서 이슈의 결과가 목표에 맞을 때만 선택한다. 프로젝트가
   미정이면 마일스톤도 미정으로 둔다. 게시 전에 사용자, 레이블, 프로젝트,
   마일스톤의 실제 ID를 확인한다. 표시 이름은 모호할 수 있다.
3. **구조를 정한다.** 팀의 관행을 따른다. 하위 이슈는 이슈 하나로는 너무
   크지만 프로젝트로는 작은 작업에 적합하다. 프로젝트는 명확한 결과나 완료
   예정일이 있는 이슈를 묶으며 여러 팀에 걸칠 수 있다. 허가받지 않았다면 새
   프로젝트는 만들지 말고 제안한다. 통합이나 검증을 상위 이슈에 남기기 전에
   상위 이슈의 자동 닫기 설정을 확인한다.
4. **게시하고 연결한다.** 생성 전에 관련 범위의 기존 이슈를 검색한다.
   설정된 GitHub Issues Sync를 존중하며 동기화된 상대 이슈를 독립 작업으로
   다시 만들지 않는다. 취약점 의심 내용을 기록하기 전에 팀의 가시성과 공개
   GitHub 저장소 동기화 여부를 확인한다. Linear가 반환한 실제 이슈 식별자를
   쓰고 수정하거나 쪼갤 때 기존 관계를 보존한다.
5. **PR 작업을 연결한다.** 자동 상태 변경에 의존하기 전에 연동 워크플로를
   확인하고 적절한 관계를 설정한 뒤 결과 연결을 확인한다. 중간 작업은 닫지
   않는 방식으로 연결하고, 머지된 코드와 배포나 검증이 더 필요한 결과를
   구분한다. 실제 PR 작업에는 PR 스킬을 재사용하며 티켓을 쓰려고 연동 설정을
   바꾸지 않는다.

## 주의사항

- 템플릿 기본값은 팀 구성원과 비구성원에게 다를 수 있으며 익숙한 이름이
  기본값이라는 뜻은 아니다. 워크스페이스 템플릿은 팀 고유 레이블이나 상태를
  미리 설정할 수 없다. API 생성에 UI 기본값이 반드시 적용되는 것은 아니며,
  제목이 일치해도 특정 템플릿이 사용되었다는 증거는 아니다.
- 하위 이슈는 상위 이슈의 팀, 우선순위, 프로젝트를 상속하지만 레이블은
  상속하지 않는다. 팀은 모든 하위 이슈가 끝나면 상위 이슈를 자동으로
  닫도록 설정할 수 있다.
- 동기화된 이슈는 공개 저장소에 취약점 세부 내용을 노출할 수 있다.
- PR 설명에서 `Fixes ENG-123`은 설정된 머지 상태를 적용하고,
  `Refs ENG-123`은 그 상태를 적용하지 않고 부분 작업을 연결하지만 다른 설정된
  상태 전환을 일으킬 수 있다. `Related to ENG-123`은 상태 변경 없이 맥락을
  연결한다. PR 댓글은 이런 연결을 만들지 않는다. 이슈 ID가 든 브랜치도 자동
  연결될 수 있으므로 닫기 키워드 생략만으로 모든 자동화가 꺼지지는 않는다.
- Linear는 이슈당 여러 PR과 PR당 여러 이슈를 지원한다. 문서화된 다중 PR
  동작은 마지막으로 연결된 PR이 설정된 상태에 도달할 때까지 기다리지만,
  앞으로 연결될 PR은 고려하지 못하며 티켓의 결과가 충족되었다는 증거도
  아니다.
