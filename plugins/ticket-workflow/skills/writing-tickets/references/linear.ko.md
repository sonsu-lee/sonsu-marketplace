# Linear

> 영문 정본: [linear.md](linear.md) (`092f9e2` 기준 번역).
> 사람이 읽기 위한 번역본이며 에이전트는 이 파일을 읽지 않는다.

## 해당 템플릿 선택하기

워크스페이스와 팀을 확정한 다음, 적용 가능한 이슈 템플릿과 팀 기본값을
확인한다. Linear에는 워크스페이스 템플릿과 팀 템플릿이 있으며, 상위 팀에서
쓸 수 있는 템플릿도 포함된다. 기본값은 팀 구성원과 비구성원에게 다를 수
있다. 익숙한 이름의 템플릿이 기본값이라고 가정하지 않는다.

번들된 대체 템플릿보다 먼저, 명시적으로 선택된 해당 템플릿이나 관련
팀/워크스페이스 템플릿을 쓴다. 내용과 속성을 모두 확인한다. 필수 폼 답변과
확립된 메타데이터는 보존하되, 우선순위, 담당자, 마감일을 지어내지 않는다.
워크스페이스 템플릿은 팀 고유의 레이블이나 상태를 미리 설정할 수 없다.

생성 도구가 템플릿 매개변수를 지원하면 선택한 템플릿을 사용하고 결과를
확인한다. 지원하지 않으면 필수 내용과 해당 속성을 직접 반영한다. API로
만들 때 UI의 기본 템플릿이 적용된다고 가정하거나, 제목이 일치한다는 이유만으로
이름 붙은 템플릿이 쓰였다고 가정하지 않는다.

## 팀과 프로젝트 메타데이터 검토하기

사용 가능한 팀/워크스페이스 레이블, 팀 구성원과 담당 지침, 우선순위 관례, 팀의
추정치 설정, 대상 프로젝트의 마일스톤을 확인한다. [공통 기준](metadata.md)을
적용해 값을 추천한다. 선택한 템플릿이나 프로젝트 지침이 이미 정한 메타데이터를
사용자에게 제공하라고 요구하지 않는다.

추정이 활성화되어 있고 범위로 의미 있는 제안을 할 수 있을 때만 팀의 실제
추정 척도를 쓴다. 추정을 새로 활성화하거나 모르는 값을 0으로 대신하지
않는다. 명시적인 담당자나 유효한 템플릿 기본값은 제안된 담당자와 구분한다.
우선순위 추천은 모든 버그를 긴급하게 취급하지 말고 보고된 영향을 근거로
설명한다.

마일스톤은 대상 프로젝트 안에서, 그리고 이슈의 결과가 그 마일스톤의 목표에
맞을 때만 선택한다. 프로젝트가 정해지지 않았다면 마일스톤도 정하지 않은 채로
둔다. 게시 전에 사용자, 레이블, 프로젝트, 마일스톤의 실제 ID를 확인한다.
표시 이름이 같다고 해서 같은 대상이라고 단정할 수 없다.

## 상위 이슈나 프로젝트 고르기

Linear는 이슈 하나로는 너무 크지만 프로젝트로는 작은 작업에 하위 이슈를
제안한다. 프로젝트는 명확한 결과나 완료 예정일이 있는 이슈를 묶으며 여러
팀에 걸칠 수 있다. 팀의 기존 관행을 따른다. 새 프로젝트는 만들지 말고
제안하며, 허가받았을 때만 만든다.

하위 이슈는 상위 이슈의 팀, 우선순위, 프로젝트를 상속하지만 레이블은
상속하지 않는다. 팀은 모든 하위 이슈가 끝나면 상위 이슈를 자동으로 닫도록
설정할 수 있다. 통합이나 검증 작업을 상위 이슈 자체에 남겨 두기 전에 그
설정을 확인한다.

## 게시하고 작업 연결하기

이슈를 만들기 전에 관련 범위에서 기존 이슈를 검색한다. 설정된 GitHub Issues
동기화를 존중한다. 동기화된 상대 이슈는 다시 만들어야 하는 독립적인 두 번째
작업 항목이 아니다. Linear가 반환한 실제 이슈 식별자를 사용하고, 작업을
수정하거나 쪼갤 때 기존 관계를 보존한다.

취약점으로 의심되는 내용을 기록하기 전에 팀의 가시성과 공개 GitHub 저장소로의
동기화 여부를 확인한다. 동기화된 이슈는 세부 내용을 노출할 수 있다.

자동 상태 변경에 의존하기 전에 연동의 현재 워크플로를 확인한다. Linear는 PR
설명의 다음 관계를 구분한다.

- `Fixes ENG-123` 같은 닫기 키워드는 설정된 머지 상태를 적용한다.
- `Refs ENG-123` 같은 비닫기 키워드는 머지 상태를 적용하지 않고 부분 작업을
  연결하지만, 설정된 다른 상태 전환은 여전히 일으킬 수 있다.
- `Related to ENG-123` 같은 관계 키워드는 상태 변경 없이 맥락만 연결한다.

이슈 ID가 들어간 브랜치도 작업을 자동으로 연결할 수 있다. 닫기 키워드를
생략하는 것만으로 모든 자동화가 꺼진다고 가정하지 않는다. 적절한 관계를
설정하고 결과로 만들어진 연결을 확인한다. PR 댓글의 키워드는 위에서 설명한
연결을 만들지 않는다.

Linear는 이슈당 여러 PR, PR당 여러 이슈를 지원한다. 문서화된 다중 PR 동작은
마지막으로 연결된 PR이 설정된 상태에 도달할 때까지 기다린다. 이는 앞으로
연결될, 아직 연결되지 않은 PR을 고려하지 않으며 티켓의 결과가 충족되었다는
증거도 아니다. 중간 작업은 닫지 않는 방식으로 연결하고, 머지된 코드와 아직
배포나 검증이 필요한 결과를 구분한다. 실제 PR 작업에는 PR 스킬을 재사용하며,
티켓을 쓰려고 연동 설정을 바꾸지 않는다.
