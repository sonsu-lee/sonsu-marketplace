# 새 글 생성 규칙

한국어 블로그·문서·메시지·티켓·PR을 새로 쓸 때 작성 중에 적용한다. 패턴 정의는 [quick-rules.md](quick-rules.md)가 담당하며 이 문서는 새 글에 적용하는 행동을 설명한다.

## 적용 경로

- 새 글은 제공된 사실과 요청 형식에 맞춰 작성한다. 아래 생성 규칙을 읽고 결과를 반환하면 된다.
- 기존 글은 작성 주체와 관계없이 요청한 구간을 [공통 보존 규칙](quick-rules.md#공통-보존-규칙)에 따라 윤문한다. 짧은 국소 수정은 채팅으로 반환하고, 파일·정량 윤문은 호스트별 SKILL.md의 절차로 진행한다.
- 수정 없는 진단은 원문을 유지하고 표현 문제의 위치와 근거만 보고한다.
- 일반 대화 답변·단순 맞춤법 교정·번역은 각 요청에 직접 답하는 경로로 처리한다.

새 글·국소 수정·진단의 결과는 요청한 형식으로 반환한다. run_id, 정량 등급, 변경률 측정, 다중 호출, 파일 출력은 파일·정량 윤문에서 사용한다.

## 쓰는 동안 적용할 규칙

- 결산 접속어는 앞 문장과 실제 인과가 확인된 곳에 쓴다. 문단마다 반복되는 결산 표현은 덜어낸다. (D-1)
- 무엇이 왜 중요한지 구체적인 결론으로 쓴다. (D-2)
- 열거 도입구 대신 본론부터 쓴다. (D-3)
- have·make·take·give 직역은 한국어 형용사·동사로 쓴다. “경쟁력을 가지고 있다”는 “경쟁력이 강하다”로 쓴다. (A-7)
- 이중 피동은 행위자를 확인한 능동문이나 단일 피동문으로 쓴다. (A-8)
- 목록 머리·제목·강조는 이모지 대신 텍스트로 표시한다. (C-5)
- 제목은 하나의 명사구로 쓴다. (C-10)
- 연결어미 뒤는 쉼표 없이 문장을 이어 쓴다. (C-11)
- 따옴표는 실제 인용을 표시할 때 쓴다. (J-2)
- 평가는 관찰한 사실로 직접 서술한다. 감각 술어, 청사진·적신호·신호탄 같은 사전 은유, 글 전체에 되풀이되는 은유는 구체적인 설명으로 풀어 쓴다. 꾸밈용 비유·수사·상투구는 더하지 않는다. (D-14)
- 불릿은 나열 자체가 의미 있는 곳에 쓰고, 셋을 넘는 연속 불릿은 문단으로 정리한다. (C-2)
- 강조는 꼭 필요한 곳에 한정하고 문장마다 반복되는 굵은 표시는 덜어낸다. (J-1)
- 한 글의 청자 경어 단계를 일관되게 유지한다. (E-7)

## 어조

사용자 지정이나 대상 공간의 관례를 따른다. 관례가 없으면 문서·티켓·PR은 합쇼체, 블로그·메시지는 해요체로 쓴다. 한 글 안에서는 한 어조만 쓴다.

## 생성 후 점검

문장을 제공된 사실·수치·관찰로 채우고 근거가 없는 부분은 미확인 상태로 둔다. 근거의 수치·날짜·시각·단위·식별자·고유명사는 [보호 구간](quick-rules.md#공통-보존-규칙)과 같이 근거에 적힌 표기 그대로 옮기고, 근거에 없는 계산값은 쓰지 않는다. 다 쓴 뒤 위 패턴을 한 번 훑어 고친다. 표현의 적절성을 평가하며 AI 작성 여부는 판단 대상에서 분리한다.

## 예시

입력: “도서관 휴관 안내를 써 주세요. 다음 주 수요일은 서가 점검으로 휴관합니다. 반납함은 이용할 수 있습니다.”

결과: “다음 주 수요일은 서가 점검으로 도서관을 쉽니다. 반납함은 이용하실 수 있습니다.”
