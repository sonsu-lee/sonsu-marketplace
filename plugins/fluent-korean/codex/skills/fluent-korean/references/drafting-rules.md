# 새 글 생성 규칙

한국어 산출물(블로그·문서·메시지·티켓·PR)을 새로 쓸 때 작성 중에 적용한다. 윤문 절차(Phase 0 이후, 단일 호출 절차)는 실행하지 않는다. 패턴 정의는 [quick-rules.md](quick-rules.md)가 정본이며, 이 파일은 그중 일부를 쓰는 동안의 지시로 바꾼 것이다.

## 쓰는 동안 피할 패턴

- "결론적으로·따라서·이를 통해·요약하면" 같은 결산 표현을 문단마다 붙이지 않는다. 앞 문장과 실제로 인과가 있을 때만 쓴다. (D-1)
- "시사하는 바가 크다·주목할 만하다·매우 중요하다"로 의의를 부풀리지 않는다. 무엇이 왜 중요한지 구체 결론으로 쓴다. (D-2)
- "크게 세 가지로 나눌 수 있다·다음과 같은" 같은 열거 도입구 없이 바로 본론을 쓴다. (D-3)
- "가지고 있다"나 have·make·take·give 직역 대신 형용사·동사로 쓴다("경쟁력을 가지고 있다" 대신 "경쟁력이 강하다"). (A-7)
- "~되어진다·~지게 된다" 같은 이중 피동을 쓰지 않는다. 능동이나 단일 피동으로 쓴다. (A-8)
- 목록 머리·제목·강조에 이모지를 넣지 않는다. (C-5)
- "X: Y" 형태의 콜론 부제 제목을 반복하지 않는다. 제목은 하나의 명사구로 쓴다. (C-10)
- 연결어미(-고/-며/-지만/-면서/-아서/-어서) 바로 뒤에 쉼표를 찍지 않는다. (C-11)
- 강조하려고 따옴표를 반복하지 않는다. 따옴표는 실제 인용에만 쓴다. (J-2)
- "서늘하다·아프다" 같은 감각 술어로 평가하지 않고, 청사진·적신호·신호탄 같은 은유를 쓰지 않는다. 같은 은유를 글 전체에 되풀이하지 않는다. 직접 서술한다. (D-14)
- 불릿을 셋 넘게 이어 붙이지 않는다. 나열 자체가 의미 있는 곳에만 불릿을 쓰고 나머지는 문단으로 쓴다. (C-2)
- 문장마다 핵심 단어를 굵게 표시하지 않는다. (J-1)
- 해요체·합쇼체 같은 청자 경어 단계를 한 글 안에서 섞지 않는다. (E-7)

## 어조

사용자 지정이나 대상 공간의 관례를 따른다. 관례가 없으면 문서·티켓·PR은 합쇼체, 블로그·메시지는 해요체로 쓴다. 한 글 안에서는 한 어조만 쓴다.

## 빼기 전용 원칙

문체를 꾸미려고 비유·수사·상투구를 넣지 않는다. 문장은 구체적인 사실·수치·관찰로 채운다. 근거가 없는 내용을 채우려고 문장을 늘리지 않는다.

## 생성 후 점검

다 쓴 뒤 위 패턴이 남았는지 한 번 훑어보고 고친다. run_id, 변경률 측정, 파일 출력, 다중 호출 절차는 실행하지 않는다.

## 판정 금지

글이 AI가 쓴 것인지 판정하지 않는다.
