# Fluent Korean — im-not-ai 기반 (Codex · GitHub Copilot CLI)

한국어 글의 표현 문제를 근거에 따라 줄이고 의미와 필자의 말투를 보존한다. Codex와 GitHub Copilot CLI는 단일 호출 경로만 제공한다. 진단→겨냥 윤문→finalize로 이어지는 다중 호출 경로는 Claude Code 전용이다.

## 절차

[적용 경로](references/drafting-rules.md#적용-경로)를 읽고 새 글·국소 수정·진단·파일 윤문을 구분한다. 새 글은 해당 문서의 생성 규칙으로 작성하고, 기존 글은 [공통 보존 규칙](references/quick-rules.md#공통-보존-규칙)을 따른다. 아래 번호 절차는 파일·정량 윤문에 적용한다.

1. **룰북 로드**: [quick-rules.md](references/quick-rules.md)의 S1·S2 패턴, 보호 구간, 자체검증과 등급 기준을 읽는다. 사용자가 지정한 `장르: 칼럼|리포트|블로그|공적`, `강도: 보수|기본|적극`, `최소심각도: S1|S2|S3`를 적용한다.
2. **입력 확보**: 붙여넣은 텍스트 또는 지정한 .txt/.md 파일을 원문으로 읽는다. 한국어 입력인지 확인하고 다른 언어면 “한국어 텍스트만 처리 가능”을 안내한다.
3. **장르 추정**: 사용자 지정이 있으면 따르고, 없으면 첫 300자로 추정한다.
4. **탐지**: A~J 패턴의 `(ID, span, severity, fix)`를 수집한다. 보호 구간은 원형대로 둔다.
5. **윤문**: D(관용구 삭제) → A → I → G → H → F → B → C·J → E 순서로 문단을 다듬는다. 변경률이 중단 기준에 가까워지면 후속 수정을 보류한다.
6. **자체검증**: quick-rules의 6항을 점검한다. 위반한 수정은 되돌린 뒤 최대 한 번 다시 윤문한다.
7. **출력**: cwd 기준 `_workspace/{run_id}/final.md`를 작성한다. run_id는 `YYYY-MM-DD-NNN-TAG`다. 당일 폴더가 있으면 NNN을 하나 늘린다. TAG는 동시에 실행되는 세션을 구분하므로 `python3 -c "import secrets;print(secrets.token_hex(2))"`로 run 시작 때 한 번 만들어 끝까지 재사용한다. 본문 끝에 빈 줄 하나 두고 `<!-- HUMANIZE-SUMMARY ... -->` HTML 주석 블록 하나를 추가한다.
   - 원본·윤문본 글자수와 변경률
   - 카테고리별 탐지 건수(before → after, quick-rules ID 기준)
   - 자체검증 6항 통과 여부
   - 등급(A/B/C/D)과 사유 한 줄
   - 주요 변경 3~5건(before → after, 각 100자 이내)
8. **응답**: 사용자에게 짧게 4가지 반환 — ① 한 줄 상태(`완료. 변경률 X% / 등급 Y / 자체검증 N/6 통과`) ② 핵심 카테고리 탐지 4~6건(before → after) ③ 변경 하이라이트 1건 ④ 등급 B 이하면 "정밀 검증은 Claude Code의 정밀 모드(3콜) 권장" 안내. 윤문본은 `final.md`로 전달하고 응답에는 경로와 요약을 쓴다.

## 결과

새 글·국소 수정은 요청한 본문을, 진단은 문제 위치와 근거를 반환한다. 파일·정량 윤문은 `final.md`와 위 절차의 상태·요약을 반환한다. 등급은 [룰북의 기준](references/quick-rules.md#등급-기준-자가-채점)으로 정한다.

## 예시

입력: “전시 안내문의 ‘작품은 두 층에 걸쳐 전시되어져 있습니다.’만 자연스럽게 고쳐 주세요.”

결과: “작품은 두 층에 걸쳐 전시되어 있습니다.”

진단만 요청하면 “A-8 이중 피동: ‘전시되어져’는 ‘전시되어’로 줄일 수 있습니다.”를 보고하고 원문을 유지한다. 두 요청 모두 짧은 국소 작업이므로 파일·정량 절차 대신 채팅으로 반환한다.
