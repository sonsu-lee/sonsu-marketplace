# 리뷰 피드백 처리

리뷰 의견은 검토가 필요한 주장이다. [공통 리뷰 기준](../../references/review-criteria.md)으로
현재 코드·요구사항·사용 중인 버전의 기본 동작과 유효 설정을 대조한 뒤 수정 여부를 정한다.

1. 동작 문제는 발생 조건을, 구조 문제는 현재의 이해·수정 비용과 영향을 확인한다.
   심각도 이름보다 실제 근거를 보고, 기존 처리로 요구를 충족하면 이유와 함께 지적을 닫는다.
2. 유효한 차단 지적과 사용자가 수정을 요청한 지적은 최소 변경으로 해결하고 영향받은 동작을
   검증한다. 추가 설정·timeout·추상화가 필요하면 기존 처리로 부족한 이유를 확인한다.
3. 미확인 가정은 관련 코드·설정·문서로 확인한다. 이전 PR의 선택 이유나 공식 권장이 현재
   버전·환경·문제에도 적용되는지 대조한다. 판정에 필수인 근거 공백만 반환한다.
   근거 있는 비차단 구조 지적은 보고하며, 후속 구현은 요청된 범위에서 다룬다.
4. 승인된 계약이나 권한을 바꿔야 하면 해당 결정만 확인한다. 기존 승인으로 해결할 수 있는
   선택은 직접 처리하고 독립적인 승인 작업은 계속한다.
5. 수정·근거로 기각·비차단 보고·필수 확인 필요 중 실제 상태와 이유를 짧게 보고한다.
   차단 지적의 원래 리비전과 근거를 보존하고 [품질 게이트 계약](../using-engineering-skills/references/quality-gates.md)에
   따라 변경 영향과 집중 재리뷰 결과를 현재 리비전에 연결한다.

예를 들어 timeout 추가 권고를 받으면 현재 provider 버전·자원의 기본 제한과 재정의 설정을
확인한다. 이미 요구를 충족하면 중복 설정 없이 지적을 닫고, 부족하면 해당 범위만 고친다.

질문형 표현이나 `suggestion` 블록이라는 이유로 제안을 채택하지 않는다. 근거가 없는 효과 주장,
중복 지적과 불필요한 증적 요구는 공통 기준으로 확인하고 필요한 조건·예외는 보존한다.
관찰 도구의 `ready`·무알림은 의미적 검토의 통과가 아니다. 기존 필수 검증·독립 리뷰는 유지하되,
선택적 개선을 관찰 도구의 새 등록·필수 수정·재검토 조건으로 만들지 않는다.

GitHub 리뷰 답글은 사용자가 전송을 승인한 경우 해당 인라인 댓글 대화에 남긴다.

## 작업 연속성

여러 단계의 작업이나 외부 쓰기를 맡은 조정자는 [task-continuity](../task-continuity/SKILL.md)에
따라 진행을 기록하고 재개할 때 현재 근거와 대조한다. 단발 작업과 위임된 에이전트·독립
리뷰어는 별도 기록을 만들지 않는다. 파일 쓰기가 금지된 범위에서는 기록 파일과 Git exclude도 유지한다.
