# 설계 문서 리뷰 프롬프트

영속 설계 문서를 생성·갱신했고 독립 리뷰가 계획 위험을 줄일 때 사용한다. 조정자는 정확한 문서 리비전과 요구사항 출처를 제공한다.

```text
설계 문서가 완전하고 일관되며 구현 계획을 작성할 준비가 됐는지 읽기 전용으로 검토한다.

리뷰할 문서: [문서 파일 경로]
요구사항 출처·승인 범위: [요구사항 출처]

원래 구현 요청·이전 사용자 승인도 유효한 출처다. 별도 설계 승인 메시지가 없다는 사실만으로
결함을 만들지 않는다. 설계 전용 요청·명시적 구현 전 확인 조건·실제 승인 계약 변경을 구분한다.

다음을 확인한다.
- 완전성: 미정 요구사항, TODO·TBD·자리표시자·불완전한 섹션이 계획을 막는가.
- 일관성: 내부 모순·충돌하는 요구사항이 있는가.
- 명확성: 다른 구현 결과로 이어질 모호함이 있는가.
- 범위: 하나의 계획으로 다룰 책임과 하위 시스템 경계가 명확한가.
- 필요성: 요청하지 않은 기능이나 불필요한 설계가 추가됐는가.

잘못된 계획으로 이어질 실제 공백만 차단 지적으로 보고한다. 표현·문체 선호와 비차단
개선은 권고로 구분한다. 필수 근거를 읽을 수 없거나 판정할 수 없으면 그 공백을 명시한다.

출력:
## 명세 리뷰
**Status:** Approved | Issues Found
**Issues:**
- [섹션 X]: [문제·근거와 계획에 미치는 영향]
**Recommendations:**
- [비차단 개선 제안]
```

조정자는 [품질 게이트 계약](../using-engineering-skills/references/quality-gates.md)에 따라 `Status`와 필수 근거의 충족 여부를 게이트 상태로 기록한다. 검토자가 필수 근거 공백을 보고했다면 `Approved`만으로 통과를 만들지 않는다.
