# 공통 리뷰 기준

현재 동작의 결함, 아키텍처·유지보수성 문제와 근거 있는 단순화 기회를 검토한다.

1. **맥락을 확인한다.** 변경과 관련 호출자·설정·검증 근거를 읽는다. 추가 확인은 판정에
   필요한 범위로 정한다.
2. **기존 동작을 확인한다.** 처리 누락을 판단하기 전에 사용 중인 프레임워크·라이브러리·
   provider 버전의 기본 동작과 유효 설정·재정의를 확인한다. 남은 중요한 불확실성만 공식
   문서·소스·집중 검사로 해소한다.
3. **문제에 맞는 근거를 제시한다.** 동작 결함은 발생 조건과 요구사항·불변식 위반을 재현
   또는 실행 경로로 설명한다. 구조 문제는 책임·의존 관계, 중복 지식과 불필요한 간접 참조가
   현재의 이해·수정 비용을 늘리는 위치를 설명하고 동작을 유지하는 대안을 제시한다. 구조
   문제에 실행 버그 재현은 필요하지 않다. 파일 길이·호출자 수·취향·미래 요구만으로 차단하지
   않으며, 승인된 설계의 문제는 근거와 함께 설계 소유자에게 반환한다.
4. **최소 수정을 제안한다.** 삭제·기존 동작 재사용·국소 수정을 먼저 검토한다. timeout·retry·
   validation·설정·추상화를 추가하려면 현재 처리로 부족한 이유를 제시한다. 필요한 보호와
   명시된 요구사항을 유지한다.
5. **보고와 차단을 구분한다.** 같은 원인의 지적을 합치고 실제 영향으로 심각도를 정한다.
   Critical/Important에는 진행 전에 해결할 이유가 필요하다. 근거 있는 비차단 구조 개선은
   보고하며, 비차단 지적만으로 필수 수정·재리뷰·할 일 목록을 만들지 않는다.

출력은 **판정 → 지적(위치·근거·영향·최소 수정) → 판정에 필수인 근거 공백** 순서다.
지적과 공백이 없으면 판정과 짧은 근거만 쓴다. 지적이 0개여도 필수 검증이 부족하면 통과로
판정하지 않는다. 취향·가상의 경계 사례·추측성 보강을 새 완료 조건으로 추가하지 않는다.
