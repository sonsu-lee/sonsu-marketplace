# finish-branch: 개발 브랜치 마무리

기존 커밋과 검증 근거를 확인하고 사용자가 선택한 통합·보존 방법을 실행한다. 이 스킬은 구현을 스테이징·커밋하는 절차가 아니며 다른 플러그인에 의존하지 않는다. 직접적인 Git·티켓·PR 요청은 해당 산출물을 다루는 사용 가능한 절차로 처리한다.

주 조정자의 여러 단계 작업은 [연속성 참고 자료](../../references/continuity.md)에 기록한다. 위임된 작업자와 새 문맥의 검토자는 별도 연속성 기록을 만들지 않는다.

## 1. 전달할 변경과 근거 확인

요청한 구현의 커밋이 존재하는지, 관련 없는 변경을 제외한 작업이 정리됐는지 확인한다. 미커밋 구현만 있고 커밋 승인이 없다면 실행 작업 절차의 최종 차이·검증 보고로 전달한다. 미승인 커밋을 마무리 조건으로 요구하지 않는다.

[품질 게이트 계약](../../references/quality-gates.md)에 따라 최종 근거가 정확한 커밋 리비전을 다루는지 확인한다. 검증한 작업 트리를 그대로 커밋했다면 트리 내용 일치를 확인해 근거를 연결할 수 있다. 국소 변경은 기존 전체 근거와 현재 변경분·집중 검증·재리뷰·영향 범위를 연결한다.

현재 위험 정책의 필수 검사·독립 리뷰와 고위험 red-team 근거를 확인한다. 일반 리뷰는 Luna xhigh 5개, 고위험 red-team은 별도 Astra high다. 사람의 명시적 `accepted_risk`는 통과와 구분한다. 필수 미실행·실패·근거 부족은 소유 단계로 반환한다. 계획 파일 존재만으로 red-team을 추가하지 않는다.

현재 근거가 다루지 않는 변경과 통합 위험에는 필요한 최종 검증을 실행한다. 동작·통합은 관련 검사 모음, 문서·메타데이터·단순 설정은 지정된 링크·구문·경로·로더·소비 명령을 사용한다. 현재 산출물을 다루는 유효한 근거가 있으면 같은 검사를 형식적으로 반복하지 않는다.

## 2. 작업 공간과 기준점 확인

작업 공간 안에서 정리 전에 필요한 정보를 기록한다.

```bash
GIT_DIR=$(cd "$(git rev-parse --git-dir)" && pwd -P)
GIT_COMMON=$(cd "$(git rev-parse --git-common-dir)" && pwd -P)
WORKTREE_PATH=$(git rev-parse --show-toplevel)
git rev-parse --show-superproject-working-tree
git branch --show-current
git worktree list --porcelain
```

서브모듈 여부를 구분하고 연결된 워크트리·일반 체크아웃·외부 관리 분리된 HEAD를 판정한다. 워크트리 생성 기록에서 소유 주체와 정확한 경로를 확인한다. 디렉터리 이름만으로 Engineering 소유라고 판단하지 않는다.

기준점은 계획·대화·상위 추적 브랜치·Git 이력에서 확인한다. 병합 전에 확정할 수 없으면 관련 근거를 제시하고 기준점만 확인한다. 분리된 HEAD에서는 이름 있는 브랜치로 전달하거나 현재 상태를 보존하며 자동 로컬 병합을 제안하지 않는다.

## 3. 통합 또는 보존 결정

사용자가 이미 방법과 범위를 정했다면 그 승인대로 실행한다. 결정이 없고 통합 선택이 필요한 경우 다음의 적용 가능한 선택지를 간결하게 제시한다.

| 현재 상태 | 선택지 |
| --- | --- |
| 이름 있는 브랜치 | 확인한 기준점에 로컬 병합 / 푸시 후 PR 생성 / 현재 브랜치·작업 공간 보존 |
| 외부 관리 분리된 HEAD | 새 브랜치로 푸시 후 PR 생성 / 현재 상태 보존 |

이 선택은 Git·외부 작업 권한을 확인하는 단계다. 구현 완료만으로 병합·푸시·PR을 추정하지 않는다. 작업 폐기는 사용자가 명시적으로 요청할 때만 다룬다.

## 4. 선택 실행

### 로컬 병합

기준점 체크아웃의 경로·현재 브랜치·미커밋 변경 상태를 확인하고 관련 없는 변경을 보존한다. 승인된 기준점과 기능 브랜치를 사용한다.

```bash
git -C "$BASE_CHECKOUT" merge "$FEATURE_BRANCH"
```

병합 충돌은 승인된 계약 안에서 해결하고 병합 결과 트리에 필요한 검증을 실행한다. 승인 계약을 바꾸는 선택은 해당 의존 작업을 보류한다. 병합 결과 검증이 실패하면 원인을 조사하며 브랜치와 작업 공간을 보존한다. 성공한 병합과 검증을 확인한 뒤 소유한 워크트리를 정리하고 통합된 브랜치는 `git branch -d`로 삭제할 수 있다.

### 푸시와 PR

승인된 원격 저장소·브랜치로 일반 푸시한다. 분리된 HEAD는 사용자가 승인한 브랜치 이름을 사용한다.

```bash
git push -u origin "$FEATURE_BRANCH"
# detached HEAD의 승인된 remote 브랜치로 전달할 때
# git push origin "HEAD:refs/heads/$FEATURE_BRANCH"
```

승인된 기준점을 대상으로 코드 호스팅 도구로 PR을 만들고 저장소 템플릿·관례를 따른다. 원격 저장소 상태와 URL을 읽어 확인해 보고한다. 푸시가 거부되면 원인을 확인하고 강제 푸시 권한을 추정하지 않는다. PR 후에는 피드백 반영을 위해 작업 공간을 유지한다.

### 현재 상태 보존

브랜치 또는 분리된 HEAD의 커밋과 작업 공간 절대 경로를 보고하고 유지한다.

### 명시적으로 요청된 폐기

삭제할 정확한 브랜치·커밋·작업 공간과 미커밋 파일·임시 자료를 확인해 먼저 목록으로 만든다. 기존 요청이 그 대상과 손실을 명확히 승인하면 수행한다. 범위가 불명확하면 구체적 목록을 제시해 해당 삭제만 확인한다. 정해진 확인 문자열을 추가 승인 조건으로 요구하지 않는다.

## 5. 작업 공간 정리

검증된 로컬 병합 또는 명시적으로 승인된 폐기에서만 정리한다. PR·보존 선택과 실패·미해결 상태에서는 유지한다.

1. 필요한 판정·검증·`accepted_risk`와 임시 자료를 최종 보고 또는 보존 위치에 남긴다. Git 제외 파일도 확인한다.
2. 정리할 워크트리 밖의 유효한 체크아웃으로 이동한다. 기록한 정확한 소유 경로만 대상으로 한다.
3. 이 작업에서 생성·관리한 워크트리라면 `git worktree remove "$WORKTREE_PATH"`를 실행한다. 다른 계획·작업·호스트가 관리하는 작업 공간은 보존하며 플랫폼 기본 종료가 필요하면 해당 기능의 범위와 권한을 따른다.
4. 수정된·추적되지 않는 파일 때문에 삭제가 거부되면 `git -C "$WORKTREE_PATH" status --porcelain -uall`로 확인한다. 대상과 보존·이동·삭제 승인을 정하기 전에는 강제 삭제하지 않는다.
5. 정리 결과를 확인하고 남은 브랜치·작업 공간·PR 위치를 보고한다. 폐기 승인이 있을 때만 해당 브랜치의 `git branch -D`를 사용한다.
