# 품질 게이트 계약

단계 소유자는 산출물, 측정할 조건, 필수 검사, 실패 반환 대상을 실행 전에 정한다.
등록한 DAG는 [evidence-gates](evidence-gates.md)가 현재 근거를 검사해 `enter`와
`complete-unit`을 제어한다. 임의의 도구 호출까지 가로막는 하네스는 아니다.

## 위험에 맞게 선택한다

| 현재 근거로 확인한 위험 | 정책 | 통과 조건 |
| --- | --- | --- |
| 의미·공개 계약 변화 없는 기계적 변경, 결정론적 검사로 판정 가능 | `checks` | 선언한 소비 검사 통과 |
| 동작 변경·일반 구현·일반 전체 리뷰 | `independent` | 검사 + Luna xhigh 5개 독립 리뷰 + 조정자의 지적 검증 |
| 어려운 설계·권한·상태·데이터 무결성·동시성·복구·호환 경계 | `red-team` | independent 조건 + 별도 Astra high의 `survives_challenge` |

깊이와 병렬화 가능성은 별개다. 새 위험을 발견하면 정책을 높이고 영향받은 단계를 다시 연다.
통과를 얻기 위해 정책·검사를 약화하지 않는다. 설계/계획은 고정 문서 패키지, 구현은 해당 격리
워크스페이스의 전체 소스, 통합은 최종 워크스페이스를 식별한다. 코드 수정 때문에 고정 설계
문서 자체의 근거가 만료되지는 않는다. 실제 계약 변경은 그 계약의 소비자 근거를 만료시킨다.

## 측정과 상태

같은 기록에 `task/unit ID`, 계약·정책·산출물 리비전, 선행 receipt, 필수 명령·관찰 결과,
리뷰 원결과·지적별 판정, 상태·반환 대상·회차를 연결한다. 없는 검사를 형식적으로 추가하지
않는다. 테스트 개수·줄 수·if 수·리뷰 길이·지적 수는 품질 통과 기준이 아니다.

| 상태 | 의미 |
| --- | --- |
| `passed` | 현재 산출물에 모든 필수 조건 충족 |
| `failed` | 유효한 필수 조건 위반 |
| `blocked` | 환경·권한·의존성 부재 |
| `inconclusive` | 판정 근거 부족 |
| `not_run` | 미실행 |
| `not_applicable` | 실행 전에 적용 대상에서 제외한 선택 검사 |
| `accepted_risk` | 지명된 사람이 정확한 리비전의 명시된 위험을 수용한 별도 결정 |

위험 수용을 `passed`로 바꾸지 않는다. 조정자·리뷰어·예산 소진은 사람의 수용을 대신하지
않는다. 실행 완료 상태와 의미 판정도 다르다. 취소/시간 초과는 `incomplete`, 잘못된 검사
입력·oracle은 `invalid_oracle_setup`으로 원결과와 함께 기록하고 해당 계층을 고친다.
도구 종료 코드 0이나 스키마 적합성은 의미적 정확성을 증명하지 않는다.

## 독립 리뷰와 수정

일반 최초·전체 리뷰는 같은 고정 산출물과 [공통 기준](../../../references/review-criteria.md)을
Luna xhigh 5개의 새 문맥에 제공한다. 서로의 지적과 구현자 자기 정당화를 먼저 보여주지 않는다.
5명이 한 라운드이며 수정 5회가 아니다. 조정자는 모든 지적을 원인별로 합치고 계약·도달 경로·
재현 근거로 각각 판정한다. 1명만 발견해도 유효한 문제는 처리한다. 다수결과 지적 수 경쟁을
사용하지 않으며 미완료 리뷰는 통과가 아니다.

국소 수정은 기존 전체 근거의 유효 범위, 실제 차이, 영향받은 소비자, 새 검사와 재사용 이유를
연결하고 Luna xhigh 1개로 집중 재검토한다. 목표·계약·설계·의존 경계가 바뀌거나 영향이
불명확하면 전체 5개를 다시 연다. 고위험 red-team은 별도 새 문맥의 Astra high가 현재 전체
묶음과 반례·수정 이력을 검토한다. 일반 리뷰를 red-team으로 대신 세지 않는다.

자동 수정/재검토는 같은 작업·게이트에 최대 5라운드다. 호출 수와 시간·토큰은 따로 기록한다.
담당자·세션·모델·패키지 변경이나 재개로 회차를 초기화하지 않는다. 새 근거가 있는 수정만
재시도하며 고정 1–3/4–5 담당자 규칙이나 실패 횟수에 따른 모델 승격은 없다.

실패는 원인을 바꿀 가장 가까운 구현·통합·계획·설계·검증·환경 단계로 반환한다. 원래 목표를
바꿔야 하는 경우에만 해당 사용자 결정을 구한다. 5라운드 뒤 유효한 필수 미해결이 남으면
`decision_required`와 상태·근거를 남기고 자동 반복을 종료한다.

## 중복 절차를 제거하는 기준

삭제하려는 검사/조건이 보호하는 실제 실패를 먼저 명명한다. 같은 계약·산출물·소비자를 더
앞선 검사에서 보장하고, 변경 이후에도 근거가 유효하며, 제거 후 경계가 빠지지 않으면 재사용한다.
독립된 실패를 잡거나 경계 신뢰가 달라지는 검사는 유지한다. 불확실하면 대표 실패·반례로
비교한 뒤 정책을 바꾼다. 요구되지 않은 미래 기능·형식만 충족하는 산출물은 추가하지 않는다.
