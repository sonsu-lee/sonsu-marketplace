# 에이전트 실행과 문맥 계약

스킬은 작업 분류·검증·예산·인계를 정하고, 별도 에이전트는 집중된 구현·조사·리뷰를 맡는다.
조정자는 현재 실행 도구에서 지원하는 설정을 적용하고 관찰한 결과를 기록한다. 본문에 모델
이름을 쓰는 것만으로 실제 모델이나 세션이 바뀌지는 않는다.

## 실행 기록

기존 계획·작업 요약·게이트·보고를 재사용해 다음 정보를 연결한다. 같은 정보를 여러 파일이나
새 엄격한 스키마로 복제할 필요는 없다.

```text
Task / Gate: 고정 ID + 승인된 계약 리비전
Artifact: 현재 소스·변경 리비전 + 읽을 수 있는 고정 패키지
Role / Scope: 역할, 필요한 기능, 작업 cwd와 쓰기 소유 범위
Routing: requested model/effort → observed model/effort, 관측 출처 또는 unknown, 대안 선택 이유
Selection: 역할·불확실성에 따른 선택 이유, 프롬프트 참조·리비전, 필요한 역할 구성
Session: fresh | resume | fork, 현재·부모 세션 ID 또는 unavailable
Environment: 검증 명령, 실행 환경·의존성, 허용 소스·임시 공간, 네트워크 조건
Budget: 작업·게이트의 소비량/상한, 남은 상위 예산, 종료 시한, 조정자의 동시 실행 상한
Result: 실제 실행 완료 상태, 명령·출력의 근거 경로, 열린 지적, 남은 예산
```

실행 환경에서 제공하지 않는 값은 `unknown` 또는 `unavailable`로 기록한다. 요청값, 도구·
실행 환경의 관측 메타데이터와 에이전트 자기보고를 구분한다. 요청·관측 불일치는 원인과
대안을 기록한다. 실제 기능으로 계약·사용자 제약을 충족하면 지원되는 대안으로 진행하고,
필수 기능이나 명시적인 모델 제약을 충족할 수 없으면 해당 실행을 `blocked`로 반환한다.
관측 수단 부재만으로 전체 작업을 막거나 확인을 위해 사용자 설정을 임의로 바꾸지 않는다.

소스 리비전은 커밋 SHA 또는 내용 digest로 고정한다. 구현자는 수정할 현재 소스를 받고,
리뷰어는 판정할 산출물과 검증 근거의 고정 사본을 받는다. 변경 후에는
[품질 게이트 계약](quality-gates.md)에 따라 영향받은 근거를 갱신한다.

## 환경과 실행 상태

실제 소비 명령에 필요한 환경만 확인한다. 파일 읽기, Git 입력 자료 생성, Python import와
pytest collection은 서로 다른 검사다. 오류가 발생한 계층을 확인하고 해당 환경부터 보완한다.
읽기 전용 리뷰에도 테스트용 쓰기 가능한 임시 공간이 필요할 수 있다. 작업별 쓰기 범위와
임시 파일·DB·포트를 분리한다. 비공개 자료의 상위 경로와 실행 공간을 분리하면 경로 권한
규칙이 필요한 상위 메타데이터 읽기까지 막는 문제를 피할 수 있다.

완료 이벤트 없는 제한 시간 종료·취소는 `execution: incomplete`와 원인, 생성 파일·근거·
소비량을 남긴다. 실행 미완료는 코드 오답이나 문맥 열화의 증거가 아니다. 예를 들어 다음은
실행 상태와 환경 차단을 구분한 기록이다.

```text
execution: incomplete; cause: deadline; gate: blocked; return: environment-owner
```

환경을 고쳐도 유효한 필수 검사 근거가 없으면 게이트는 통과하지 않는다. 후속 실행에서
확인한 제품 결함은 별도 기록한다.

## 역할과 인계

작업 요약은 목표·승인 계약·근거·쓰기 범위·필수 검증·완료 조건으로 구성한다. 공통 정책은
한 곳에서 참조하고 모델·추론 수준·역할 구성을 각각 선택한다.

| 역할 | 제공할 내용과 책임 |
| --- | --- |
| 구현자 | 승인 계약·의사코드·현재 소스·검증 환경. 집중 수정에는 열린 지적·새 반례·현재 리비전을 제공한다 |
| 리뷰어 | 새 문맥에서 승인 계약·고정 변경·사실 중심 검증을 받는다. 최초 독립 리뷰끼리는 서로의 지적을 먼저 공유하지 않는다 |
| red-team | 일반 최종 리뷰 뒤 새 문맥에서 전체 목표·가정을 고정 묶음과 지적·수정 이력으로 검토한다 |
| 전문가 | 명명된 독립 위험이나 자료 조사를 맡는다. 전문 검토들의 합이나 다수결이 전체 리뷰를 대신하지 않는다 |

조정자는 원 보고의 명령·출력·변경 범위·제약을 전달하고 구현 서사·자기 정당화·자체 통과
판정·칭찬은 독립 검토 입력에서 제외한다. 원 보고는 진행 기록으로 보존한다. 재리뷰에는
검증할 기존 지적과 수정 근거를 제공한다.

승인 계약·외부 동작·권한·쓰기 범위 변경이나 필수 규칙 공백이 발견되면 해당 결정과 의존
작업을 조정자에게 반환한다. 조정자는 기존 승인으로 해결할 수 있는지 확인하고 새 사용자
결정이 필요한 경우에만 요청한다. 독립적인 승인 작업은 계속하며, 기존 관례로 정할 수 있는
내부 이름·동등한 표현은 직접 선택한다.

세션 계보와 식별자는 조정자의 복구 기록이다. 새 리뷰어·수정 구현자에게 이전 대화 탐색을
시키지 않는다. 별도 세션도 같은 파일을 공유할 수 있으므로 병렬 소유 범위와 통합은
[dispatching-parallel-agents](../../dispatching-parallel-agents/SKILL.md)를 따른다. SDD의 기본 구현
반복은 순차적으로 수행한다.

## 수정 회차와 예산

운영 기본값은 같은 작업의 수정 1–3회에 원 구현자를 재개하고, 4–5회에 사실 중심 인계를 받은
새 구현자를 사용하는 방식이다. 원 에이전트가 없거나 새 반례에도 같은 잘못된 가정을 반복해
진전이 없으면 더 일찍 새 진단·수정으로 전환할 수 있다. `3+2/max5`는 운영 상한이며 모델의
최적 횟수나 세 번째 이후 품질 열화를 입증한 수치가 아니다.

같은 작업·게이트 ID, 현재 리비전, 소비·남은 예산과 종료 조건을 인계한다. 더 낮은 단계별
상한과 Fast Path 예산이 우선하며, 세션·모델·담당자·패키지 변경이나 중첩 호출로 초기화하지
않는다. 새 정보가 있을 때 재시도하고 필수 조건을 충족하면 상한 전에 마친다. 새 변경·실패·
미해결 우려가 없으면 무관한 검사나 같은 검사를 반복하지 않으며 후속 필수 리뷰는 유지한다.

## 실행 환경별 대응

`fresh`는 이전 이력을 상속하지 않는 실행, `resume`은 같은 세션 재개, `fork`는 기존 이력의
분기다. 현재 도구의 이름보다 실제 이력 전달 동작을 확인한다. Codex는
[codex-tools.md](codex-tools.md), Claude Code는 [claude-code-tools.md](claude-code-tools.md)를 참고한다.
각 환경이 지원하는 모델·추론 수준만 사용하고 같은 이름의 추론 수준을 같은 계산량으로
간주하지 않는다. 도구 스키마 확인은 모델 성능이나 전체 절차의 동작 검증과 구분한다.

참고: [Codex subagents](https://learn.chatgpt.com/docs/agent-configuration/subagents),
[Claude Code subagents](https://code.claude.com/docs/en/sub-agents),
[Anthropic context engineering](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents).
