# 스킬의 실제 동작 평가

호출 조건, 권한, 실행 순서나 결과 형식이 바뀌어 정적 검사만으로 판단하기 어려울 때 사용한다.
평가는 수정한 지침이 실제 작업에서 필요한 선택과 결과를 만드는지 확인한다.

## 사례와 판단 기준을 정한다

1. 바뀐 규칙과 실패했을 때의 영향을 정하고 해당 조건을 드러내는 현실적인 사례를 고른다.
2. 호출해야 하는 작업과 바로 답하면 되는 작업을 함께 포함한다. 조건 분기에는 양쪽 사례를 둔다.
3. 각 사례의 입력, 사용할 스킬·참고 자료의 고정 사본, 기대 결과와 보호할 의미·형식을 정한다.
4. 필요한 실행 수와 비용·시간 범위를 정하고, 실제 허용된 도구와 모델 설정을 확인한다.

일반론을 알고 있는지 묻기보다 파일 읽기, 답변 작성, 다음 행동 선택처럼 관찰할 수 있는 작업을
시킨다. 시간 압박이나 이미 작성된 코드가 판단을 바꾸는 실제 위험일 때만 그 조건을 사례에 넣는다.

## 새 문맥에서 실행한다

변경된 지침과 필요한 입력만 전달한다. 생성자에게 기대 정답, 과거 판정이나 지침을 잘 따라야
한다는 암시를 추가하지 않는다. 파일과 외부 작업은 독립 임시 환경·fixture로 범위를 고정한다.

문구 변경의 효과를 비교하려면 같은 조건에서 기존 지침 또는 지침 없는 대조군도 실행한다.
출력 차이가 판정에 중요한 경우에만 반복 수를 늘린다. 모델·설정·도구·자료를 함께 바꿨다면
그 비교에서 문구만의 효과를 주장할 수 없다.

## 결과를 읽고 수정한다

원출력과 실행 이력에서 선택한 스킬, 행동, 생성 결과와 실패 조건을 확인한다. 자동 검사가
지적한 항목은 문맥을 읽어 인용·예시·실제 행동을 구별한다. 위임된 작업은 하위 원결과와
부모의 최종 답변을 각각 읽고, 생성·결과 수집·최종 요구 충족을 따로 판정한다. 하위 결과의
통과를 부모 답변의 통과로 대신하지 않는다. 관찰된 문제를 다음처럼 고친다.

| 관찰 | 수정 방향 |
| --- | --- |
| 호출이 과하거나 필요한 작업을 놓침 | description의 대상·상황과 진입 조건을 구체화 |
| 조건에 따른 행동이 달라지지 않음 | 해당 단계에 관찰 조건과 후속 행동을 연결 |
| 결과의 필수 정보가 빠짐 | 필요한 결과 항목을 예시나 양식으로 제시 |
| 사실·권한·실행 순서를 잘못 바꿈 | 영향을 주는 도메인 계약과 판단 근거를 해당 위치에 명시 |
| 불필요한 단계·반복으로 작업이 길어짐 | 중복 절차를 합치고 완료 기준을 분명히 제시 |

문제와 관련된 부분을 수정하고 같은 사례와 인접한 회귀 사례를 다시 확인한다. 추가 제약은
관찰된 실패를 해결하는 범위에서 작성한다. 원본 실패와 후속 결과를 별도로 보존하며,
미리 정한 실행을 첫 통과에서 중단하거나 변경 없이 통과할 때까지 반복하지 않는다.

## 근거를 남긴다

원본·지침 리비전, 입력, 모델·설정, 실제 읽은 자료, 도구 호출, 출력과 판정을 연결한다.
실행 미완료·환경 실패·평가 불확실성을 구분하고 미실행은 `not_run`으로 남긴다.
수동으로 지침을 제공한 사례는 명시적 적용 평가이며, 자동 스킬 선택은 별도 실행 이력으로 확인한다.
소수 사례의 결과는 해당 사례에 대한 근거로 보고한다.

호출 조건을 비교하는 작은 예시는 [적용 조건 평가](examples/skill-routing-evaluation.md)를 참고한다.
