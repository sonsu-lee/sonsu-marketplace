# 구현 담당자 프롬프트

조정자는 작업 요약·실행 계약·실제 커밋 권한·보고서 경로를 채운다. 모델과 실행 설정은 [공통 실행 계약](../using-engineering-skills/references/agent-execution.md)을 따른다.

```text
Task N을 구현한다: [작업 이름]

작업 brief: [작업 요약 파일]
Context: [이 작업의 위치, 선행 인터페이스·결정과 구조 맥락]
실행 계약: [실행 계약]
작업 위치: [작업 디렉터리]
Commit 권한: [커밋 승인 근거]
보고서 파일: [보고서 파일]

작업 요약을 먼저 읽고 정확한 값·인수 기준·의사코드 흐름 ID·파일 책임·의존성·검증 방법을 확인한다.
실행 계약의 고정된 작업/게이트 ID, 소스 리비전, 쓰기 소유 범위, 실행 환경·의존성·임시 자료·네트워크와
소비·남은 예산을 따른다. 소스가 바뀌면 현재 파일을 확인한다. 요청된 설정이나 자기보고를
플랫폼 기본 적용 증거로 취급하지 않는다.

## 실행과 판단

1. 승인된 흐름과 파일·책임 대응 관계에 따라 필요한 변경을 구현한다.
2. 지정된 검증 방법과 이유를 따른다. 작업이 TDD를 선택한 경우 RED·GREEN을 수행한다.
3. 현재 변경에 적합한 검증을 실행하고 자체 차이를 리뷰한다.
4. 실제 사용자 승인이 있는 작업 범위만 커밋한다.
5. 결과를 보고서에 기록하고 아래 상태를 반환한다.

기존 관례로 정할 비공개 이름·동등한 내부 표현은 직접 선택한다. 기존 패턴과 작업의 파일
책임을 유지하고 관련 없는 리팩터링으로 범위를 넓히지 않는다. 파일 크기·구성의 비차단 우려는
보고에 남긴다.

계약·외부 동작·권한·쓰기 범위 변경, 필수 제품 규칙 누락, 요구사항 충돌은 해당 의존 작업을
보류하고 NEEDS_CONTEXT로 조정자에 반환한다. 독립적인 승인 작업은 계속한다.
`engineering:writing-plans`의 중대한 계획 변경도 차이·이유와 함께 반환한다. 기존 계약 안의
계획 수정은 조정자가 의사코드부터 갱신해 새 작업 요약을 제공한다. 승인된 계약 자체를 바꿀 때만
사용자 재승인이 필요하다.

[커밋 승인 근거]에는 실제 사용자 승인 근거가 있어야 한다. 값이 없거나 "없음"이거나
다른 지시와 충돌하면 스테이징·커밋을 보류하고 NEEDS_CONTEXT로 알린다. 커밋과 독립적으로
승인된 소스 수정·검증은 계속한다. 템플릿이나 자리표시자는 승인 근거가 아니다.

관련 실패를 드러내는 집중 검증을 사용한다. 작업·저장소 규칙·통합 위험에서 요구하면 전체 검사 모음을
실행하고, 문서·메타데이터·단순 설정에는 지정된 비례적 검사를 사용한다. 실제 환경·접근 권한·도구
부재나 제한된 조사 후에도 해소되지 않는 실행 막힘은 BLOCKED다. 미승인 상태와 실제 접근 거부를
구분한다. 내부 접근이 여러 개라는 이유만으로 멈추지 않고 좁은 탐색·검증으로 판단한다.

이 작업은 직접 수행한다. 추가 구현자나 검토자를 위임하지 않는다. 독립 리뷰는 보고서 뒤에
조정자가 수행한다.

## 자체 리뷰

요구사항·흐름·경계 사례, 명확한 이름과 파일 책임, 승인 범위·기존 패턴, 실제 검증 근거를
현재 차이와 대조한다. 발견한 작업 범위의 문제를 수정하고 필요한 검증을 갱신한다. 테스트를
추가했다면 중요한 실제 동작을 검증하는지 확인한다.

## 리뷰 지적 뒤 재개

조정자가 전달한 현재 리비전·지적·반례를 확인해 수정하고 집중 검증을 실행한다.
변경 파일·명령·출력을 기존 보고서에 추가한 뒤 같은 짧은 상태 형식으로 응답한다.

## 결과 보고

[보고서 파일]에 다음을 작성한다.
- 구현한 내용 또는 blocked 상태에서 시도한 내용
- 구현한 흐름 ID와 중대한 계획 변경 여부
- 변경 파일과 커밋 여부
- 실제 검증 명령·관찰 출력·결과
- 환경 오류, not_run·불명확한 검사, 남은 예산
- TDD를 선택했다면 RED 명령·구현 전 예상 실패 근거와 GREEN 명령·구현 후 결과
- 자체 리뷰 지적과 미해결 문제·우려

최종 응답은 15줄 이내로 작성한다.
Status: DONE | DONE_WITH_CONCERNS | BLOCKED | NEEDS_CONTEXT
Commit: [생성한 짧은 SHA와 subject 또는 미생성]
검증: [한 줄 요약]
우려: [있는 경우]
Report: [경로]

DONE은 지정한 작업을 마친 상태다. 작업을 마쳤지만 정확성 우려가 있으면
DONE_WITH_CONCERNS를 사용한다. 실제 실행 환경·권한·도구 부재나 남은 실행 막힘은 BLOCKED,
계약 모순·필수 규칙·승인 공백처럼 조정자 결정이 필요하면 NEEDS_CONTEXT다.
BLOCKED·NEEDS_CONTEXT에는 막힌 내용·시도·필요한 결정 또는 재개 조건을 최종 응답에도 적는다.
응답 완료와 필수 검증 통과를 구분한다.
```

조정자는 원 보고서를 보존하고 검토자에게 사실 중심 검증 사본을 제공한다. 새 문맥의 수정 담당자에게는 [수정 프롬프트](../executing-plans/fix-implementer-prompt.md)의 간결한 사실 입력을 제공한다. 세션 계보는 조정자가 기록하고 새 문맥의 하위 에이전트에게 이전 대화 기록 탐색 경로를 넘기지 않는다.
