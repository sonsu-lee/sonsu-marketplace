# 제품 브레인스토밍

제품 탐색 초기에 선택 공간을 넓히고 검토할 후보를 만든다. 아이디어는 사실·수요·승인된 결정과 구분해 제시한다.

## 절차

1. 제공된 아이디어·관찰·제약·제외 범위를 확인한다. 관찰과 가정, 문제와 해법, 사용자 제약과 제안 기준, 확정된 결정과 다시 열 수 있는 결정을 구분한다. 핵심 목적이 달라질 만큼 정보가 부족할 때 하나의 짧은 질문을 하고, 나머지는 가정을 밝혀 진행한다.
2. 요청에 맞는 탐색 방향과 후보 수를 정한다. 사용자·상황을 바꾸거나 현재 행동·우회 방법·감수하는 비용에서 기회를 찾는다. 결과를 유지하면서 제품 책임을 달리하는 해법과 문제를 제거·축소·예방하는 선택도 살핀다. 독립적인 후보를 먼저 확보한 뒤 익숙한 예시를 자극으로 사용한다.
3. 후보마다 문제·상황, 기대 결과, 작동 원리, 현재 근거, 가장 큰 가정, 반례·실패 가능성·검증 질문과 다른 후보와의 차이를 연결한다. 표현만 다른 후보는 합치고 독립적인 가정은 분리한다.
4. 수렴을 요청받으면 합의된 기준으로 비교한다. 점수는 근거가 뒷받침하는 정밀도로만 표현하고 다음 탐색이나 검증에서 확인할 질문을 고른다.

## 결과

문제 공간과 가정 → 구분되는 후보 → 후보별 기대 결과·trade-off·미확인 가정 → 더 넓힐 축 또는 수렴 기준 → 가장 중요한 다음 질문 순으로 제공한다. 후보와 결정, 아이디어와 증거가 구분되고 다음 행동이 분명하면 완료한다.

## 예시

입력: “공동 작업실의 공구를 찾는 시간을 줄일 방법을 발산해 줘.”

결과: 공구 위치를 안내하는 후보와 작업별 공구 묶음을 미리 두는 후보를 비교한다. 전자는 위치 정보의 최신성이, 후자는 작업 유형의 반복성이 가정이다. 둘 다 검증 전 아이디어로 두고 “실제 지연은 찾기와 준비 중 어디서 생기는가?”를 다음 질문으로 남긴다.

## 경계

- 기술 설계, 근거의 체계적 coding·수요 판정, PRD·구현 계획·티켓·정본 문서 작성은 각 담당 작업으로 넘긴다.
- 외부 조사·사용자 접촉·데이터 수집·원격 상태 변경은 별도 요청과 권한을 확인한다.

## 참고 자료

- 여러 단계의 주 조정자는 [작업 연속성](../../references/continuity.md)을 필요할 때 읽는다. 단발 작업과 위임된 작업자는 별도 기록을 만들지 않는다.
