# 제품 브레인스토밍

제품 탐색 초기에 선택 공간을 넓히고 검토할 만한 후보를 만든다. 후보를 사실, 사용자 요구나
승인된 결정으로 표현하지 않는다.

## 경계

- 사용자 문제, 기회, 가치 제안, 제품 행동과 해법 후보를 다룬다.
- 코드 구조, API, 라이브러리와 구현 방법을 정하는 기술 brainstorming은 다루지 않는다.
- 인터뷰나 피드백의 theme을 체계적으로 종합하거나 시장 수요를 검증했다고 판정하지 않는다.
- PRD, 구현 계획, ticket과 정본 문서를 작성하지 않는다.
- 외부 조사, 사용자 접촉, 데이터 수집과 원격 상태 변경을 자동으로 시작하지 않는다.

## 현재 공간을 고정한다

제공된 아이디어, 관찰, 제약과 이미 제외한 범위를 먼저 확인한다. 다음 내용을 구분한다.

- 관찰된 문제와 이를 설명하려는 가정
- 문제 후보와 해법 후보
- 사용자가 명시한 제약과 모델이 제안한 기준
- 이미 결정된 내용과 다시 열어도 되는 내용

핵심 목적을 바꿀 정도의 정보가 없을 때만 하나의 짧은 질문을 한다. 그 밖에는 명시한 가정으로
후보를 제시한다.

## 선택 공간을 넓힌다

요청에 필요한 만큼 서로 다른 탐색 방향을 사용한다.

- 사용자나 상황을 바꾸어 같은 문제를 다시 본다.
- 현재 행동, 우회 방법과 사용자가 감수하는 비용에서 기회를 찾는다.
- 결과는 유지하면서 제품의 책임과 경계를 다르게 둔다.
- 해법을 추가하기 전에 문제를 제거, 축소하거나 발생하지 않게 하는 선택을 포함한다.
- 익숙한 예시 하나에 맞춘 변형만 만들지 않고, 독립적인 후보를 먼저 확보한 뒤 예시를 자극으로
  사용한다.

고정된 후보 수, framework와 scoring 표를 강제하지 않는다. 사용자가 수렴을 요청하면 합의된
기준으로 비교하되, 점수의 정밀도가 근거의 정밀도보다 높아지지 않게 한다.

## 후보를 표현한다

각 후보에는 필요한 만큼 다음 정보를 연결한다.

- 해결하려는 문제와 대상 상황
- 기대하는 사용자·제품 결과
- 핵심 작동 원리 또는 제품 행동
- 현재 근거와 가장 큰 가정
- 반례, 실패 가능성과 검증할 질문
- 다른 후보와 실제로 다른 선택

비슷한 표현만 다른 후보는 합치고, 하나의 아이디어에 여러 독립 가정이 있으면 분리한다.

## 결과

다음 순서로 필요한 만큼만 제공한다.

1. 현재 이해한 문제 공간과 명시한 가정
2. 서로 구분되는 문제·기회·해법 후보
3. 후보별 기대 결과, trade-off와 미확인 가정
4. 더 넓혀야 할 축 또는 수렴에 사용할 기준
5. 다음 제품 탐색이나 검증에서 확인할 가장 중요한 질문

후보와 결정, 아이디어와 증거를 구분했고 다음 탐색 행동이 분명할 때 완료한다.
