# 제품 검증 설계

제품 가설을 검증 가능한 주장과 관찰 계획으로 바꾸고, 결과를 보기 전에 판정 계약을 고정한다.
고객 인터뷰나 MVP를 기본 해법으로 강제하지 않고 가설의 성격과 위험에 맞는 방법을 선택한다.

## 경계

- 문제, 수요, 가치, usability, viability, feasibility와 제품 행동에 관한 가설을 다룬다.
- 코드 단위 테스트, 통합 테스트, QA test case와 보안 검증은 다루지 않는다.
- 인터뷰 모집, 사용자 연락, 실험 노출, 결제, 데이터 수집과 제품 변경을 실행하지 않는다.
- 관찰된 결과를 판정하거나 제품 결정을 승인하지 않는다.
- 성공을 보장하거나 하나의 실험으로 시장 전체를 검증할 수 있다고 표현하지 않는다.

## 검증 계약을 고정한다

다음 입력을 확인한다.

- 검증하려는 주장과 현재 근거
- 대상 사용자, 상황과 제외 범위
- 결과에 따라 내릴 실제 결정
- 잘못된 긍정과 잘못된 부정의 비용
- 개인정보, 동의, 규제, 브랜드와 운영 위험
- 시간, 접근 가능한 표본, 도구와 예산처럼 사용자가 실제로 정한 제약

핵심 가설이나 결과에 따른 결정이 불명확하면 먼저 하나의 작은 가설로 좁힌다. 숫자, 기간,
표본과 성공 기준은 근거 없이 만들지 않는다.

## 가설과 경쟁 설명을 만든다

검증할 주장을 다음 요소로 표현한다.

- 대상과 상황
- 예상하는 관찰 가능한 행동 또는 결과
- 결과가 나타나야 하는 이유
- 주요 competing explanation
- 가설을 약화하거나 반증하는 관찰

선호, 의향과 실제 행동을 구분한다. 기능을 사용할 것이라는 응답과 실제 사용, 사용량과 제품
가치, 상관관계와 인과관계를 같은 증거로 취급하지 않는다.

## 방법을 가설에 맞춘다

검증 방법은 무엇을 알아야 하는지에 따라 선택한다.

- 문제와 현재 행동: 맥락 인터뷰, 관찰, diary와 기존 행동 자료
- 이해와 usability: prototype 또는 task 기반 관찰
- 수요와 commitment: 선주문, 신청, 가격 선택, concierge, fake door와 실제 행동 신호
- 제품 효과: cohort, quasi-experiment, controlled experiment와 전후 비교
- viability와 운영 경계: 가격·비용 자료, 공급자·정책 확인과 operational rehearsal
- feasibility: 기술 spike, 공급망 또는 제약 검증

방법 이름을 적용하는 데 그치지 않고 대상 가설, 예상 bias와 결정에 필요한 증거 수준을
설명한다. 표본 수는 고정 상수로 정하지 않고 목적, 모집단 다양성, 분석 방식과 중단 조건에
연결한다.

## 실행 전에 판정 기준을 정한다

test plan에는 필요한 만큼 다음 내용을 포함한다.

- plan ID, 리비전과 가설 ID
- 대상, 모집·선정 방식과 제외 기준
- 절차, 노출, 비교 조건과 수집할 최소 데이터
- primary signal, guardrail과 instrumentation 확인
- `supported`, `invalidated`, `inconclusive`를 구분할 기준
- 누락, 중도 이탈, 오염, 중복과 실행 편차의 처리
- 분석 방법과 competing explanation 확인 방법
- 개인정보, 동의, 중단·취소와 피해 완화
- 결과별 continue, revise, pivot, stop 또는 추가 검증 선택

정량 기준이 아직 합의되지 않았으면 임의 수치를 넣지 않고 `open`으로 표시한다. 그 상태로
실행하면 판정이 왜 불가능하거나 약해지는지도 설명한다.

## 결과

실행 가능한 test plan, 미결정 기준, 예상 한계와 필요한 승인·외부 행동을 구분하여 제공한다.
실행을 요청받지 않았다면 계획에서 멈춘다. 가설, 관찰, 판정 기준과 다음 결정이 서로 추적되고
결과를 본 뒤 기준을 바꾸지 않아도 될 때 설계를 완료한다.
