# 관련 쟁점만 확인하는 질문 목록

외부 연동·저장 데이터·권한·운영 방식이 제품 결과를 바꿀 때 읽는다. 저장소·합의·정책에서
답할 수 있는 사실은 먼저 확인하고, 아직 결정되지 않은 제품 행동만 질문한다. 모든 항목의
답변이나 사용자의 일괄 N/A 승인을 PRD·티켓의 선행 조건으로 만들지 않는다.

| 확인된 조건 | 사용자에게 필요한 결정 |
| --- | --- |
| 데이터를 저장·삭제하거나 다른 곳에 복제 | 누가 정본을 소유하고 무엇을 보존·삭제하며 사용자가 결과를 언제 확인하는가? |
| 중복 제출·재시도·동시 작업 가능 | 사용자 관점에서 중복·충돌을 어떻게 처리하고 어떤 상태를 보여야 하는가? |
| 대량 처리·다중 외부 연동 | 일부 성공·실패에서 무엇을 유지하고 무엇을 다시 실행할 수 있는가? |
| 역할·조직·계정 경계를 넘는 행동 | 누가 어떤 정보를 보고 실행하며 권한 변경 시 진행 중 작업은 어떻게 되는가? |
| 기존 고객·클라이언트·배포 버전 공존 | 보존할 동작·데이터와 전환·복구 시 사용자 영향은 무엇인가? |
| 되돌리기 어려운 변경·단계적 출시 | 무엇을 되돌릴 수 있고 남은 상태·사용자 안내는 어떻게 처리하는가? |
| 장애·지원 대응 필요 | 사용자가 어떤 상태·오류를 보고 운영자가 무엇을 확인해야 대응할 수 있는가? |

해당 쟁점과 답·출처, 미결정의 영향을 기존 탐색 결과에 연결한다. 엔지니어가 정할 라이브러리,
스키마·timeout·feature flag 이름·알림 임계치를 제품 결정으로 만들지 않는다. 이미 합의된
결정은 다시 묻지 않고 조건부 PRD와 준비 상태의 기존 구분을 유지한다.
