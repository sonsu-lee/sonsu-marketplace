# 제품 검증 판정

실행된 검증이 원래 질문에 어떤 증거를 제공하는지 판정한다. 사전 계획과 사후 탐색을 구분하여 가설·표본·지표·기준을 원래 리비전으로 대조한다.

## 절차

1. 가설·competing explanation·test plan, 사전 primary signal·guardrail·판정 기준, 실제 모집·표본·절차·노출·기간·instrumentation, 원자료 또는 재확인 가능한 결과 위치, 편차·누락·데이터 제외, 결과를 쓸 결정·승인 범위를 확보한다. 여러 리비전 중 판정할 조합을 명시한다. 결과를 본 뒤 바꾼 분석·기준은 `exploratory result`로 분리한다. 원자료나 재확인 가능한 결과 위치가 없으면 요약·발표 자료만으로 `supported`·`invalidated`를 내지 않고 `inconclusive`로 두며 그 한계를 기록한다.
2. 수치의 방향보다 실행 유효성을 먼저 확인한다. 실행 여부, 대상·상황의 가설 적합성, 노출·비교·계측 작동, 중복·오염·이탈·누락, 표본·기간의 충분성, 개인정보·동의·중단 조건·guardrail 위반을 대조한다. 가설을 검사하지 못한 실행은 결함과 남은 증거에 따라 `invalid` 또는 `inconclusive`로 둔다.
3. 아래 상태로 판정하고 effect size·불확실성·실제 중요도·일반화 범위를 설명한다. `supported`의 적용 범위와 `invalidated`가 반증한 가설을 한정한다.
4. 제외 자료나 다른 합리적 처리에 따른 민감도, segment 차이의 사전·사후 여부, novelty·seasonality·selection·survivorship·observer effect·외부 사건을 검토한다. 행동·만족·매출·비용·proxy 중 직접 측정한 대상과 동일 사용자·사건의 채널 간 중복을 확인한다.

| 상태 | 의미 |
| --- | --- |
| `not-run` | 계획만 있고 실행되지 않음 |
| `invalid` | 실행·측정 결함으로 해당 가설에 사용할 수 없음 |
| `inconclusive` | 실행됐지만 사전 기준을 지지·반증할 증거가 부족하거나 양립 가능한 설명이 남음 |
| `supported` | 정의한 범위에서 사전 기준을 충족하고 중요한 경쟁 설명이 충분히 약화됨 |
| `invalidated` | 정의한 범위에서 사전 반증 기준을 충족함 |
| `mixed` | primary signal·guardrail·segment·반복 결과의 방향이 다름 |

## 결과

plan·실행 리비전과 가설·범위 → 실행 여부·편차 → 사전 기준별 관찰 → 판정·확신의 한계 → 경쟁 설명·반례·guardrail → 증거가 허용하거나 허용하지 않는 결정 → continue·revise·pivot·stop·재검증 후보와 별도 승인 사항 순으로 보고한다. 원자료·사전 기준으로 추적되고 실행 결함·불확실성과 제품 결정의 경계가 드러나면 완료한다.

## 예시

입력: “보관함 안내 실험에서 완료율은 올랐지만 비교군의 완료 이벤트가 누락됐어.”

결과: 누락으로 비교가 불가능하다면 `invalid`. 상승 수치는 가설 지지 근거로 쓰지 않고 계측 결함과 재실행 조건을 보고한다. 실험을 아직 실행하지 않았다면 결과의 좋고 나쁨 대신 `not-run`으로 기록한다.

## 경계

- roadmap·출시·중단·예산·우선순위 승인은 결정권자에게 남긴다.
- 추가 분석에 새 수집·외부 접근·제품 변경이 필요하면 판정과 분리하여 필요한 승인을 알린다.
