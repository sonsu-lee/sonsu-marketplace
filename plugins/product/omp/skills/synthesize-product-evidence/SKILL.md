# 제품 근거 종합

제공되었거나 허용된 제품 자료를 추적 가능한 근거로 종합한다. theme이 설명하는 표본과 관찰 범위를 밝혀 후속 탐색과 결정에 전달한다.

## 절차

1. 제품 질문·분석 범위, 출처·리비전·수집 시점·접근 범위, 분석 단위(사람·계정·세션·발화·이슈·사건), 기존 codebook을 쓰는 연역 분석인지 후보 theme을 찾는 귀납 분석인지 확인한다. 빈도·심각도·확신도를 판단할 자료와 다음 결정·오판 위험을 확인한다. 질문이 모호해도 안전하게 분석할 수 있으면 가정을 밝혀 진행한다.
2. 출처마다 안정적인 ID를 부여한다. 유형·locator·리비전·확인 시점, 관찰 대상·표본·coverage, 직접 관찰과 해석, 개인정보·공개 범위, 중복 가능성·누락·수집 편향을 근거 원장에 기록한다. 대표 인용은 의미를 보존해 출처에 연결하고 민감정보는 최소화하며 익명화 여부를 밝힌다.
3. 반복 목표·문제·행동·우회 방법·결과, 사용자·상황·채널 차이, negative case, 출처 충돌·경쟁 설명을 비교한다. 빈도와 별개로 심각도·비용·되돌리기 어려움을 살피고 기존 결정과 맞는 근거와 새 질문을 만드는 근거를 구분한다. theme의 포함·제외 기준을 정해 비슷한 표현과 서로 다른 원인을 구분한다. 귀납 theme은 사람이 원문과 분류를 검토할 후보로 둔다.
4. 빈도는 분모·분석 단위·중복 제거 방법이 확인될 때 수치로 제시한다. 동일 사람·사건의 여러 채널 기록은 독립성에 맞게 집계한다. 확인이 어려우면 `반복 관찰`·`소수 사례`·`단일 사례`·`미확인`으로 표현한다. 가치·우선순위·인과관계는 별도 판단 근거가 필요한 것으로 남기고 작은 표본·자기선택·recall·moderator·측정 한계를 기록한다.

## 결과

질문·범위·출처·분석 단위 → 근거 원장 → theme별 지지 근거·대표 인용·빈도·심각도 → 반례·충돌·경쟁 설명 → 자료·분석 한계 → 탐색 시사점과 아직 내릴 수 없는 결정 → 다음 확인·사람의 검토 항목 순으로 제공한다. 핵심 theme이 원문에 연결되고 관찰과 제품 결정이 구분되면 완료한다.

## 예시

입력: “자료 A는 박물관 관람 동선 안내가 부족했다고 하고, B는 자유롭게 둘러볼 수 있어 좋았다고 해.”

결과: ‘동선 선택 지원’이라는 후보 theme에 A를 지지 근거, B를 일률적 안내의 반례로 연결한다. 관람 목적이 다른지 경쟁 설명을 남긴다. 표본과 독립성을 확인하기 전에는 선호 비율이나 전체 방문객 요구로 확정하지 않는다.

## 경계

- 새로운 외부 출처 조사와 제품 문제·우선순위·roadmap·요구사항·승인 결정은 각 담당 작업으로 넘긴다.
- 비공개 자료는 공개 검색·외부 모델·승인되지 않은 시스템으로 전송하지 않는다.

## 참고 자료
