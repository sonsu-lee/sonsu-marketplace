# Codex 메모리 접근

Codex 메모리를 대상으로 할 때만 읽는다. 현재 호스트의 메모리 지침이 저장 위치, 수정 권한과
반영 방식을 결정한다. 이 파일의 경로 예시나 디렉터리가 있다는 사실이 수정 권한은 아니다.

## 탐색

사용자가 명시한 Codex home을 우선하고, 없으면 현재 `CODEX_HOME`, 그다음 사용자 홈의
`.codex`를 후보로 확인한다. 메모리 지침에 정확한 root가 주어졌다면 그것을 따른다.
설정 전체를 출력하거나 환경변수 값을 덤프하지 않는다.

자주 보이는 파일은 `memories/memory_summary.md`, `memories/MEMORY.md`,
`memories/rollout_summaries/`와 `memories/raw_memories.md`다. 존재 여부와 실제 역할을
확인하고 제공된 요약을 다시 읽지 말라는 지침도 지킨다. JSONL·원시 입력·세션 요약은 검증 근거로만
읽으며 사람이 편집하는 주제 파일과 구분한다. SQLite와 내부 캐시는 이 스킬의 편집 대상이 아니다.

현재 프로젝트의 기억을 찾을 때는 인덱스의 프로젝트 경로·저장소 식별자를 사용한다. linked
worktree의 경로가 달라도 같은 저장소인지 확인하되 다른 프로젝트의 규칙을 전역으로 끌어올리지
않는다. 저장 구조를 확인할 수 없으면 확인된 범위만 읽기 전용으로 보고한다.

## 수정 방식

현재 지침이 허용하는 방식 하나를 따른다.

- **수정 노트 경로가 지정됨:** 그 경로와 형식을 사용한다. 예를 들어 현재 지침이
  `<codex-home>/memories/extensions/ad_hoc/notes/<timestamp>-<slug>.md`에 작은 노트 하나를
  요구한다면 원본 대신 새 노트 하나만 만든다. 기존 파일을 덮어쓰지 않는다.
- **직접 편집이 허용됨:** 실제 편집 가능한 curated 파일에만 본문의 백업·재확인 절차를 적용한다.
- **방식 불명 또는 직접 편집 금지인데 대체 경로 없음:** 정리안을 대화로 반환한다. 임의의
  `.proposed.md`, 새 메모리 폴더 또는 내부 DB 수정으로 우회하지 않는다.

노트 내용에는 대상 파일·항목, 추가/병합/교체/제거 요청, 짧은 변경안, 근거 위치와 적용 범위를
넣는다. 삭제 요청에도 제거할 주장을 식별할 정보를 남긴다. 원문 전체나 민감값은 복사하지 않는다.
같은 변경 요청 노트가 이미 있으면 새로 중복 작성하지 않고 그 상태를 보고한다.

```text
대상: MEMORY.md의 프로젝트 A / 테스트 실행 항목
요청: 오래된 명령 2건을 현재 명령 한 건으로 병합·교체
변경안: 프로젝트 A에서는 package.json의 현재 test script를 따른다.
근거: 프로젝트 A의 package.json과 해당 사용자 결정의 위치
범위: 프로젝트 A만. 전역 규칙이나 다른 프로젝트에는 적용하지 않는다.
상태: 수정 요청이며 원본 반영은 별도 확인 필요
```

노트를 쓴 뒤 실제 원본에 반영됐다고 가정하거나 내부 consolidation 명령을 추측해 실행하지
않는다. 호스트가 제공하는 지원 경로가 확인됐을 때만 요청 범위에서 사용하고 결과를 재조회한다.
명령이나 반영 상태를 알 수 없으면 `원본 반영 미확인`으로 끝낸다.
