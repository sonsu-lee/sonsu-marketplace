# Codex 메모리 접근

Codex 메모리를 대상으로 할 때만 읽는다. 현재 호스트의 메모리 지침이 저장 위치, 수정 권한과
반영 방식을 결정한다. 이 파일의 경로 예시나 디렉터리가 있다는 사실이 수정 권한은 아니다.

## 탐색

사용자가 명시한 Codex home을 우선하고, 없으면 현재 `CODEX_HOME`, 그다음 사용자 홈의
`.codex`를 후보로 확인한다. 메모리 지침에 정확한 root가 주어졌다면 그것을 따른다.
설정 전체를 출력하거나 환경변수 값을 덤프하지 않는다.

자주 보이는 파일은 `memories/memory_summary.md`, `memories/MEMORY.md`,
`memories/rollout_summaries/`와 `memories/raw_memories.md`다. 존재 여부와 실제 역할을
확인하고 제공된 요약을 다시 읽지 말라는 지침도 지킨다. JSONL·원시 입력·세션 요약은 검증 근거로만
읽으며 사람이 편집하는 주제 파일과 구분한다. SQLite와 내부 캐시는 이 스킬의 편집 대상이 아니다.

현재 프로젝트의 기억을 찾을 때는 인덱스의 프로젝트 경로·저장소 식별자를 사용한다. linked
worktree의 경로가 달라도 같은 저장소인지 확인하되 다른 프로젝트의 규칙을 전역으로 끌어올리지
않는다. 저장 구조를 확인할 수 없으면 확인된 범위만 읽기 전용으로 보고한다.

## 원본 수정 방식과 결과물 저장을 구분한다

현재 호스트의 원본 메모리 수정 계약과 별도 MD 산출물 쓰기 허용 범위를 각각 확인한다.
원본이 읽기 전용이어도 작업 결과물 위치에 쓰기가 허용되면 본문의 전체 교체용 MD를 만든다.

- **수정 노트 경로가 지정됨:** 원본의 변경 요청은 그 경로와 형식을 따른다. 예를 들어
  `<codex-home>/memories/extensions/ad_hoc/notes/<timestamp>-<slug>.md`에 작은 노트 하나를
  요구하면 대상, 변경안, 근거와 적용 범위를 적는다. 같은 요청의 노트가 있으면 재사용한다.
  정리안만 있는 노트를 완료 산출물로 보고하지 않고 별도 MD 파일 생성을 이어간다.
- **별도 결과물 쓰기가 허용됨:** 활성 메모리 경로 밖의 허용된 위치에 원본 파일 전체를 교체할
  `.md` 파일을 만든다. 정리안이나 붙여넣기 안내를 파일 본문에 섞지 않는다. 원본 파일 안의
  정리 범위 밖 내용도 보존하되, 다른 파일의 원문이나 민감값을 추가로 복사하지 않는다.
- **직접 편집이 허용됨:** 사용자가 원본 반영을 명시했을 때만 본문의 백업·재확인 절차를 적용한다.
- **별도 파일 생성이 금지되거나 허용 위치를 확인할 수 없음:** `완성본 파일 미생성`과 제한을
  알린다. 대화 본문이나 수정 노트만으로 별도 MD 제공이 완료됐다고 하지 않는다. 임의의
  메모리 폴더, 다른 출력 경로, 내부 DB 수정으로 제한을 우회하지 않는다.

## 완성본을 전달한다

최종 답변에는 실제 MD 파일 링크와 해당 로컬 머신에서 확인한 원본 메모리 절대 경로를
함께 제공한다. 다음은 형식 예시이며 `/example/` 경로를 실제 출력에 복사하지 않는다.

````text
완성본: [MEMORY.ready.md](/example/work/outputs/MEMORY.ready.md)

붙여넣을 원본 경로:
```text
/example/codex-home/memories/MEMORY.md
```

완성본 파일 내용 전체 복사 → 원본 파일 전체 선택 → 붙여넣기 → 저장.
전체 교체용 MD 제공됨 · 원본 미반영.
````

MD 생성과 원본 반영은 별도 상태다. 원본을 재조회해 확인하기 전에는 반영됐다고 가정하지
않고, 내부 consolidation 명령을 추측해 실행하지 않는다.
