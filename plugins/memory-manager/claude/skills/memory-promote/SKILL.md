독립적으로 반복된 사례와 원출처에서 재사용할 절차를 찾는다. 적용 조건과 불확실성을 포함한 검토용 초안을 제시한다.

## 절차

1. 사용자가 지정한 범위를 정하고 [공통 계약](../../references/store-contract.md)의 조회·경계를 적용한다. 이 스킬 디렉터리 기준으로 `python3 ../../scripts/memory_store.py search '주제' --scope project --cwd /absolute/project`를 실행하고 관련 ID를 `get`으로 읽는다.
2. 기억과 원출처에서 서로 독립적인 반복 사례가 최소 두 개인지 확인한다. 같은 대화에서 복제한 기록은 한 사례로 센다. 여러 프로젝트를 사용자가 정확히 지정했으면 각각의 프로젝트 디렉터리에서 별도로 조회한다.
3. 요청의 목적·입력·출력·예외·검증을 분리하고 공통 절차를 도출한다. 프로젝트마다 다른 조건은 적용 범위와 예외로 남긴다.
4. 근거가 충분하면 검토용 초안을 제시한다. 부족하면 어떤 독립 사례나 원출처가 더 필요한지 적는다.

## 결과

**검토용 초안**에 목적, 입력, 출력, 주장, 출처 ID, 일반화한 단계, 적용하지 않을 조건, 검증 방법, 불확실성을 담는다. 근거가 부족하면 초안 대신 부족한 사례와 이유를 보고한다.

## 예시

입력:

> 지정한 사진 전시 프로젝트와 상품 카탈로그 프로젝트의 이미지 교체 기억에서 공통 절차를 뽑아 줘.

각 프로젝트를 별도로 조회해 독립된 요청과 출처를 확인한 경우의 검토용 결과:

```text
목적: 이미지 교체 때 승인된 원본과 게시 파일의 대응 유지
입력: 교체 이미지, 대상 페이지, 승인 기록
출력: 교체 목록과 게시 파일 대응표
주장·출처 ID: 전시 프로젝트의 <조회 ID A>, 카탈로그 프로젝트의 <조회 ID B>
단계: 승인 기록 확인 → 파일별 게시 위치 연결 → 교체 → 승인본과 대조
예외: 승인 기록이 없거나 이미지 사용 권한이 불명확하면 보류
검증: 대응표의 모든 게시 파일이 승인본과 일치하는지 확인
불확실성: 다른 배포 방식에서도 같은 절차가 충분한지는 미확인
상태: 검토용 초안, 파일 생성·설치·기억 변경 없음
```

두 기록이 같은 요청을 복제한 것으로 드러나면 독립 사례는 하나이므로 추가 사례가 필요하다고 보고한다.

## 경계

- 사용자 검토 전에는 스킬 경로에 파일을 만들거나 설치·자동 호출하지 않는다.
- 기존 기억을 삭제하거나 상태를 바꾸지 않는다. 여러 프로젝트의 기억을 섞어 한 프로젝트에 다시 저장하지 않는다.
