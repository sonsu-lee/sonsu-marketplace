# ADR 0017: 두 호스트가 공유하는 로컬 Markdown 메모리

- Status: Accepted
- Date: 2026-09-26

## Context

기존 `memory-manager` 0.1.x는 각 호스트가 이미 저장한 메모리를 명시적으로 점검하는
단일 스킬이었다. Codex와 Claude Code가 같은 기기에서 작업할 때 장기 지식의 수집,
회상, 정리와 반복 절차의 승격을 한 흐름으로 다룰 필요가 있다. 호스트 자체 메모리와
Engineering 작업 연속성 기록은 소유권과 수명 주기가 다르다.

## Decision

플러그인 이름을 유지하고 기존 단일 스킬을 `memory-recall`, `memory-capture`,
`memory-maintain`, `memory-promote`로 교체한다. `~/.sonsu/memory-manager/`의 Markdown을
정본으로 두고 개인·프로젝트 범위를 분리한다. SQLite FTS5는 재생성 가능한 검색 색인이다.
Git linked worktree는 공통 Git 디렉터리로 같은 프로젝트를 식별한다. 파일 잠금,
원자적 교체와 읽은 내용의 SHA 비교로 동시 변경을 다룬다.

Codex 패키지가 소스이며 Claude Code 패키지는 생성한다. 자동 후보 수집은 프로젝트별
옵트인이고 훅은 장기 기억을 확정하지 않는다. 기존 호스트 메모리는 사용자가 선택한
항목만 읽기 전용으로 가져오기 후보로 삼는다. 실제 삭제는 명시적 요청에서만 수행한다.

## Alternatives Considered

- 호스트 기본 메모리를 직접 수정: 호스트별 권한과 저장 형식이 달라 공통 정본이 되기 어렵다.
- SQLite를 정본으로 사용: 사람이 검토·수정할 수 있는 출처 연결과 복구가 약하다.
- MCP 서버나 외부 동기화 서비스: 첫 배포의 같은 기기 요구보다 운영·권한 범위를 넓힌다.
- 항상 자동 수집: 비밀정보와 무관한 대화의 보존 위험을 높인다.

## Consequences

한 기기의 두 호스트가 같은 기억을 조회할 수 있다. 기본 메모리도 별도로 동작하므로
중복 맥락이 생길 수 있다. 훅 실행은 호스트 신뢰 설정과 이벤트 전달에 좌우되며,
수동 네 흐름은 훅 없이도 동작한다. 색인 오류는 Markdown에서 복구할 수 있다.

## Revisit When

기기 간 동기화·팀 공유가 실제 요구가 되거나, 호스트의 훅·스킬 선택 계약이 바뀌거나,
현지 파일 잠금과 FTS5가 지원되지 않는 환경을 지원해야 할 때 재검토한다.
