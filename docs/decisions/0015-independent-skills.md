# ADR 0015: 독립 스킬 중심 플러그인 경계

- Status: Accepted
- Date: 2026-09-25
- Supersedes: ADR 0014의 공개 스킬 이름과 절차 진입점. ADR 0014의 관리형 게이트·검토 인원·근거 보존 원칙은 아래 범위에서 유지한다.

## 문제

작업 산출물보다 실행 절차를 앞세운 공개 스킬과 긴 호출명이 늘어나면서 단독 요청에도 별도
라우팅·검증 스킬을 선택해야 했다. Git의 서로 다른 요청도 하나의 공개 진입점에 묶여 있었다.
작업 연속성은 생성 원본과 hook을 유지하면서도 일반 작업의 공개 선택 목록을 차지했다.

## 결정

12개 플러그인을 유지하고 배포 대상은 Codex로 한정한다. 공개 스킬은 단독 요청으로 완결할 결과를 맡고, 공통 실행 절차와
검증 기준은 해당 플러그인의 `references/`에 둔다. 다른 플러그인의 설치나 선행 호출은 요구하지
않는다. 호출명 변경과 삭제된 진입점의 현재 위치는 [스킬 라우팅](../architecture/skill-routing.md)에
명시한다. 옛 공개 호출명의 별칭은 제공하지 않는다.

Engineering의 일반 코드 리뷰와 개발 단계의 전체 독립 리뷰는 `engineering:review`의 같은
고정 입력·조정 계약을 사용한다. 동작이 바뀐 구현과 직접 요청한 일반 리뷰는 새 문맥 5개,
한 관점 리뷰와 유효한 전체 근거에 대한 국소 재검토는 1개, 의미 변화가 없는 기계적 변경은
선언한 소비 검사와 0개 리뷰를 기본으로 한다. 계약·설계·의존 경계 또는 영향 범위가 바뀌면
전체 리뷰를 다시 연다. 고위험 red team과 명시적 심층 PR 리뷰 구성은 유지한다. 지적은 다수결이
아닌 현재 코드·계약·도달 경로로 조정자가 판정한다.

Workflow의 Git 진입점은 `branch`, `commit`, `push`, `review-commit`으로 분리한다. 각 스킬은
단독으로 완료하며 `commit`이 `push`를 선행 또는 후속 의무로 만들지 않는다. 아홉 플러그인의
작업 연속성은 `references/continuity.md`와 기존 활성 기록에 반응하는 hook으로 제공한다.
기존 기록의 옛 `active_skill` 값은 읽을 수 있지만 새 기록은 현재 설치된 작업 스킬을 사용한다.

평가 가능한 신규·재설계 디자인 산출물은 독립 평가자 2명이 판정한다. 탐색 대화, 문구만의 수정,
디자인 산출물이 없는 코드 작업에는 디자인 평가를 자동으로 추가하지 않는다. Product→PRD,
Interface Design→Figma Workflow, Engineering→Workflow 연계는 요청한 결과에 필요할 때만 적용한다.

## 검증과 한계

frontmatter·경로·생성 결과와 단독·조합 설치의 native 발견을 검사한다. 실제 자동 선택과 결과
품질은 형식 검사와 다른 근거로 보고한다. 이번 전환의 관찰과 미실행 범위는
[검증 기록](../../evals/skill-routing/RESTRUCTURE-VERIFICATION.md)에 있다. 검토 인원수의
정량적 재조정은 이 결정의 범위가 아니다.
