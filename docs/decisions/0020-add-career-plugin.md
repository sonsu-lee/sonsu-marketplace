# ADR 0020: Career 플러그인 추가와 omp 기본 배포 포함

- 날짜: 2026-10-07
- 상태: 채택
- 관련 결정: [ADR 0015](0015-independent-skills.md)

## 배경

마켓플레이스에는 개발자의 지원 서류와 면접을 맡는 플러그인이 없었다. 확인한 외부 스킬은 공고 수집과
지원 자동화를 중심에 둔 프레임워크이거나 일본 시장 서류만 다루는 소규모 프로젝트였고, 기술 면접은
다루지 않았다. 사용자의 주 실행 환경은 omp이므로 Codex·Claude Code catalog에만 추가하면 실제로 쓰기 어렵다.

## 결정

독립 플러그인 `career`를 추가하고 omp 기본 배포에도 포함한다.

- 스킬은 `career-inventory`, `write-career-documents`, `prepare-interview`, `mock-interview`,
  `interview-retro` 다섯 개다. 다섯 스킬은 공통 [작업 공간 계약](../../plugins/career/references/workspace.md)과
  [근거 규칙](../../plugins/career/references/evidence-rules.md)을 따른다.
- 서류는 미국식 영문 resume를 중심에 두고 일본 기업용 履歴書·職務経歴書를 같은 경력 원본에서 만든다.
  スキルシート는 사용자 요청, 응모 안내의 제출 요구, SES·フリーランス 案件 지원 중 하나에 해당할 때만 만든다.
- 기술 면접은 경험 심층과 프론트엔드 시스템 설계를 포함하고, 알고리즘 문제 풀이와 채점은 제외한다.
- 서류 작성자와 검토자를 분리한다. 검토는 작성 대화를 넘기지 않은 별도 검토자가 체크리스트로 수행하고,
  분리할 수 없으면 "독립 검토 아님"을 결과에 남긴다.
- 사용자 자료에서 위험 신호 16종을 탐지해 곤란한 질문을 만든다. 탐지와 준비는 `prepare-interview`가 맡고,
  `mock-interview`의 deep-dive가 이 질문을 먼저 출제하며 반박형 꼬리질문을 쓴다. 신호 목록은
  `references/risk-probes.md`에 고정하고 목록에 없는 약점은 만들지 않는다.
- 서류에는 독자가 둘이라고 본다. 서류 심사는 HR이 JD 체크리스트와의 문구 일치로 판단하므로 Matched
  요구사항의 JD 표기와 경험 연수를 HR이 훑는 자리에 두고, HR 스크리닝 시뮬레이션으로 검증한다.
  1차 기술 면접관은 서류를 펼쳐 질문하므로 판단 이유와 해결·대응을 서류에 드러내고 제출 서류 기반
  질문을 준비한다.
- 면접은 면접관 체크리스트로 판정된다고 보고 준비와 모의면접 평가를 그 기준에 맞춘다. HR 기본 질문
  6종은 공통 답변으로 관리한다. 답변에는 이유를, 부정적 사건에는 해결·대응과 결과를 요구한다.
  역질문은 입사 후 그 자리에서 일하는 모습을 심는 방향으로 만든다.
- 회사 프로덕트는 공개 자료와 에이전트의 브라우저 사용으로 분석하고, 사용할 수 없으면 `not_run`으로
  기록한다. "직접 써 봤다"는 1인칭 경험은 사용자가 확인한 관찰로만 말한다.
- omp 기본 배포에 비격리 6번째 플러그인으로 추가한다. `./plugins/career`를 그대로 배포하며 hook과
  task continuity를 포함하지 않는다. 재개 상태는 사용자 작업 공간 파일이 담당한다.
- MIT 라이선스 외부 저장소 4개는 관점만 참고하고 파일이나 문구는 복사하지 않는다. 출처와 고정 revision은
  [UPSTREAM.md](../../plugins/career/UPSTREAM.md)에 기록한다.

## 대안

- **Writing에 스킬 추가**: Writing은 독자·목적에 맞는 문서 구성을 맡는다. 경력 원본, 서류 양식, 면접
  연습까지 넣으면 범위가 맞지 않는다.
- **외부 프레임워크 설치 또는 fork**: 공고 스캔과 지원 자동화 중심이고 일본 서류 지원이 약하다.
- **단일 스킬 또는 스킬 3개**: 경력 정리, 서류, 준비, 연습, 회고의 트리거가 달라 라우팅이 흐려지고
  스킬 본문이 지나치게 커진다.
- **개인 볼트 형식 채택**: 특정 사용자의 디렉터리 구조라 공개 배포에 맞지 않는다.
- **omp 배포에서 제외**: 주 실행 환경에서 쓸 수 없다.

## 결과

- omp 배포 개수가 5개에서 6개로 바뀌어 배포 정책 문서, `scripts/render-omp-compat.py`,
  `evals/plugin-compat/test_compat.py`를 함께 갱신한다. Engineering·continuity 문서의 "기본 5개"
  문구는 omp 기본 배포에 Engineering이 없다는 뜻이므로 그대로 둔다.
- 행동 평가는 [evals/career](../../evals/career/README.md)의 사례로 정의하며 실행 전까지 `not_run`이다.
- 개인 데이터는 사용자 작업 공간에만 두고 저장소에는 가상 fixture만 둔다.

## 다시 볼 때

- スキルシート 요청이 잦아져 조건부 생성이 불편할 때
- 알고리즘 코딩 연습 수요가 생길 때
- 한국 시장 지원 서류가 필요해질 때
- omp 순정 기능이 이 역할을 대체할 때
