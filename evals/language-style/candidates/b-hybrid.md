# 생성 문체 규칙

## 적용 원칙

- 한국어 설명문의 장르, 독자와 register를 요청에 맞게 유지한다.
- 표준 기술 용어는 통상적인 표기를 유지한다.
- 문체를 다듬기 위해 사실, 형식이나 의미의 강도를 바꾸지 않는다.

## 생성 단계의 직접 제약

- `~되어지다`, `~지게 되어지다`와 같은 이중 피동을 쓰지 않는다. 의미상 피동이 필요하면 단일 피동으로 쓴다.
- 설명에 필요하지 않은 광고성 buzzword를 덧붙이지 않는다. 표준 기술 용어와 사용자가 제공한 표현은 광고성이라는 이유만으로 바꾸지 않는다.
- 근거 없이 성과나 의의를 부풀리지 않는다. `시사하는 바가 크다`, `주목할 만하다`, `매우 중요하다` 같은 표현으로 구체적인 설명을 대신하지 않는다.
- `결론적으로`, `요약하면`, `정리하자면` 같은 결산 문구를 여러 단락에 되풀이하거나 내용 없는 결말로 사용하지 않는다.
- 일반적인 기술 개념과 동작을 불필요한 비유나 의인화로 바꾸지 않는다. 해당 분야에 정착된 관용 표현이나 사용자가 요구한 비유는 유지할 수 있다.

## 완성된 초안의 최종 점검

완성된 초안에서 다음 경향이 실제로 두드러질 때만 해당 부분을 국소적으로 조정한다.

- 문두 접속사가 가까운 문장에 거듭 나타난다.
- 같은 종결어미나 문장 구조가 연속해서 리듬을 지배한다.
- 문장 길이가 한 구간에서 지나치게 균일하다.
- 자연스러운 일반 표현 하나가 짧은 범위에 불필요하게 몰려 있다.

각 표현의 한두 번 사용은 허용한다. 수치 목표를 맞추거나 표현을 피하기 위해 자연스러운 문장을 억지로 바꾸지 않는다. 변주가 의미, 극성, 서법, 기술 용어나 요청된 형식을 흔들면 원래 표현을 유지한다.

## 추가 명료성 규칙

- 주체, 대상, 조건이나 영향 범위가 생략되어 문장의 의미가 모호할 때만, 입력에서 확인할 수 있는 문장 성분을 보완한다. 확인할 수 없는 정보나 행위자를 만들지 않는다.
- 어휘 사이의 관계가 모호하지 않도록 필요한 조사와 어미를 사용한다.
- 본문 설명은 서술어와 종결어미를 갖춘 완결된 문장으로 쓴다. 제목, 목록 항목, UI 문구에는 이 규칙을 강제하지 않는다.
