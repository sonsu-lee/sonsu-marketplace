# 공통 보존 계약

이 계약은 모든 후보에 동일하게 적용한다. 문체 규칙과 보존 계약이 충돌하면 보존 계약을 우선한다.

## 적용 범위

- 사용자가 요청한 한국어 답변과 문서의 설명문에 적용한다. 기술 답변과 기술 문서의 설명문도 포함한다.
- 사용자가 요구한 내용, 독자, 어조와 출력 형식을 따른다.
- 외국어 문장이나 기술 용어를 임의로 번역하거나 다른 표현으로 바꾸지 않는다.

## 정확히 보존할 내용

입력에 있거나 출력에 포함하라고 지정된 다음 항목은 철자, 대소문자, 문장부호와 값을 바꾸지 않는다.

- fenced code block과 fence, inline code
- 명령어, option, 환경 변수, 경로와 식별자
- API endpoint, HTTP method, 함수와 API signature, JSON/YAML key
- 로그와 오류 메시지, 버전, commit SHA와 ticket ID
- 수치, 날짜, 단위, URL과 Markdown link destination
- 프롬프트에서 별도로 지정한 보호 문자열과 literal

## 구조 보존

- 요청되거나 입력에 주어진 제목의 계층과 순서를 유지한다.
- 표의 형태, 열과 행의 의미와 순서를 유지한다.
- 불릿과 번호 목록의 종류, 항목과 순서를 유지한다.
- 번호가 있는 절차의 단계 수와 실행 순서를 바꾸거나 합치지 않는다.
- 형식 변경이 명시적으로 요청되지 않았다면 표, 목록과 절차를 산문으로 바꾸지 않는다.

## 의미 보존

- 사실, 주장, 귀속, 인과 관계와 영향 범위를 추가하거나 삭제하지 않는다.
- 부정과 긍정의 극성을 바꾸지 않는다.
- 조건, 전제, 예외와 제한 범위를 유지한다.
- 추측, 가능성, 확신과 불확실성의 정도를 유지한다.
- `must`, `should`, `may`에 해당하는 의무와 허용 수준을 바꾸지 않는다.
- 입력으로 뒷받침되지 않는 결론, 수치, 사례, 출처나 행위자를 만들지 않는다.
