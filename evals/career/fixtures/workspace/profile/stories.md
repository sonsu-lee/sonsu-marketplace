# STAR+R 스토리

### S-001 checkout CI를 13분에서 4분으로 줄인 일

- 역량: performance, ownership
- 사실: F-001
- Situation: checkout rewrite 중 PR마다 CI가 13분 걸려 리뷰와 배포가 밀렸다.
- Task: 팀의 대기 시간을 줄이기 위해 CI 병목을 찾아 줄이는 일을 맡았다.
- Action: GitHub Actions 실행 기록으로 단계별 시간을 나눠 보고, 의존성 설치와 테스트가 병목임을 확인했다. 의존성 캐시를 도입하고 테스트를 병렬 job으로 나눴다.
- 해결·대응: -
- Result: 2주 중앙값 기준 CI 시간이 13분에서 4분으로 줄었다(2024-06).
- Reflection: 체감이 아니라 실행 기록으로 병목을 먼저 확인한 것이 효과적이었다.
- 15초: checkout rewrite에서 CI 병목을 분석해 캐시와 병렬 job으로 CI 시간을 13분에서 4분으로 줄였다.
- 60초: checkout rewrite 중 PR마다 CI가 13분 걸려 리뷰가 밀렸다. 실행 기록을 단계별로 나눠 보니 의존성 설치와 테스트가 대부분을 차지했다. 의존성 캐시를 넣고 테스트를 병렬 job으로 나눴고, 2주 중앙값 기준 4분이 됐다. 이후에는 개선 전에 측정부터 하는 습관을 팀에 공유했다.
- 2분: 60초 버전에 캐시 키 설계와 병렬화로 늘어난 실행 비용을 어떻게 판단했는지를 더한다.

### S-002 결제 연동 단계의 INP를 개선한 일

- 역량: performance, customer-focus
- 사실: F-002
- Situation: 제휴 은행 결제 연동 단계에서 입력 반응이 느리다는 고객 문의가 이어졌다.
- Task: checkout 결제 단계의 반응성을 개선하는 일을 맡았다.
- Action: Chrome DevTools Performance로 긴 작업을 찾고, 입력 핸들러를 나누고 불필요한 렌더링을 지연시켰다.
- 해결·대응: -
- Result: RUM 대시보드 기준 p75 INP가 480ms에서 190ms로 개선됐다(2024-02 → 2024-08).
- Reflection: 실제 사용자 지표(RUM)를 기준으로 삼아 개선 효과를 설명할 수 있었다.
- 15초: 제휴 은행 결제 단계의 긴 작업을 나눠 p75 INP를 480ms에서 190ms로 개선했다.
- 60초: 제휴 은행 결제 연동 단계에서 입력이 느리다는 문의가 있었다. DevTools로 긴 작업을 찾아 입력 핸들러를 나누고 렌더링을 지연시켰다. RUM 기준 p75 INP가 480ms에서 190ms가 됐다. 지표를 먼저 정하고 개선한 덕분에 효과를 숫자로 공유할 수 있었다.
- 2분: 60초 버전에 원인 후보를 좁힌 과정과 회귀를 막기 위한 확인 방법을 더한다.
