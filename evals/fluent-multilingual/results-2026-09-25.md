# 언어별 단일 Fluent 스킬 집중 사례 결과

> 이전 `fluent-languages` 패키지에서 실행한 역사적 스냅샷이다. 아래 해시의
> `cases.json`은 분리 전 입력이며, 현재 `evals/fluent-multilingual/cases.json`의 해시나
> 세 독립 패키지의 설치·자동 선택 결과를 나타내지 않는다.

## 범위와 판정

2026-09-25에 `cases.json`의 한국어·영어·일본어 각 3건을 새 문맥에서 한 번씩 실행했다.
최종 출력 9건 모두 프로세스가 정상 종료했고, `protected_literals`의 정확한 문자열 검사는
9/9 통과했다. 작성·윤문·진단 범위와 `must_preserve`·`must_not_introduce`는 출력과 입력을
대조해 수동으로 점검했으며, 9건에서 명확한 위반을 발견하지 못했다. 이는 제한된 사례의
관찰 결과이지 자연스러움이나 외부 스킬 대비 우위를 입증한 결과가 아니다.

각 실행은 `codex exec -s read-only --ephemeral`의 별도 세션에서 `gpt-6-sol`, reasoning
`xhigh`로 진행했다. 후보 `SKILL.md`의 본문을 프롬프트에 직접 포함했고, 한국어 참고 자료는
필요할 때 읽을 수 있게 했다. 실제 플러그인의 자동 선택·로딩을 검증한 실행은 아니다.
판정자는 작성자와 같으며 블라인드 평가나 원어민 검토를 수행하지 않았다.

## 실행 중 발견해 조정한 부분

- 영어 윤문의 첫 실행은 `groundbreaking`을 `major`로 낮췄지만 근거 없는 평가를 남겼다.
  영어 지침에 평가 수식어를 다른 찬사로 치환하지 말라는 조건을 추가했다. 같은 입력의
  재실행에서는 `We optimized \`cacheKey\`.`가 나왔다. 각 버전 1회 실행이므로 개선율을
  계산하거나 일반화하지 않는다.
- 일본어 진단의 첫 입력은 설정 변경 단계가 생략된 절차로도 읽혔다. 그대로 둘 반례로
  명확하도록 입력을 수정하고 다시 실행했다. 입력이 달라졌으므로 두 출력을 직접 A/B
  비교하지 않는다.
- 초기 한국어 윤문·일본어 작성 실행은 로컬 플러그인 갱신 중 종료 훅이 옛 캐시 경로를
  참조해 최종 종료를 확인하지 못했다. 경로 복구 뒤 같은 사례를 다시 실행했고 정상 종료했다.

## 남은 검증

기존판과의 동일 조건 비교, 실제 플러그인 자동 라우팅, 반복 실행의 안정성, 한국어·영어·일본어
원어민 또는 동등한 편집자 선호 평가는 `not_run`이다. 특히 일본어 스킬의 beta 상태는 이
9건으로 해제하지 않는다.
