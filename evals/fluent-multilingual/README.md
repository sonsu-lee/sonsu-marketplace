# Fluent 언어별 플러그인 공통 사례

언어별 단일 스킬의 윤문·수정 없는 진단과 문체 샘플·의미 보존을
확인하기 위한 고정 입력이다. 세 언어의 기존 fixture와 별도로 관리하며 과거 평가의
사례 수나 결과에 합산하지 않는다.
영어·일본어에는 새 작성 사례도 있다. 한국어는 원본 범위에 맞춰 기존 글의 AI 티·번역투
윤문을 검사하며, 일반 새 작성은 라우팅 평가에서 Writing의 책임으로 둔다.

[`cases.json`](cases.json)의 `prompt`와 `evidence`만 실행 모델에 제공한다. 각 사례를 새 문맥에서
case의 `plugin`에 해당하는 패키지의 `SKILL.md`와 함께 실행하고, `expectations`는 평가자만 본다. 편집 결과에 포함해야 할
`protected_literals`는 정확히 대조하고, `must_preserve`와 `must_not_introduce`는 원문·샘플의
조건, 문체와 편집 범위를 살펴 의미로 판정한다. 진단 사례는 원문을 그대로 두는 판단이
정답일 수 있으며, 저자 판별이나 임의 점수를 반환하면 실패다.

정적 검사:

```sh
python3 -m json.tool evals/fluent-multilingual/cases.json >/dev/null
```

JSON 검사는 사례 형식만 확인한다. 실제 스킬 로딩, 모델 출력의 의미 보존과 한국어·영어·일본어
원어민 선호는 별도로 기록한다. [2026-09-25 집중 사례 결과](results-2026-09-25.md)는
기존 `fluent-languages`의 스킬 본문을 직접 제공한 당시 단일 출력의 보존 점검이며 현재 세 패키지의 자동 라우팅이나 원어민 선호를
검증하지 않았다. 미실행 항목은 `not_run`이다.

[세 플러그인 분리 후 평가](results-2026-09-25-three-plugins.md)는 현재 패키지의 스킬 본문과
기존 언어별 평가 입력을 실행한 결과, 격리된 native 로더 발견 결과와 남은 미실행 범위를 구분한다.
그 모델 출력은 이번 한국어 적용 범위 정리 전의 스킬과 사례에 대한 기록이며, 갱신한
`cases.json`의 한국어 사례는 다시 실행하지 않았다.
