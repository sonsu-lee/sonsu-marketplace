# 한국어 결과물 평가

[cases.json](cases.json)의 대표 사례에 fluent-korean을 적용해 결과물의 보존성과 품질을 확인한다. 일반 설명·기술 문서·업무 문장·번역투·이미 자연스러운 글을 포함한다. 별도 모델 실행기나 변경률 도구는 요구하지 않는다.

## 실행

1. 평가할 스킬 파일을 고정하고 모델·실행 설정·실행일을 기록한다.
2. 사례마다 `prompt`, `evidence`, 편집 사례의 `source_text`만 모델에 전달한다. `expectations`, `families`, `expected_action`은 평가자만 본다.
3. [SKILL.md](../../plugins/fluent-languages/skills/fluent-korean/SKILL.md)에서 시작해 필요한 참조를 읽도록 한다. 참조 전체를 미리 주입한 실행은 실제 참조 로딩 확인과 구분한다. 사례는 서로 독립된 문맥에서 실행한다.
4. 입력·출력과 실제 읽은 지침을 저장하고 아래 기준으로 평가한다. 실행 자료는 저장소 밖이나 무시된 작업 디렉터리에 둔다.
5. 실패 사례의 규칙을 수정하고 영향받는 사례를 다시 확인한다. 실행하지 않은 사례와 사람의 평가는 `not_run`으로 기록한다.

## 사례 형식

`schema_version`은 `fluent-korean-review-cases-v1`이다. `mode`는 `generation` 또는 `editing`, `expected_action`은 `generate`·`edit`·`keep`이다. `keep`은 본문을 그대로 반환해야 하는 사례이며 응답 마지막 줄바꿈 차이만 무시한다. `edit`은 지정된 문제를 고쳤는지 확인한다.

`expectations`에는 보호 문자열·코드 블록·제목·순서·횟수와 의미 보존·추가 금지 사항을 기록한다. 문자열 일치는 자동 확인할 수 있지만 의미 보존과 교정 필요성은 출력과 원문을 직접 대조해야 한다.

## 판정 기준

| 항목 | 판정 |
| --- | --- |
| 보호 대상 | 문자열·수치·날짜·코드·링크·고정 구조 손상 사례 수 / 실행 사례 수 |
| 의미 | 주체·조건·인과·가능·의무·부정·시제 손상 사례 수 / 검토 사례 수 |
| 편집 범위 | 요청 범위 밖 수정 사례 수 / 편집 사례 수 |
| 불필요한 교정 | keep 사례 중 변경된 사례 수 / 실행한 keep 사례 수 |
| 필요한 교정 | edit 사례 중 지정 문제를 해결한 사례 수 / 실행한 edit 사례 수 |
| 자연스러움 | 1: 읽기 어려움, 3: 이해되나 어색함이 남음, 5: 독자·장르에 자연스러움 |
| 명료성 | 1: 요점·관계가 모호함, 3: 일부 관계가 불명확함, 5: 요점·관계가 분명함 |
| 문체 적합성 | 1: 요청·격식과 어긋남, 3: 일부 불일치, 5: 요청·격식·화자의 목소리에 적합 |

2·4점은 인접 기준 사이의 판단이다. 점수마다 실제 문장을 근거로 적고 평가자를 기록한다. 모델의 보조 평가와 사람의 평가를 합산하지 않는다. 필수 보존·의미·범위 손상과 keep 사례의 불필요한 교정은 0건이어야 한다. 평균 점수가 높아도 보존 실패를 상쇄하지 못한다.

## 결과 기록

사례 ID, 실행 상태, 입력·출력 위치, 적용한 지침, 보존 검사, 의미·범위 판정, 세 품질 점수와 근거, 평가자, 미확인 항목을 남긴다. 성공·실패·미실시 건수와 각 지표의 분모를 함께 보고한다. 사람의 평가가 없으면 자연스러움이 검증됐다고 결론 내리지 않는다.

## 자료 검사

```sh
python3 -m json.tool evals/fluent-korean/cases.json >/dev/null
```
