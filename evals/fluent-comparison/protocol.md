# Fluent 비교 평가 계약 — 2026-09-25

## 질문과 범위

독립 패키지의 언어 스킬이 같은 모델의 기본 출력(`none`)과 분리 전 배포 스킬(`legacy`)에
비해 사실·보호 문자열을 유지하면서 요청한 언어·문체·편집 범위를 더 잘 처리하는지
작은 고정 세트에서 비교한다. 외부 저장소의 원본 스킬에 대한 우열은 이 평가의 주장이 아니다.

## 입력과 실행

- 이 디렉터리의 18문항은 언어별 6개이며, 새 작성·윤문·수정 없는 진단을 각 2개씩 포함한다.
  현재 스킬을 이 문항으로 수정한 이력은 없지만 문항 작성자가 스킬 내용을 알고 있으므로
  독립적인 블라인드 held-out 세트는 아니다.
- `prompt`와 `evidence`만 생성 모델에 제공한다. 숨긴 `checks`는 판정 단계에만 사용한다.
- `gpt-6-sol`, reasoning `medium`, 각 문항·arm에서 2회씩 총 108개 출력을 새 문맥에서 생성한다.
  arm 순서와 문항 순서는 고정 seed로 섞고, 각 문항의 두 반복에서는 arm 순서를 뒤집는다.
- 모든 arm에 같은 격리 설정을 적용한다. `legacy`와 `current`는 해당 `SKILL.md`를
  직접 제공한다. 한국어 윤문·진단에는 각 snapshot의 관련 참고 자료를 같은 방식으로
  제공한다. `none`은 해당 지침을 제공하지 않는다. 실제 자동 스킬 선택을 측정하지 않는다.
- 스킬·참고 자료, 문항, 명령, 모델 설정과 판정 rubric의 hash를 생성 전에 고정한다.
  실패·timeout·빈 출력은 성공으로 세지 않고 원자료와 별도로 표시한다.

## 판정

- 보호 문자열은 정확한 문자열로 검사한다. 문자열 건수와 통과 문항 수를 별도로 보고한다.
  자동 검사가 사실의 진위·문체 자연스러움을 대신하지 않는다.
- 같은 문항의 출력은 출처 표시를 제거하고 순서를 바꿔 고정 rubric의 LLM 판정자에게
  제공한다. `semantic_ok`, `task_ok`, `overedit`을 출력별로 평가하고 `current` 대
  `none` 및 `current` 대 `legacy`의 선호를 pairwise로 평가한다. 원문과 확인된 자료에 없는
  주장이나 조건 변경은 선호보다 우선하는 실패다.
- 두 반복은 한 문항의 관측치로 묶는다. 반복을 독립된 36문항으로 세지 않는다.
  문항별 선호가 일치하지 않으면 `mixed`로 남긴다. 명확한 승패 문항에 양측 exact sign
  test를 적용하고 동률·mixed·실행 실패를 별도로 보고한다.
- 같은 LLM의 판정은 사람 2명 또는 독립 모델 2개의 의견이 아니다. 사람의 원어민 선호,
  실제 사용 환경에서의 자동 라우팅, 외부 스킬 대비 우열은 `not_run`으로 남긴다.
  유의미한 개선이라 말하려면 current 승수가 패수보다 많고 양측 p<0.05이며,
  신규 의미·보호 문자열 회귀가 없어야 한다. 작은 개발자 작성 세트에 대한 결과만 주장한다.
