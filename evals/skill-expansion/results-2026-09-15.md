- 오래된 APPROVED와 봇 👍를 새 head의 통과로 간주하지 않았다. CI pending과 thread 페이지 timeout을 구분했다.
- push timeout과 readback unavailable을 unknown으로 남기고 재전송·thread 해결을 진행하지 않았다.
- 리뷰어 2/3 완료와 head 변경을 심층 리뷰 완료로 계산하지 않았다.
- 지도 좌표 부재는 디자인용 도식으로 표시하고 차트 값 10/20/15와 단위를 보존했다. 실제 시안 검증은 미실행으로 남겼다.

- 제품 질문은 결제 성공/주문 저장 실패의 사용자 결과·재시도·복구 책임으로 좁히고 구현 선택을 만들지 않았다.

## 실행 식별과 임시 증거

작업 `01a0a271-fb59-75d2-96d9-4f930c70b8be`의 `eval_research`, `routing_eval`,
`behavior_eval`, `ui_execution_eval` 독립 실행 결과를 대조했다. native 원시 events와 요약은
`/private/tmp/sonsu-native-skills-zot5v1gh/`, UI 예제는 `/tmp/sonsu-interface-eval-reading-43af/`에
생성했다. 임시 경로는 배포 파일·영구 재현 fixture가 아니다. 재평가는 `cases.json`과 README의
프로토콜을 사용하고 새 실제 관찰을 기록한다.

실제 CLI 자동 선택 실행은 `01a0a2cb-63cc-7321-90ef-bd987e769b3d`입니다.
`codex exec --ignore-user-config --ephemeral --sandbox read-only`로 복사한 프로젝트 스킬을
로드했습니다. 사용자 설치·인증 파일을 복사하거나 수정하지 않았고 CLI는 기존 인증을 사용했습니다.
최초 선택과 SKILL.md 읽기는 trace에 남았습니다. 이후 모델이 임시 프로젝트의 출력 trace도 읽었으므로
후속 행동의 완전한 입력 격리는 주장하지 않습니다. 모바일 기기 실행 증거는 없습니다.

반례 검토에서 Operations UI의 일반 UI 직접 호출 허용과 기존 비운영 화면 중단 조건이 충돌함을
찾아 일반 UI 구현 경로를 명시했습니다. 운영형 웹의 기존 validator·G0–G7은 유지합니다.
