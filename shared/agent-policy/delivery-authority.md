# Git·외부 전달 권한

현재 사용자 요청과 이전에 확인한 승인 범위를 이어서 적용한다. 구현은 소스 수정·필요한
격리·검증을 포함한다. staging은 명시 요청 또는 승인된 commit의 일부로 수행한다.
commit·push·PR·merge·배포·메시지 게시에는 각각 해당 동작을 포함하는 사용자 승인이 필요하다.
스킬·계획·모델 기능은 이 권한을 추가하지 않는다.

승인받은 작업은 반복 확인하지 않는다. 새 승인이 필요하면 승인 전 가능한 준비를 끝내고
정확한 변경·대상·결과를 검토 가능한 형태로 제시한다. 구현만 요청받았다면 검증된 diff를
전달하며 Git 작업을 위한 추가 질문을 형식적으로 만들지 않는다.

Engineering은 변경과 검증 준비 상태를, Workflow는 승인된 Git·티켓·PR 전달을 소유한다.
전달 직전 현재 산출물과 근거를 대조하고 외부 변경 뒤 대상의 실제 상태를 다시 읽는다.
로컬 통과·도구 요청 성공·빈 원격 검사 목록만으로 외부 반영이나 CI 성공을 주장하지 않는다.
